# HLS на сайте — клиент (T5, T6)

Контракт — `docs/HLS.md` (§9 `direct_ok`, §10 блок `hls` в `variant-url`, §12 сайт). Здесь — как устроен плеер сайта и админка.

## T5. Плеер

### Файлы

| Файл | Что |
|---|---|
| `website/public/hls-player.js` | модуль плеера (ES2017, без сборщика, внешний скрипт — CSP пускает только `'self'` и хеши встроенных скриптов). В браузере — `window.SuslikHls`, в Node — `module.exports` (без DOM) |
| `website/public/index.html` | точка врезки: `<script src="hls-player.js" defer>` и одна строка в конце `psLoad()` — `SuslikHls.attach({sheet, file, magnet, mirrorUrl, live, api, watch})` |
| `website/public/vendor/hls.min.js` | hls.js (кладёт T4); грузится лениво, только когда нужен |
| `website/test/hls-player.test.js` | `pickSource` на фикстурах `docs/hls-fixtures/variant-url-*.json`, сдвиг позиции, `direct` → MIME, разбор `master-v1.m3u8`, выбор дорожек, реакция на ошибки hls.js |
| `website/scripts/check.js` | проверка синтаксиса `hls-player.js` в `npm run check` |

CSP не меняется: `pageCsp()` (`src/services/precompressed.js`) считает хеши встроенных скриптов из файла сам, у `<script src>` хеша нет.
Адрес CDN в `connect-src`/`media-src` и `worker-src 'self' blob:` (для воркера hls.js) добавляет T4.

### Как работает

1. Окно фильма (`openPlaySheet` → `psLoad`) как раньше подписывает зеркало (`GET /api/file/mirror-url`) и готовит кнопку «Смотреть» (PotPlayer, VLC, приложение Android). Это не меняется.
2. Затем `attach()`:
   - запущено в приложении Android (`nativeApp()`: `window.__suslikApp >= 2` и `SuslikNative`) — ничего не делает, приложение играет само;
   - у окна нет раздачи (файл из поиска без `magnet`) — ничего не делает;
   - иначе `POST /api/file/variant-url {ad_id, path}`. Ошибка или в ответе нет блока `hls` (HLS выключен, пользователь не в бете) — всё как раньше.
3. `pickSource(resp, caps)` — чистая функция:

| Ответ | Браузер | Что видно |
|---|---|---|
| нет `hls` | любой | как раньше (`legacy`) |
| `ready` | HEVC через MediaSource (`isTypeSupported('video/mp4; codecs="hvc1.1.6.L120.90"')`) | «▶ Смотреть в браузере», hls.js |
| `ready` | Safari: `canPlayType('application/vnd.apple.mpegurl')` и `canPlayType` hvc1 | «▶ Смотреть в браузере», нативный HLS |
| `ready`, `v1-copy`, `direct.vcodec = h264` | H.264 через MediaSource или нативно | HLS (копия видео H.264, `docs/HLS.md` §5) |
| `ready`, без HEVC | `direct_ok` и `canPlayType` по `direct` | зеркало (прямой файл) |
| `ready`, без HEVC | прямой файл не играет | «Этот браузер не показывает такое видео» + «Открыть в приложении» |
| `encoding` / `none` | `direct_ok` и `canPlayType` | зеркало; HLS включится позже (см. ниже) |
| `encoding` | прямой файл не играет | «Готовим для браузера, примерно N мин» (`eta`) + «Открыть в приложении» |
| `none` | прямой файл не играет | «Скоро будет готово для браузера» + «Открыть в приложении» |

   `direct` → MIME (`directMime`): `mp4`/`m4v` → `video/mp4`, `webm` → `video/webm`; `h264` → `avc1.640028`, `hevc` → `hvc1.1.6.L120.90`, `vp9`, `av1`;
   звук `aac` → `mp4a.40.2`, «плохой» звук тоже пишется в codecs (`ac-3`, `ec-3`, `dtsc`, `mlpa`), чтобы `canPlayType` честно ответил «нет». `mkv`/`avi`/`ts` → прямого просмотра нет.
   «Открыть в приложении» нажимает ту же ссылку, что «Смотреть» (приложение Android, PotPlayer, VLC). Пока окно открыто и статус `encoding`/`none`, статус переспрашивается раз в минуту.
4. Плеер — полноэкранный слой поверх окна фильма: `<video controls>`, «Закрыть» (и Esc), выбор озвучки и субтитров из `master.m3u8` (hls.js: `audioTracks`/`subtitleTracks`; Safari и зеркало — `video.audioTracks`/`textTracks`). По умолчанию — дорожка с `DEFAULT=YES`, субтитры выключены; выбор сохраняется при переключении источника (по имени, потом по языку).
5. Ошибки hls.js (`hlsErrorAction`): сеть — до 3 повторов `startLoad()`, потом новая подпись (`variant-url`) и перезапуск с того же места, потом откат; медиа — `recoverMediaError()`, затем `swapAudioCodec()` + `recoverMediaError()`, потом откат; прочее — откат. Откат — на зеркало, если `direct_ok` и браузер его играет, иначе сообщение и «Открыть в приложении». hls.js не загрузился (`vendor/hls.min.js` нет) — нативный HLS, если есть, иначе откат.
6. HLS стал готов во время просмотра зеркала: раз в 90 с переспрашивается `variant-url`; когда `ready` — надпись «Версия для браузера готова — включим, когда поставите на паузу», переключение **на паузе** (не на лету), а также при следующем запуске и на следующей серии (окно фильма заново спрашивает `variant-url`).
7. Позиции: время HLS = время файла + `shift_ms` (`toHlsMs`/`toFileMs`). Старт — с места «здесь вы остановились» (`/api/sync`, как карточка в окне фильма).
   Сохранение — `POST /api/sync {watch:[{key:"<id раздачи>|<путь>", pos, len, at}]}` во времени файла: раз в 30 с при просмотре, на паузе, в конце, при закрытии и уходе со страницы (`keepalive`).
   Сервер принимает только вход через Discord; на 403 (общий пароль) больше не шлём.

### Проверено

- `node --test website/test/*.test.js`, `npm run check`.
- Chrome 64-бит без окна (headless, Windows, без GPU, страница-стенд с фикстурами вместо сервера): `ready` без HEVC → «Этот браузер не показывает такое видео»;
  с подменой `isTypeSupported` под HEVC → «Смотреть в браузере», без `vendor/hls.min.js` → «Не удалось запустить плеер. Откройте в приложении.»; `encoding` → «Готовим для браузера, примерно 14 мин»;
  `none` → «Скоро будет готово…»; `mp4-direct` → «Смотреть в браузере», битый файл → сообщение; без блока `hls` — панели нет; в приложении (`__suslikApp`, `SuslikNative`) — панели нет.
- **Не проверено:** настоящий сайт с сервером T4, настоящее видео HLS и hls.js, Safari, Firefox, Chrome с аппаратным HEVC, переключение на паузе, сохранение в `/api/sync`.

### Ручной сценарий

Нужно: сервер с T4, `HLS_ENABLED`, пользователь в бете (`HLS_BETA_USERS`), вход через Discord (иначе позиция не сохраняется), раздачи: (А) MKV HEVC с готовым ассетом, (Б) MKV в кодировании, (В) MP4 H.264+AAC без ассета, (Г) раздача без ассета и не MP4.

Chrome (Windows с аппаратным HEVC):
1. (А) «Смотреть» → в окне есть «▶ Смотреть в браузере». В DevTools → Network: `POST variant-url`, `master.m3u8`, `index.m3u8` и `.m4s` с CDN, ошибок CSP в Console нет.
2. Переключить озвучку и субтитры, перемотать, поставить на паузу, закрыть. Открыть окно снова — «С ЧЧ:ММ» совпадает с местом закрытия (после минуты кэша `loadWatch`). Тот же фильм в приложении на ПК/Android начинает с этого места.
3. В DevTools заблокировать запросы к CDN во время просмотра — после повторов воспроизведение остановится с сообщением (у (А) `direct_ok = false`) или перейдёт на прямой файл (если `direct_ok`).
4. (Б) — «Готовим для браузера, примерно N мин» и «Открыть в приложении» (открывает PotPlayer); (Г) — «Скоро будет готово для браузера».
5. (В) — «Смотреть в браузере» играет зеркало (`/api/file/proxy/…`). Дождаться, пока ассет станет `ready`, поставить на паузу — источник меняется на HLS с того же места (с алиасом — с поправкой `shift_ms`).
6. Сериал: досмотреть серию с зеркала, пока следующая готова в HLS, — следующая серия открывается в HLS.

Safari (macOS/iOS):
7. (А) — играет нативно (в Network нет `hls.min.js`), выбор озвучки и субтитров работает, на iPhone — полноэкранный режим системы.

Firefox (без HEVC) — заглушка:
8. (А) — «Этот браузер не показывает такое видео» и «Открыть в приложении»; (В) — прямой файл; (Б) — «Готовим для браузера…».

Приложение Android (WebView с `SuslikNative`):
9. Окно фильма без новой панели, «Смотреть» открывает плеер приложения, как раньше.
