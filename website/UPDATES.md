# Обновления приложений Suslik Media

Приложения (Android и Windows) сами спрашивают сервер о новой версии: при каждом запуске.
Если версия на сервере новее установленной, появляется окно «Доступна версия …» с описанием, кнопкой
«Обновить» и «Пропустить версию».

## Как выложить обновление

Положить файл в папку **`updates/`** рядом с `server.js` (создаётся сама при старте сайта).
Версия берётся **из имени файла**, поэтому в имени должна быть версия вида `1.2.3`:

| Приложение | Файл | Пример |
|---|---|---|
| Android | `.apk` | `suslik-media-1.4.1.apk` |
| Windows | `.msi` (или `.exe`) | `Suslik Media-1.5.1.msi` |

Можно рядом положить описание изменений — файл с тем же именем и `.txt`:
`suslik-media-1.4.1.txt` — его текст покажется в окне обновления.

Сайт выбирает файл с самой большой версией и **сам удаляет прошлые версии** этой платформы (вместе с их `.txt`) — сразу после загрузки через curl/GitHub или при первом запросе после копирования по scp. Перезапускать сайт не нужно.

### Через scp (с компьютера)

```bash
scp "Suslik Media-1.5.1.msi" root@ВАШ_VPS:~/medialibrary/updates/
scp suslik-media-1.4.1.apk suslik-media-1.4.1.txt root@ВАШ_VPS:~/medialibrary/updates/
```

(в WinSCP / FileZilla — просто перетащить в папку `updates`).

### Через curl (без доступа к серверу по SSH)

В `.env` сайта задать `UPDATE_TOKEN=длинная_случайная_строка` и перезапустить сайт. Затем:

```bash
curl -H "X-Update-Token: ТОКЕН" -H "X-File-Name: suslik-media-1.4.1.apk" \
     -H "Content-Type: application/octet-stream" \
     --data-binary @app-release.apk https://short.suslikovanora.ru/api/app/upload
```

Без `UPDATE_TOKEN` загрузка по сети выключена.

## Где брать файлы

**Windows:** `.\gradlew packageMsi` → `build\compose\binaries\main\msi\Suslik Media-<версия>.msi`
(имя уже с версией). Версия задаётся в `build.gradle.kts` одной строкой `val appVersion = "…"`.

**Android:** в `app/build.gradle.kts` увеличить **`versionCode`** (на 1) и **`versionName`**, собрать APK
(Build → Generate Signed App Bundle / APK → APK), переименовать в `suslik-media-<versionName>.apk`.

Важно для Android:
- **`versionCode` должен расти** — иначе Android откажется ставить («версия ниже установленной»).
- **APK должен быть подписан тем же ключом**, что и установленная версия. Сборки Android Studio «debug» подписаны
  ключом конкретного компьютера; надёжнее один раз создать release-ключ (keystore) и подписывать им всегда.
- При первом обновлении Android попросит разрешить установку из «Suslik Media» — приложение само откроет
  нужный экран настроек, затем нажать «Установить» ещё раз.

Важно для Windows:
- Начиная с 1.5.0 у установщика постоянный идентификатор (upgradeUuid), поэтому новая версия заменяет старую.
  Версии **до 1.5.0** установщик может не заменить: один раз удалите старую через «Приложения» Windows
  и поставьте 1.5.0 — дальше обновления пойдут сами. Настройки и прогресс (папка %APPDATA%\SuslikMedia) сохраняются.

## Первый раз

Версии с проверкой обновлений: **Android 1.4.0**, **Windows 1.5.0**. Их нужно поставить вручную один раз,
дальше — через окно обновления.

## «Что нового» (тексты для пользователей)

Руками ничего делать не нужно. Тексты лежат в самих приложениях:
- Windows — `desktop/src/main/resources/changelog.json`;
- Android — `android/app/src/main/assets/changelog.json`.

Каждая сборка несёт свою историю и показывает окно «Что нового» сама, без сервера (3 последние версии не новее
установленной). На сайт эти файлы отправляет GitHub Actions: при каждом их изменении (workflow «Changelog to the site»)
и при публикации сборки. Сайт хранит их в `DATA_DIR/changelog/` и на вкладке «Приложения» показывает только
уже выложенные версии — будущая появится вместе со своим .msi / .apk.

Формат (новые сверху): `[{ "version": "1.7.0", "title": "Коротко", "items": ["Пункт простыми словами."] }]`.

## Ограничение скорости скачивания релизов (40 Мбит/с)

При отдаче установочных файлов (`.apk`, `.msi`, `.exe`) сервер передает заголовок:
```http
X-Accel-Limit-Rate: 5242880
```
Nginx на VPS автоматически считывает его и ограничивает скорость отдачи файла клиенту до **40 Мбит/с (5 МБ/с)**. Это защищает сервер от просадки сетевого канала во время скачивания больших файлов приложений (100–150 МБ) и предотвращает заикание видеопотоков у других пользователей. Поддержка докачки (`Range`) полностью сохраняется.
