## 2. Что было изменено и добавлено

### 2.1. Фоновый поиск на RuTracker с ПК без всплывающих окон
- **Проблема**: RuTracker блокирует серверные запросы (Cloudflare Turnstile и защита от ботов) и требует авторизацию по куки (`bb_session`).
- **Реализация**:
  - Запуск браузера (Edge, Chrome, Яндекс Браузер) в изолированном скрытом виртуальном рабочем столе Windows (`SuslikHiddenDesktop`) через Win32 API (`CreateDesktopW`).
  - Браузер полностью невидим: отсутствуют окна, всплытия и иконки на панели задач.
  - По завершении поиска или скачивания торрент-файла дерево процессов браузера гарантированно и полностью завершается (`taskkill /F /T` / Win32 `TerminateProcess`).
  - Выполняет поиск по `tracker.php?nm=...`, парсит результаты и позволяет скачивать `.torrent` файлы напрямую с сайта.

### 2.2. Автоопределение и поддержка всех популярных браузеров (Chrome, Яндекс, Edge, Brave, Opera, Vivaldi, Firefox)
- **Проблема**: В современных версиях Chromium на Windows куки в SQLite-базе зашифрованы с помощью Windows App-Bound Encryption (`v20`), ключ от которого защищен системной службой и недоступен оффлайн; кроме того, файл `Network/Cookies` блокируется запущенным браузером.
- **Реализация**:
  - `BrowserExecutableFinder` сканирует стандартные пути установки и реестр Windows (`App Paths`), находя все установленные браузеры.
  - Интерактивный вход в 1 клик через Chrome DevTools Protocol (CDP): для любого Chromium-браузера запускается окно с изолированным профилем и отслеживается успешный вход на трекер через `Storage.getCookies`.
  - Как только пользователь авторизован, куки (`bb_session`, `bb_ssl`, `cf_clearance`) моментально извлекаются и сохраняются в настройках, а окно закрывается.
  - Для Firefox реализовано прямое чтение и парсинг локальной SQLite-базы `cookies.sqlite`.

### 2.3. Настройки трекеров в интерфейсе поиска
- В окно поиска добавлена кнопка **«Трекеры (ПК ✓)»** с диалоговым окном на 2 вкладки:
  - **Вкладка 1: «Локальные трекеры»** — ввод cookie для RuTracker, кнопка проверки соединения, выбор браузера для подсказки путей / 1-клик входа.
  - **Вкладка 2: «Выбор трекеров»** — переключатели (toggle) для каждого отдельного трекера (Rutor, RuTracker, NNM-Club, Kinozal, The Pirate Bay, Nyaa). Позволяет отключать ненужные трекеры на лету.

### 2.4. Проверка типов файлов при добавлении раздач
- При ручном добавлении пользователем magnet-ссылок или файлов `.torrent` выполняется валидация структуры Bencode (`TorrentInspector.kt`).
- Анализируется список файлов внутри раздачи:
  - Если раздача не содержит поддерживаемых видеофайлов (`.mkv`, `.mp4`, `.avi`, `.mov`, `.webm`, `.ts`, `.m2ts`), добавление отклоняется с понятным сообщением (например, при попытке добавить игру, музыку или софт).

### 2.5. Фильтрация тизеров, трейлеров и не-видео контента
- Добавлена Unicode-регулярка (`?iu`) для распознавания тизеров и трейлеров: отсекаются слова `тизер`, `трейлер`, `тизер-трейлер`, `teaser`, `trailer`.
- Фейковые раздачи вроде *«Человек-паук: Новый день [2026] тизер-трейлер»* автоматически исключаются из выдачи.
- Отсекаются игры и программное обеспечение (сигнатуры `FPKG`, `RePack`, `GOG`, `FitGirl`, не-видео категории трекеров).

### 2.6. Умная релевантность и автоочистка стоп-слов
- `SearchQueryCleaner`: очищает запрос от мусорных слов (*«фильмы», «сериал», «кино», «смотреть», «скачать», «онлайн», «в хорошем качестве»*). Запрос *«фильмы новый человек паук»* трансформируется в *«новый человек паук»*.
- `computeRelevanceScore`: система оценки совпадения:
  - Старт названия с точной фразы запроса: **+2000 баллов** (фильм «Новый Человек-паук» поднимается выше старого «Человек-паук»).
  - Наличие всех слов запроса в правильном порядке: **+850 баллов**.
  - Совпадение указанного в запросе года выпуска: **+1500 баллов** (несовпадающие года штрафуются на **-1500**).
  - Штраф за экранки (CAM/TS): **-300 баллов**, штраф за мертвые раздачи без сидов: **-250 баллов**.

### 2.7. Исправление багов трекеров Rutor и NNM-Club
- **Rutor (поиск с годом давал 0 результатов)**:
  - *Причина*: Движок Sphinx на Rutor требует строгой близости слов. Все релизы оформлены как `Русское название / English Title (ГОД)`. Русское название отделено от года английским названием, поэтому поиск `[Русское название] [ГОД]` всегда возвращал 0 результатов на самом трекере.
  - *Решение*: Если запрос с годом возвращает 0 результатов, сервер автоматически опрашивает Rutor без года (получая все раздачи фильма) и точно фильтрует релизы по запрошенному году (`2012`).
- **NNM-Club (выдача случайных фильмов 2012 года)**:
  - *Причина*: В коде стояло кодирование параметров в Windows-1251 (`encodeCp1251`). Веб-сервер NNM-Club ожидает UTF-8 и вырезал все кириллические байты как невалидные, оставляя в запросе только цифры `2012`. В результате трекер искал по запросу `2012` и вываливал случайные фильмы, софт и уроки 2012 года.
  - *Решение*: Кодирование запроса к NNM-Club переведено на нативный UTF-8 (`encodeURIComponent`). Поиск `новый человек паук 2012` теперь находит именно раздачи фильма «Новый Человек-паук (2012)».
