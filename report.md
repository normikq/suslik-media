## 2. Что было изменено и добавлено

### 2.1. Фоновый поиск на RuTracker с ПК без всплывающих окон
- **Проблема**: RuTracker блокирует серверные запросы (Cloudflare Turnstile и защита от ботов) и требует авторизацию по куки (`bb_session`).
- **Реализация**:
  - Запуск браузера (Edge, Chrome, Яндекс Браузер) в изолированном скрытом виртуальном рабочем столе Windows (`SuslikHiddenDesktop`) через Win32 API (`CreateDesktopW`).
  - Браузер полностью невидим: отсутствуют окна, всплытия и иконки на панели задач.
  - По завершении поиска или скачивания торрент-файла дерево процессов браузера гарантированно и полностью завершается (`taskkill /F /T` / Win32 `TerminateJobObject`).
  - Выполняет поиск по `tracker.php?nm=...`, парсит результаты и позволяет скачивать `.torrent` файлы напрямую с сайта.

### 2.2. Автоопределение и поддержка всех популярных браузеров (Chrome, Яндекс, Edge, Brave, Opera, Vivaldi, Firefox)
- **Проблема**: В современных версиях Chromium на Windows куки в SQLite-базе зашифрованы с помощью Windows App-Bound Encryption (`v20`), ключ от которого защищен системной службой и недоступен оффлайн; кроме того, файл `Network/Cookies` блокируется запущенным браузером.
- **Реализация**:
  - `BrowserExecutableFinder` сканирует стандартные пути установки и реестр Windows (`App Paths`), находя все установленные браузеры.
  - Интерактивный вход в 1 клик через Chrome DevTools Protocol (CDP): для любого Chromium-браузера запускается окно с изолированным профилем и отслеживается успешный вход на трекер через `Storage.getCookies`.
  - Как только пользователь авторизован, куки (`bb_session`, `bb_ssl`, `cf_clearance`) моментально извлекаются и сохраняются в настройках, а окно закрывается.
  - Для Firefox реализовано прямое чтение и парсинг локальной SQLite-базы `cookies.sqlite`.

### 2.3. Исключение зависания процессов браузера в фоне (Windows Job Object)
- **Проблема**: При завершении браузера дочерние процессы (GPU, Crashpad, Utility, Renderers) могли оставаться висеть в памяти.
- **Решение**:
  - Все запускаемые браузерные процессы привязываются к Windows Job Object с флагом `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`. При вызове `stop()` или закрытии приложения ОС Windows уничтожает всю группу процессов целиком.
  - Метод `killProcessTree` принудительно снимает дерево процессов через `taskkill /F /T /PID`.
  - Метод `cleanOrphanTrackerProcesses()` при старте и завершении сканирует и устраняет любые зависшие процессы с профилями трекера (`_tracker_profile`).
  - Таймаут ожидания неактивного браузера уменьшен с 90 до 15 секунд.

### 2.4. Проверка подключения к RuTracker через CDP
- **Проблема**: Старая проверка `testConnection()` делала прямой запрос через Java `HttpClient` и всегда блокировалась Cloudflare Turnstile («Just a moment»).
- **Решение**:
  - В `EdgeBrowserBridge` добавлен метод `checkConnection(baseUrl, cookies)`: проверка проходит через движок браузера, благодаря чему Cloudflare Turnstile проходится автоматически.
  - Считывается имя авторизованного пользователя (`✓ Авторизован как <user> (<browser>)`) и диагностируется недействительная сессия.

### 2.5. Устранение микрофризов интерфейса
- **Проблема**: Вызов остановки браузера и запись настроек выполнялись синхронно в UI-потоке Event Dispatch Thread.
- **Решение**:
  - Закрытие диалога `onDismiss()` срабатывает моментально (0 мс).
  - Остановка браузера перенесена в `EdgeBrowserBridge.stopAsync()`, работающий в пуле `Dispatchers.IO`.
  - Запись настроек `Store.flushAll()` вынесена в `Dispatchers.IO`.

### 2.6. Настройки трекеров в интерфейсе поиска
- В окно поиска добавлена кнопка **«Трекеры (ПК ✓)»** с диалоговым окном на 2 вкладки:
  - **Вкладка 1: «Локальные трекеры»** — ввод cookie для RuTracker, кнопка быстрой проверки соединения, выбор браузера для 1-клик входа.
  - **Вкладка 2: «Выбор трекеров»** — переключатели (toggle) для каждого отдельного трекера (Rutor, RuTracker, NNM-Club, Kinozal, The Pirate Bay, Nyaa). Позволяет отключать ненужные трекеры на лету.

### 2.7. Проверка типов файлов при добавлении раздач
- При ручном добавлении пользователем magnet-ссылок или файлов `.torrent` выполняется валидация структуры Bencode (`TorrentInspector.kt`).
- Если раздача не содержит поддерживаемых видеофайлов (`.mkv`, `.mp4`, `.avi`, `.mov`, `.webm`, `.ts`, `.m2ts`), добавление отклоняется с понятным сообщением (игры, софт, музыка).

### 2.8. Фильтрация тизеров, трейлеров и не-видео контента
- Добавлена Unicode-регулярка (`?iu`) для распознавания тизеров и трейлеров: отсекаются слова `тизер`, `трейлер`, `тизер-трейлер`, `teaser`, `trailer`.
- Фейковые раздачи вроде *«Человек-паук: Новый день [2026] тизер-трейлер»* автоматически исключаются из выдачи.
- Отсекаются игры и программное обеспечение (сигнатуры `FPKG`, `RePack`, `GOG`, `FitGirl`, не-видео категории трекеров).

### 2.9. Умная релевантность и автоочистка стоп-слов
- `SearchQueryCleaner`: очищает запрос от мусорных слов (*«фильмы», «сериал», «кино», «смотреть», «скачать», «онлайн», «в хорошем качестве»*).
- `computeRelevanceScore`: система оценки совпадения (старт названия +2000, порядок слов +850, год +1500, штрафы за экранки CAM/TS и мертвые раздачи).

### 2.10. Исправление багов трекеров Rutor и NNM-Club
- **Rutor (поиск с годом давал 0 результатов)**: автоматический опрос без года и локальная фильтрация по году.
- **NNM-Club (выдача случайных фильмов 2012 года)**: перевод запросов на нативный UTF-8 (`encodeURIComponent`).
