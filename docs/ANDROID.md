# Suslik Media — Android-приложение (`android/`)

Документация по мобильному клиенту Suslik Media для телефонов, планшетов и ТВ-приставок (Android TV): архитектура, модули плеера, интеграция с общим ядром `shared/`, отладка и сборка.

---

## 1. Стек технологий

- **Язык:** Kotlin 2.0+ (JVM 17 байткод).
- **Интерфейс:** Jetpack Compose (Material 3), Compose Navigation, Accompanist.
- **Видеоплеер:** нативный **libVLC 3.6** для Android (`org.videolan.android:libvlc-all`).
- **Сетевой слой:** OkHttp 4 (с кастомной стратегией ретраев на мобильных сетях).
- **Асинхронность:** Kotlin Coroutines & Flow.
- **Общий модуль:** прямая зависимость от `:shared` (модели, локальный прокси `BurstProxy`, сторож плеера `PlaybackSupervisor`, Blu-ray расчеты `TsClock`).

Идентификатор пакета:
- Релизная сборка: `ru.suslikovanora.media`
- Диагностическая сборка (Suslik Debug): `ru.suslikovanora.media.diag`

## 3. Декомпозиция модулей плеера (`player/`)

Вся логика плеера разделена на изолированные контроллеры, координируемые через `PlayerActivity`:

| Контроллер | Обязанности и особенности реализации |
|---|---|
| `PlayerAudioSession.kt` | Управление `MediaSessionCompat` для системных медиа-нотификаций и Bluetooth-кнопок. Реализация `AudioFocusRequest` (приглушение звука при вызовах и навигации). Реакция на `ACTION_AUDIO_BECOMING_NOISY` (автоматическая пауза при отключении наушников). |
| `PlayerGestures.kt` | Обработка touch-событий в Compose: горизонтальный свайп для перемотки с визуальным таймкодом; вертикальный свайп по левому краю — яркость экрана (`WindowAttributes.screenBrightness`); вертикальный свайп по правому краю — громкость; pinch-to-zoom для изменения масштабирования кадра (Fill / Fit / 100%); двойной тап по краям экрана для шага перемотки ±10 с. |
| `PlayerNetworkMonitor.kt` | Слушатель `ConnectivityManager.NetworkCallback`. Отслеживает переход между Wi-Fi и мобильной сетью, а также смену IP при обрыве VPN (`tun0`). Инициирует мягкий реконнект видеопотока с сохранением точной миллисекунды. |
| `PlayerBluRayController.kt` | Работа с потоками Blu-ray (`.m2ts`): расчет точной длительности через парсер меток времени PCR (`TsClock`). Кусочно-линейная интерполяция перемотки по контрольным точкам без накопления погрешности на VBR потоках. Поддержка функции «Продолжить» со смещением времени. |
| `PlayerTrackSelector.kt` | Парсинг и переключение аудиодорожек и субтитров. Загрузка внешних аудиодорожек и субтитров (sidecars). Мгновенный сброс буфера `reseekHereNow` для устранения 3-секундной задержки смены аудио. Сохранение предпочтений языка. |
| `PlayerPipController.kt` | Вход в режим «Картинка в картинке» (PiP): расчет соотношения сторон `PictureInPictureParams.Builder.setAspectRatio` с учетом реального SAR видеоряда. Автоматический вход при сворачивании на Android 12+ (`setAutoEnterEnabled(true)`). |
| `PlayerWatchProgress.kt` | Сохранение текущей позиции просмотра в SharedPreferences по композитному ключу раздачи и пути файла. Логика порогов: при просмотре > 92% серия считается просмотренной; при > 98% прогресс сбрасывается в начало. Защита от перезаписи сохранённой позиции значением 00:00 во время открытия потока. |
| `PlayerPlaylistQueue.kt` | Поддержка плейлистов сериалов (`.m3u`): навигация «Предыдущая / Следующая серия», отображение индекса (например, «3/12»), плашка обратного отсчета с кнопкой отмены перед автопереходом к следующему эпизоду. |
| `PlayerControlsOverlay.kt` | Контроль видимости интерфейса поверх видео: таймер автоскрытия (3.8 с), плавные анимации выезда панелей, режим блокировки от случайных касаний («экранный щит»). Управление системными барами (System Bars / Immersive Mode). |
| `PlayerDiagnostics.kt` | Периодический опрос состояния плеера и сетевого запаса (каждые 5 секунд вывод в лог `[vlc]` и `[proxy]`). Обнаружение необходимости программного декодирования (например, кодек VC-1 на процессорах Exynos) и автоматический перезапуск с программным декодером. Управление динамической частотой обновления дисплея (`Surface.setFrameRate`) на Android 11+. |

## 4. Интеграция с ядром `shared/` (`BurstProxy` и `PlaybackSupervisor`)

Android-приложение воспроизводит видео не по прямой ссылке сервера, а через локальный HTTP-прокси, работающий внутри самого приложения:

```
[Сервер зеркала] ◄── HTTPS (интернет) ──► [BurstProxy (127.0.0.1)] ◄── HTTP (loopback) ──► [LibVLC]
                                                │
                                                ▼
                                    [Кольцевой кэш на диске]
```

1. **Скачивание рывками (`BurstProxy`):**
   - Прокси скачивает видео порциями на максимальной скорости мобильного радио, заполняя дисковый кольцевой буфер (до 128 МБ / 256 МБ в зависимости от пресета).
   - После заполнения запаса радиомодуль телефона переходит в энергосберегающий спящий режим, что радикально снижает нагрев и расход батареи.
2. **Режим «Сеть медленнее фильма — копим запас» (`hold`):**
   - Если скорость сети падает ниже 1.15× от битрейта видео, прокси удерживает отдачу данных в VLC, накапливая до 30 секунд фильма в буфер, после чего отпускает поток.
   - Плеер не рассыпает картинку на макроблоки и не останавливается каждые несколько секунд.
3. **Сторож воспроизведения (`PlaybackSupervisor`):**
   - Каждые 5 секунд анализирует метрики libVLC: число декодированных кадров, время аудио-PTS, позицию.
   - При обнаружении застывшего кадра или зависания таймера сторож последовательно выполняет мягкое восстановление (перезапуск видеопайплайна → перевыбор дорожки → переоткрытие потока с текущего места).

## 5. Сетевой уровень и работа на нестабильных каналах (`net/Api.kt`)

Специфика мобильных сетей в РФ (высокий джиттер, потеря SYN-пакетов при первичном подключении, обрывы VPN-туннелей):
- Сетевой клиент `Api.kt` реализует агрессивные тайм-ауты на первичное подключение: 6 секунд на первый запрос, 8 на второй, 10 на третий. При отсутствии ответа сокет принудительно разрывается и создаётся заново на чистом соединении.
- Ошибки «нет сети» (`UnknownHostException`, потеря default network) не сжигают счетчик попыток ретрая — плеер переходит в режим ожидания и мгновенно возобновляет работу, как только `ConnectivityManager` сообщает о появлении сети.

## 6. Отладка и диагностическая сборка (Suslik Debug)

Для расследования сложных плавающих проблем воспроизведения и энергопотребления собирается вариант **`diag`** (флавор сборки):
- Устанавливается параллельно с релизной версией (`ru.suslikovanora.media.diag`).
- В интерфейсе плеера появляется кнопка 📍 (**Метка**), которая при нажатии записывает в лог тег `[mark]`. Это позволяет пользователю зафиксировать точный момент заикания звука или артефакта картинки.
- Полный журнал пишется в общедоступный файл:
  `Android/data/ru.suslikovanora.media.diag/files/diag/player.log`.
- Теги журналов:
  - `[vlc]` — состояние декодера VLC (кадры, время, буферизация).
  - `[proxy]` — запас буфера на диске, скорость сети, размер рывка.
  - `[net]` — события переключения сетей и VPN.
  - `[sys]` / `[battery]` — нагрузка процессора, уровень заряда, температура.
  - `[http]` — каждый исходящий сетевой запрос и его тайминги.
- Подробные инструкции по снятию дампа батареи и журналов приведены в [`android/DEBUG-BUILD.md`](file:///c:/Users/nanar/OneDrive/Desktop/suslik-media-mpv/android/DEBUG-BUILD.md).

## 7. Сборка и релизы

### Локальная сборка:
```powershell
# Сборка релизного APK
./gradlew assembleRelease

# Сборка диагностической версии Suslik Debug
./gradlew assembleDiag

# Быстрая установка отладочной версии на подключённый телефон по ADB
./install-android-debug.ps1
```

### Версионирование:
- Номер версии задаётся в `android/app/build.gradle.kts`:
  - `versionCode` (целое число, монотонно увеличивается).
  - `versionName` (формат `2.x.x`).
- При изменении функционала текст для пользователей добавляется в начало `android/app/src/main/assets/changelog.json`.

### GitHub Actions (`android.yml`):
- Запускается при пуше изменений в `android/` или `shared/`.
- Собирает артефакты `android-apk` и `android-debug-apk`.
- При ручном запуске с параметром `publish=true` загружает подписанный APK на сайт в канал `beta` или `stable`.
