# Обновления приложений Suslik Media

Приложения (Android и Windows) спрашивают сервер о новой версии при запуске (`GET /api/app/update?platform=…`).
Если версия на сервере новее установленной, появляется окно «Доступна версия …» с описанием, кнопками «Обновить»
и «Пропустить версию». Samsung TV самообновления не имеет — его ставят вручную (`tizen/README.md`).

## Каналы: бета и стабильный

- **Бета** — папка `updates/beta/`. Её видят только тестировщики: приложение шлёт код из «Настройки → Бета-версии»
  (`X-Beta-Code`, должен совпасть с `BETA_CODE` в `.env`).
- **Стабильный** — папка `updates/`, видят все.
- Тестировщику предлагается бета, если она новее стабильной.
- «Выпустить всем» (`POST /api/app/promote`, workflow `promote.yml`) переносит бету в стабильный канал.

Версия берётся **из имени файла**: `suslik-media-<V>-b<код>.apk`, `Suslik Media Setup-<V>.exe` (или `.msi`).
Сайт выбирает файл с самой большой версией и сам удаляет прошлые версии этой платформы. Перезапускать сайт не нужно.

## Как выложить

Обычно — из GitHub Actions: `android.yml` / `desktop.yml` с `publish=true` и `channel=beta`, потом `update-status.yml`
(что видит сайт), по команде «выпускай всем» — `promote.yml`. Сборки грузятся так:

```bash
curl -H "X-Update-Token: ТОКЕН" -H "X-File-Name: suslik-media-2.7.0-b73.apk" -H "X-Channel: beta" \
     -H "Content-Type: application/octet-stream" \
     --data-binary @app-release.apk "$SITE_URL/api/app/upload"
```

`SITE_URL` — адрес сервера с путём, если он не в корне (`https://<домен>[/путь]`). Без `UPDATE_TOKEN` в `.env`
загрузка по сети выключена. Файл можно и просто положить в `updates/` (или `updates/beta/`) по scp: сервер
предложит его через минуту после того, как он перестал меняться.

Важно для Android: **`versionCode` должен расти**, и APK подписывается тем же release-ключом (секреты `ANDROID_KEYSTORE_B64` и
др.), иначе Android не поставит обновление. При первом обновлении Android попросит разрешить установку из «Suslik Media».

Важно для Windows: обновление запускает `Suslik Media Setup.exe /update` (MSI внутри, постоянный upgradeUuid);
настройки и прогресс (`%APPDATA%\SuslikMedia`) сохраняются.

## «Что нового» (тексты для пользователей)

Тексты лежат в самих приложениях: `desktop/src/main/resources/changelog.json`, `android/app/src/main/assets/changelog.json`
(Tizen — `tizen/js/changelog.js`). Каждая сборка показывает «Что нового» сама, без сервера. На сайт эти файлы
отправляет GitHub Actions: при пуше в `main` с изменённым changelog (`changelog.yml`) и при публикации сборки. Сайт хранит
их в `DATA_DIR/changelog/` и на вкладке «Приложения» показывает только уже выложенные версии.

Формат (новые сверху): `[{ "version": "2.7.0", "title": "Коротко", "items": ["Пункт простыми словами."] }]`.

## Ограничение скорости скачивания релизов (40 Мбит/с)

При отдаче установочных файлов (`.apk`, `.msi`, `.exe`) сервер передаёт заголовок `X-Accel-Limit-Rate: 5242880`:
nginx ограничивает скорость отдачи до 5 МБ/с, чтобы скачивание обновления не мешало видео у других. Докачка (`Range`)
работает.
