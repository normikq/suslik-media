# Suslik Media: как устроен проект

Подробная карта проекта: что из чего состоит, как фильм доходит до экрана, где какой код и куда смотреть, если
хочется что-то поменять. Состояние на 16.10.2026: Android 2.2.3, Windows 2.2.1.

---

## 1. Общая картина

Suslik Media — частная медиатека поверх **AllDebrid**. AllDebrid сам скачивает торренты на свои серверы и отдаёт
готовые файлы по прямым ссылкам. Но в России AllDebrid заблокирован, поэтому все запросы и само видео идут через
ваш сервер (VPS), который работает как **зеркало**.

```
                 ┌──────────────────────── ваш VPS ───────────────────────┐
  AllDebrid  ◄───┤  nginx (HTTPS, без http2)  ──►  Node.js (website/)     │
  (файлы,        │     │   отдаёт видео сам          API: вход, медиатека,│
   торренты,     │     │   (X-Accel-Redirect)        поиск, ссылки,       │
   API)          │     │                             обновления приложений│
                 │  Xray (VPN) — на том же сервере                        │
                 └─────┬──────────────────────────────────────────────────┘
                       │ HTTPS
        ┌──────────────┼───────────────────┬──────────────────────────┐
        ▼              ▼                   ▼                          ▼
   Сайт (браузер)   Android-приложение   Windows-приложение     GitHub Actions
   public/index.html  android/            desktop/               (сборки, выпуск)
                        └── общий код shared/ ──┘
```

Три части:

| Часть | Технологии | Что делает |
|---|---|---|
| `website/` | Node.js + Express, один HTML с JS | сервер: вход, медиатека, поиск торрентов, ссылки и зеркало видео, раздача обновлений приложений; плюс сам сайт |
| `android/` | Kotlin, Jetpack Compose, libVLC 3.6 | приложение для телефона и ТВ-приставок |
| `desktop/` | Kotlin, Compose Desktop, vlcj (VLC, установленный на ПК) | приложение для Windows |
| `shared/` | чистый Kotlin (без Android и без окон) | общий код обоих приложений: запас фильма, сторож воспроизведения, Blu-ray, модель медиатеки, версии |

## 2. Путь одного фильма: от нажатия до картинки

1. **Медиатека.** Приложение спрашивает сервер `GET /api/library`. Сервер берёт список «магнетов» (раздач) у AllDebrid,
   кеширует его и отдаёт в упрощённом виде. В `shared/Model.kt` этот ответ разбирается: раздача → файлы → фильм или
   сериал по сезонам, субтитры и внешние озвучки рядом с видео.
2. **Ссылка.** При выборе фильма приложение просит у сервера `GET /api/file/mirror-url?link=…`. Сервер возвращает
   **подписанную ссылку зеркала**:
   `https://ваш-сайт/api/file/proxy/<имя>?link=<ссылка AllDebrid>&exp=<срок>&sig=<подпись>`.
   Подпись — HMAC с секретом сервера: без неё зеркало не отдаст файл, и ссылка работает ограниченное время.
   (Параллельно спрашивается `POST /api/file/unlock` — прямая ссылка AllDebrid, вариант «Напрямую».)
3. **Зеркало на сервере.** Запрос на `/api/file/proxy` приходит в Node: он проверяет подпись и узнаёт у AllDebrid
   настоящий адрес файла. Сами байты видео отдаёт **nginx** (заголовок `X-Accel-Redirect`, настройка в
   `website/NGINX-MIRROR.md`), чтобы Node на одном ядре не гонял через себя гигабайты. Если ссылка AllDebrid устарела,
   nginx возвращает запрос в Node, тот получает свежую.
4. **Запас на устройстве (`BurstProxy`).** Приложение не даёт VLC ссылку зеркала напрямую. Оно запускает на устройстве
   крошечный HTTP-сервер `127.0.0.1` и даёт VLC адрес на нём. Этот прокси качает фильм с зеркала **рывками** вперёд
   (до ~130 с фильма, не больше 256 МБ) в кольцевой файл, а VLC читает уже с диска. Зачем: радио телефона отдыхает
   между рывками, обрывы связи не прерывают фильм, внешняя озвучка не расходится с видео.
5. **VLC** читает с локального прокси и показывает видео. Над ним работает **сторож** (`PlaybackSupervisor`): замечает
   застывшую картинку, пропавший звук, «стоящие часы» и мягко чинит (перезапуск видео → перевыбор звука → переоткрытие).
6. **Прогресс** (где остановились) хранится на устройстве по ключу «раздача + путь файла», чтобы работало «Продолжить».

## 4. Сервер и сайт (`website/`)

> 📖 **Подробная документация:** [docs/WEBSITE.md](WEBSITE.md)

### Файлы

| Файл | Что внутри |
|---|---|
| `server.js` (~1690 строк) | весь сервер: вход, медиатека, поиск, ссылки, зеркало, плейлисты, постеры, обновления приложений, отчёты об ошибках |
| `search.js` | мета-поиск торрентов по трекерам (через Prowlarr/Jackett и др.), единый формат результатов |
| `search-ru.js` | парсеры русских трекеров (rutor, rutracker, kinozal, NNM-Club), кодировка windows-1251 |
| `classify.js` | определяет тип раздачи по названию/категориям: сериал, фильм, «другое» |
| `public/index.html` | сам сайт: одна страница с HTML, CSS и JS внутри |
| `public/redesign.css`, `redesign.js` | оформление и анимации сайта |
| `index.html` | копия `public/index.html` (проверяется скриптом проверки) |
| `client-check.js`, `client-inline-check.js` | копии клиентского скрипта, нужны только для проверки синтаксиса |
| `scripts/check.js` | проверка синтаксиса всего JS и встроенных скриптов страницы (`npm run check`) |
| `test/classify.test.js` | модульные тесты классификатора раздач (`npm test` или `node --test`) |
| `NGINX-MIRROR.md` | как настроить nginx, чтобы он сам отдавал видео |
| `TORAPI.md`, `UPDATES.md`, `README*.txt` | заметки по отдельным доработкам |
| `.env` (не в репозитории) | секреты: ключ AllDebrid, пароль входа, секрет подписи, `UPDATE_TOKEN`, `BETA_CODE`; образец — `.env.example` |

### Маршруты `server.js` по группам

| Группа | Маршруты | Смысл |
|---|---|---|
| Вход | `POST /api/login`, `/api/logout`, `GET /api/session` | вход по паролю, сессия в cookie, защита от перебора |
| Медиатека | `GET /api/library`, `/api/magnets/:id`, `/api/magnets/:id/files`, `POST /api/magnets/:id/cancel` (и удалить) | список раздач, файлы раздачи, отмена/удаление |
| Добавление | `POST /api/magnets` (magnet-ссылка), `/api/torrents` (.torrent), `/api/unlock` | отправить раздачу в AllDebrid |
| Поиск | `GET /api/search`, `POST /api/search/add`, `/api/favorites` | поиск по трекерам, добавить найденное, избранное |
| Ссылки и видео | `POST /api/file/unlock`, `GET /api/file/mirror-url`, `GET /api/file/proxy/...` | прямая ссылка, подписанная ссылка зеркала, само зеркало |
| Сериалы | `POST /api/playlist`, `GET /api/playlist/:id/:name` | плейлист серий до конца сезона (.m3u) |
| Оформление | `POST /api/media-metadata`, `GET /api/poster`, `/api/poster/img/...` | постеры и описания фильмов (с кешем) |
| Приложения | `GET /api/app/update`, `/api/app/download/...`, `/api/app/beta…`, `POST /api/app/upload`, `/api/app/promote`, `GET /api/app/status`, `GET/POST /api/app/changelog` | раздача обновлений, каналы «релиз/бета», загрузка сборок из CI |
| Ошибки | `POST /api/app/report`, `GET /api/app/reports` | приложения присылают отчёты о сбоях |

Небольшие данные сервер хранит в JSON-файлах рядом с собой (сессии, кеш медиатеки и файлов раздач, кеш метаданных),
сборки приложений — в папке `updates/` (с подпапкой для беты).

### Что важно помнить
- Пуш в GitHub **не обновляет сервер**: workflow `website.yml` только проверяет синтаксис. На сервер код ставите вы.
- Зеркало нельзя заменять прямыми ссылками AllDebrid (блокировка в РФ).
- nginx без http2, потому что на сервере ещё Xray.

## 5. Общий модуль (`shared/`)

Код, который одинаково нужен Android и Windows. В нём нет ничего про экран, поэтому он покрыт модульными тестами
(`shared/src/test/...`, запускаются в CI на каждый пуш с изменениями в `shared/`):
- `ModelTest.kt` — парсинг ответа сервера, сериалы по папкам и именам, коллекции фильмов, очистка названий, внешние дорожки и субтитры, статусы и прогресс;
- `BurstProxyTest.kt` — локальный прокси, кольцевые файлы, скачивание рывками, смены сети, hold-буферизация, тайм-ауты;
- `TsClockTest.kt` — расчет длительности Blu-ray по меткам PCR, перемотка, сетка контрольных точек VBR;
- `CoreTest.kt` — сравнение версий (`Versions`), вердикты каналов, парсинг `changelog.json`, сторож плеера (`PlaybackSupervisor`), очистка кэша (`LibraryKeep`), формат времени (`clockText`), правила «копим запас» (`CatchUp`);
- `MirrorLinkTest.kt` — подписанные адреса зеркала: ключ файла, срок подписи, адрес для обновления.

| Файл | Что делает |
|---|---|
| `BurstProxy.kt` (~1000 строк) | **запас фильма**: локальный HTTP-сервер для VLC, «окна» в кольцевых файлах, рывки между нижней и верхней границей запаса (по битрейту фильма), короткий разгон после открытия/перемотки, сторож зависших запросов (`headerStallMs`, `bodyStallMs`), быстрый сброс соединений при разрыве сокетов/таймаутах и мгновенный повтор при голодающем буфере, перезапуск запросов при смене сети, ожидание без сети, «мосты» при перемотке назад, «копим запас» (`hold`) на сети медленнее фильма, замер скорости сети, адаптивная глубина запаса (`reserveSeconds`), порции с запасом на «съедание» буфера плеером, кэш конца файла в памяти (`tailCache`), остановка при выключенном экране/закрытом фильме/без сети (`stopped()`), `readRange` для маленьких кусков, новая подпись адреса вместо ошибки, когда старая истекла (`refreshUrl`, ответ 401/403) |
| `PlaybackSupervisor.kt` | **сторож воспроизведения**: по статистике VLC решает, что картинка застыла, звук пропал или часы стоят, и выбирает действие (по одному, с паузами и бюджетом на серию) |
| `TsClock.kt` | **Blu-ray (.m2ts)**: длительность по «часам» потока (PCR), сетка контрольных точек (срезы 25%, 50%, 75%) для кусочно-линейной интерполяции переменного битрейта (VBR), динамическое обучение (`learn`) в процессе воспроизведения, кэширование по ссылке |
| `TsPlayback.kt` | **Blu-ray**: общие решения для обоих плееров — точная перемотка по контрольным точкам (`TsClock.posFor`), «Продолжить» со смещением времени, динамическое обучение при воспроизведении |
| `Model.kt` | **модель медиатеки**: разбор ответа сервера, раздачи и файлы, главный видеофайл, сериалы по сезонам и сериям, субтитры и внешние озвучки, ключ прогресса просмотра |
| `PlaybackPresets.kt` | варианты настроек «Запас фильма» (до 160 и 256 МБ для 4K/Remux) и «Буфер плеера» |
| `MirrorLink.kt` | **адрес зеркала** `/api/file/proxy/<имя>?link=…&exp=…&sig=…`: ключ файла без подписи (`fileKey`, им пользуются `BurstProxy`, `TsClock`, выбор движка), срок подписи (`isExpired`), запрос новой подписи (`renewPath` → `/api/file/mirror-url`) |
| `CatchUp.kt` | правила «копим запас» для обоих плееров: когда начинать, прогресс, когда заканчивать и нужна ли перемотка для перезапуска декодеров |
| `TimeText.kt` | `clockText(ms)` — время «05:03» / «1:05:03» в обоих приложениях |
| `LibraryKeep.kt` | что оставить после обновления медиатеки (постеры, прогресс, запас на диске) |
| `Versions.kt` | сравнение версий (`2.2.3` новее `2.2.1` и т.п.) |
| `Changelog.kt` | чтение `changelog.json` («Что нового») |

### Архитектура плеера Windows (`player/`)

Плеер на Windows совмещает **прямой аппаратный вывод 4K HDR видео** через mpv или libVLC с **современным полупрозрачным UI на Compose Desktop**:

1. **Решение проблемы наложения тяжелых компонентов (Airspace Problem):**
   - Библиотека libVLC рисует видео через DirectX/Direct3D напрямую в нативный системный Win32 HWND (`java.awt.Canvas`), заполняющий главное окно приложения. Это даёт 0% нагрузки на CPU при воспроизведении тяжелых 4K Remux файлов.
   - Любые стандартные легковесные Compose-компоненты, расположенные в том же окне в `Box` поверх `Canvas`, перекрываются видеокартой (флаг `compose.interop.blending` работает только для обычных Swing `JPanel`, но не для нативных DirectX HWND).
   - **Двухоконная схема (`topDialog` и `bottomDialog`):** интерфейс управления вынесен в два независимых дочерних окна `ComposeDialog(owner)` с `isUndecorated = true` и `isTransparent = true`. Это активирует нативную попиксельную альфа-прозрачность Skiko/DirectX на уровне Windows DWM.
   - **Свободный центр экрана:** верхний оверлей занимает 75px, нижний — окно высотой 460px, но кликабельна и рисуется только нужная его часть (см. «Стабильная высота нижнего оверлея»). Центральная область кадра не перекрыта: клики (пауза/плей), двойной клик (полный экран) и колесико мыши (громкость) попадают в слой Compose главного окна без задержек.
   - **`focusableWindowState = false`:** оверлеи не перехватывают фокус операционной системы при кликах на кнопки, поэтому все горячие клавиши в главном окне (`Space`, `F`, `F11`, `Enter`, `Esc`, `←`/`→`, `↑`/`↓`, `T`, `S`, `I`) работают без потери фокуса.
   - **Мгновенная синхронизация координат без задержек (Zero-Lag Bounds Sync):** положение и габариты оверлеев синхронизируются через `syncOverlayBounds()`, привязанный напрямую к `contentPane` корневого окна (`RootPaneContainer`). В отличие от внутреннего `Canvas` внутри `SwingPanel`, размеры которого обновляются Compose с опозданием на несколько кадров, геометрия `contentPane` обновляется AWT/Win32 мгновенно. Слушатель `.onSizeChanged` на корневом контейнере гарантирует адаптацию оверлеев без задержек и «залипания» координат при изменении размера окна.
   - **Стабильная высота нижнего оверлея (Zero-Jitter):** окно `bottomDialog` всегда высотой 460px, поэтому открытие и закрытие меню не меняет его размер и не перестраивает Compose. Область, которая рисуется и принимает мышь, ограничивается системной областью окна (`WindowMode.clipToBottom` → `SetWindowRgn`, с учётом масштаба экрана): 220px, пока меню закрыто, и все 460px, пока открыто меню или инфо-панель (`tallBottom`, сужение с задержкой 0,4 с под анимацию закрытия). Так прозрачная верхняя часть не перехватывает клики по видео. Положение окон дополнительно сверяется с холстом раз в 300 мс (`setBounds` только при расхождении).

2. **Дизайн и эргономика «Жидкое стекло» (Liquid Glass & Obsidian Cards):**
   - **Монохромный минималистичный стиль:** элементы управления и оверлеи выполнены в строгом монохроме с высоким контрастом без визуального шума. Отвлекающие тултипы при наведении удалены, верхняя панель освобождена от дублирующей кнопки закрытия.
   - **Единая векторная дизайн-система иконок (100% Vector Canvas):** полный отказ от системных Unicode-глифов и эмодзи (`🔊`, `⚙`, `♫`, `CC`, `⛶`, `⏭`), вызывавших разнобой пропорций и артефакты шрифтов платформы:
     - `AudioTrackIcon`: векторная нота с овалом и флагом.
     - `SubtitlesBadgeIcon`: контурный бейдж со скруглением 3.2dp и математически центрированными векторными буквами `CC`.
     - `SettingsGearIcon`: прецизионная 8-зубчатая шестеренка с круглым вырезом (`PathFillType.EvenOdd`).
     - `VolumeSpeakerIcon`: монохромный рупор с динамическими 1–2 дугами волн или диагональной линией Mute (строго `Color.White` / `Sm.lamp`), масштабированный в единый визуальный вес с Hero-кнопками.
     - `FullscreenToggleIcon`: векторные угловые скобки для входа и выхода из полноэкранного режима.
     - `NextEpisodeIcon`, `NextPlayTriangleIcon`, `CloseCrossIcon`: векторные треугольники и крестики с выверенным выравниванием по центру и базовой линии.
   - **Калиброванное люминесцентное радиальное свечение:** мягкий радиальный градиент (`Brush.radialGradient`), рассеивающийся вокруг кнопок ($R \approx 0.60 \times \text{size}$, уменьшен на 20% для сохранения четких контуров и исключения мыла):
     - Hover: деликатный световой ореол ($\alpha = 0.28$, плавный tween 160 мс).
     - Active (открыто меню): устойчивое свечение ядра ($\alpha = 0.40$).
     - Pressed: световой импульс ($\alpha = 0.46$).
     - Интегрировано в `GlassIconButton`, кнопку звука и активные чипы.
   - **Монохромный таймлайн и люминесцентный таймкод:**
     - Устранен паразитный янтарно-желтый цвет `Sm.lamp` при перемотке/наведении: таймкод всегда отображается белым (`Color.White`), акцентируясь полужирным начертанием и мягким радиальным ореолом свечения ($\alpha = 0.38$).
     - В компоненте `SeekBar` активная точка (thumb) при наведении или скраббинге получает мягкий белый ореол ($R \approx 16\ \text{dp}$, $\alpha = 0.52$), а при движении курсора по шкале отображается превью-метка с деликатным белым свечением.
   - **Векторная перемотка ±10 с (`Seek10Icon`):** увеличенный на 10% диаметр, правильная пространственная ориентация стрелок по ходу времени (влево — назад, вправо — вперед) и строго центрированная цифра 10.
   - **Анимированные контекстные меню (Popups):**
     - Меню субтитров, звуковых дорожек и настроек скорости плавно вылетают из нажатой кнопки-источника по направлению к центру над панелью управления (`TransformOrigin`, синхронная интерполяция `scale: 0.82f → 1.0f`, `alpha: 0f → 1f`, `translationY: 18dp → 0dp`, `FastOutSlowInEasing`).
     - Меню подробной информации (HUD): при открытии по горячей клавише `I` органично выдвигается из нижней центральной части экрана (`TransformOrigin(0.5f, 1f)`).
     - Сами карточки используют глубокий обсидиановый фон (`0xF20E1118`, радиус 14dp, окантовка `0x26FFFFFF`). Выбранные опции отображаются через `PlayerChip` со сплошной белой заливкой (`Color.White`) и контрастным тёмным текстом (`0xFF111418`).
   - **Интерактивная капсула звука (`VolumeGlassCapsule`):** в покое занимает 42dp с монохромной векторной иконкой. При наведении мыши или скролле колесиком плавно разворачивается в горизонтальный слайдер (или компактный вертикальный оверлей при ширине окна $< 880\,\text{dp}$).
   - **Плавающие бейджи действий:**
     - **Следующая серия:** заменен кричащий желтый цвет на чисто белый с деликатным полупрозрачным фоном-капсулой; векторный треугольник запуска и крестик закрытия увеличены на 10% и идеально отцентрированы по вертикали.
     - **Пропуск заставки:** компактная монохромная капсула над таймлайном без посторонних цветных эмодзи, укороченная строго по контуру текста «Пропустить заставку (S)».
   - **Без прыжков видео:** элементы управления выезжают строго поверх видеоряда, не деформируя и не смещая кадр фильма вверх/вниз.

3. **Автоматическое сворачивание и скрытие курсора:**
   - При бездействии курсора мыши в течение 2.5 секунд контролы плавно уезжают за пределы экрана (`translationY = -90dp` вверх и `300dp` вниз) с затуханием прозрачности (`alpha = 1f → 0f`).
   - По завершении анимации окна оверлеев выставляют `isVisible = false`, а системный курсор мыши над видео полностью скрывается (`blankCursor`).
   - Любое движение мыши мгновенно возвращает видимость и курсор.
   - Панель удерживается на экране только при реальных активных действиях: на паузе, при перетаскивании ползунка времени, при открытом меню дорожек или HUD информации.

4. **Бесшовное управление звуком и фильтрами (ночной режим):**
   - **Динамический компрессор диапазона (DRC):** для ночного просмотра диалоги приподнимаются, а взрывы и спецэффекты приглушаются фильтром `compressor` (`--compressor-threshold=-24`, `--compressor-ratio=6`, `--compressor-makeup-gain=10`).
   - **Переключение без перезапуска UI:** опции компрессора передаются на уровне отдельного медиапотока (`:audio-filter=compressor` в `open()`), а не в глобальный конструктор `MediaPlayerFactory`.
   - **Мягкий `reopen(time)` с фиксацией кадра:** при клике на «🌙 Ночной звук» плеер захватывает текущий кадр в Compose-битмап (`grabFrame()`) и переоткрывает поток с текущей миллисекунды. Окно, интерфейс, оверлеи и холст `Canvas` не пересоздаются, исключая мигание черным экраном и сброс состояния.
   - **Защита от потери звука при паузе/буферизации и синхронизация мута (2.1.4):**
     - Если фильм ставился на паузу в процессе открытия или буферизации, входящее событие `playing` глушило звук вызовом `mp.audio().setMute(true)`, предотвращая преждевременный проигрыш звука. При снятии с паузы в `togglePause()` отсутствовала передача `setMute(userMuted)`, а ветка `!wasStarted` в событии `playing` блокировала повторный анмут уже запущенного видео, навсегда оставляя плеер без звука.
     - В `togglePause()` при возобновлении добавлен явный вызов `mp.audio().setMute(m)`.
     - В обработчике `playing` условие `else if (!wasStarted)` разделено: мут `mp.audio().setMute(m)` синхронизируется на любое событие воспроизведения вне паузы, а громкость `setVolume(v)` применяется однократно при первом старте.
     - В `onVolumeChange` ползунка громкости добавлен автоматический сброс заглушения (`userMuted = false`, `setMute(false)`) при перетаскивании ползунка выше 0%.

5. **Слабая сеть: «копим запас» (2.1.4):** на сети, почти не быстрее фильма (`BurstProxy.slowerThanFilm`: сеть < 1,15× битрейта), и пустом запасе (< 2 МБ) `PlayerView` вызывает `BurstProxy.hold` — прокси держит фильм, пока не накопится `catchUpTargetMb` (~30 с фильма, не больше половины кольца), но не дольше `CATCH_UP_MAX_MS` (45 с). VLC на паузу не ставится: для него это одна долгая буферизация. По окончании — `hold(url, 0)` и, при ≥ 8 с запаса позади, `vlcSeekTo(time)`: декодеры стартуют заново с диска, и картинка не остаётся рассыпанной. Не раньше 20 с после открытия, перемотки и прошлого накопления. Сторож на это время ждёт 60 с вместо 30 с. Сами правила (когда начинать и заканчивать) — в общем `CatchUp`, одинаково для Android и ПК.

5a. **Мини-плеер на ПК (2.1.5):** `WindowMode.setMiniMode` работает только через Win32, как полноэкранный режим, и не трогает `WindowState` Compose (иначе Compose и Win32 спорят за размер). Вход: запоминаются стиль и `WINDOWPLACEMENT` (из полного экрана — сохранённые при его включении), снимаются `WS_CAPTION`/`WS_THICKFRAME`/кнопки (толстая рамка давала полупрозрачные полосы), окно ставится «поверх всех» и за ~320 мс (ease-out) уезжает в правый нижний угол рабочей области монитора (`rcWork`, отступ 24 dp, физические пиксели с учётом DPI). Размер — по площади ≈ 590×330 dp, подгоняется под формат фильма (ширина 400–620 dp); формат (`videoAspect`) обновляется из потока VLC раз в 1,5 с, из потока интерфейса VLC не спрашиваем. Анимация идёт в потоке `mini-fly` с `SWP_ASYNCWINDOWPOS` (чужой поток иначе ждёт владельца окна), размер меняется шагами ≥ 24 px; на время полёта оверлеи скрыты и не пересчитываются (`WindowMode.miniAnimating`), а состояние Compose `mini = true` и `onTop = true` включаются только после полёта (`onFinished`) — иначе рекомпозиция замораживала окно. В конце размер синхронизируется с AWT через `setBounds` (в dip). Выход возвращает стиль и размещение. Перетаскивание — AWT-слушатель мыши в `PlayerView`. В журнале теги `[ui] mini …`, пауза между кадрами > 100 мс пишется как `mini frame gap`.

6. **Полноэкранный режим (Borderless Fullscreen), защита DWM и горячие клавиши:**
   - **Устранение конфликта с FSEM:** стандартный режим `WindowState.placement = WindowPlacement.Fullscreen` в Java AWT использует эксклюзивный захват дисплея (FSEM). В Windows DWM показ нативных дочерних окон (`ComposeDialog`) поверх FSEM принудительно сбрасывает окно в оконный режим. Для решения этой проблемы в `WindowMode.kt` реализован нативный Win32 Borderless Fullscreen через JNA (`SetWindowLongW`, `SetWindowPos`, `MONITORINFO`).
   - **Блокировка DirectFlip и устранение белого экрана:** чтобы предотвратить уход менеджера окон Windows (DWM) в DirectFlip / Exclusive Fullscreen (при котором драйвер заливает контекст белым цветом из-за конфликта Compose OpenGL с VLC Direct3D нативным `Canvas`), окно не использует стиль `WS_POPUP`, а сохраняет структуру оверлейного окна со срезанными рамками (`savedStyle and borderStyles.inv()`), при этом высота выставляется на 1 пиксель больше экрана (`monH = (m.bottom - m.top) + 1`).
   - **Синхронизация хитбоксов и insets (AWT / Compose):** при выходе из полноэкранного режима в `SwingUtilities.invokeLater` вызывается двойной вызов `win.setBounds(b.width - 1)` / `win.setBounds(b.width)` (трюк для сброса закэшированных отступов `Insets` в native `WWindowPeer`), после чего вызываются `win.invalidate()`, `win.validate()`, `contentPane.validate()`, `rootPane.revalidate()`, `win.repaint()` и `WindowMode.restoreComposeFocus(win)`. Это восстанавливает правильные границы клиентской области ComposeWindow и SkiaLayer, исключая смещение хитбоксов мыши.
   - **Устойчивость к частым F11 и выходу из развёрнутого окна:** `setFullscreen` игнорирует смену режима чаще чем раз в 450 мс и запоминает `WINDOWPLACEMENT`/стиль только когда у окна есть рамка (не промежуточное полноэкранное состояние). Для окна, открытого «на весь экран» (`showCmd = SW_MAXIMIZE`), выход делает сначала `SW_SHOWNORMAL`, затем снова `SW_MAXIMIZE`: для Windows такое окно и в полном экране остаётся «развёрнутым», и повторное «развернуть» ничего не пересчитывало — окно с рамкой оставалось размером с монитор и уходило за нижний край.
   - **Ожидание потока VLC с тайм-аутом (`vlcAwait`):** все вызовы VLC идут в один поток `vlc-control`. Ответ из него ждётся через `async(vlcThread)` + `withTimeoutOrNull { await() }`: так тайм-аут реально срабатывает, пока поток занят зависшим вызовом VLC (остановка, перемотка при провале сети). Меню дорожек/субтитров тогда открывается с прошлым списком (`trackMenuCache`), а выход из плеера не ждёт. Циклы опроса (раз в секунду: время, запас, сторож) идут через `vlcPoll`: пока прошлый вызов не вернулся, новый не ставится в очередь, так зависший VLC не копит за собой сотни задач.
   - **Общее состояние перемотки:** `seeking` живёт в `PlayerView` и передаётся в нижнюю панель (`seeking`, `onScrubChange`), поэтому во время перетаскивания ползунка время плеера не перезаписывает позицию, а панель не скрывается. Одноразовые `javax.swing.Timer` в `playing()` создаются через `oneShot` и останавливаются при закрытии плеера.
   - **Привязка геометрии к нативному холсту VLC (`canvas`):** в `syncOverlayBounds()` экранные координаты и габариты считываются напрямую у `canvas` (пока он отображается), что исключает паразитный сдвиг оверлеев на 32px вниз от устаревших Insets шапки окна.
   - **Защита клавиатурного фокуса и надежность горячих клавиш (`KeyEventDispatcher`, `SetForegroundWindow`, `SetFocus`, `WS_DISABLED`):**
     - **Глобальный `KeyEventDispatcher` и `onPreviewKeyEvent`:** в `Main.kt` перехват всех нажатий клавиш вынесен на уровень `KeyboardFocusManager.getCurrentKeyboardFocusManager().addKeyEventDispatcher(...)` без проверки `window.isActive`, а также продублирован в `Window(onPreviewKeyEvent = { ... })`. Это гарантирует 100% срабатывание горячих клавиш (`Space`, `F`, `F11`, `Enter`, стрелки, `Esc`) независимо от того, где находится системный фокус.
     - **Блокировка перехвата фокуса нативным холстом VLC и его дочерними окнами (`WS_DISABLED`, `EnumChildWindows`):** метод `WindowMode.disableNativeCanvasInput(canvas)` рекурсивно находит все дочерние окна VLC (модули вывода Direct3D/OpenGL) через `EnumChildWindows` и отключает их через `WS_DISABLED` и `EnableWindow(false)`. Direct3D вывод VLC продолжает функционировать аппаратно, но Windows физически запрещает внутренним окнам VLC забирать системный клавиатурный фокус (`SetFocus`). Повторный вызов через таймер 250 мс в событии `playing` глушит vout-окна, созданные VLC с задержкой.
     - **Единая обработка кликов и колесика в Compose (`Box.pointerInput`):** благодаря `WS_DISABLED` на холсте все события мыши проходят сквозь нативный слой в контейнер `Box` видеоряда, где средствами Compose обрабатываются одиночный клик (пауза/плей), двойной клик (полный экран) и вертикальный скролл колесиком (громкость ±5%).
     - **Активация окна через Win32 `SetForegroundWindow` и `SetFocus`:** в `WindowMode.restoreComposeFocus` вызовы Win32 API `SetForegroundWindow(hwnd)` и `SetFocus(hwnd)` принудительно возвращают системный фокус ОС на главное окно после вызовов `SetWindowLongW` и при показе оверлеев. Только если приложение и так на переднем плане (`appInForeground`, по `GetForegroundWindow`): иначе окно не отбирает фокус у браузера или другой программы.
     - **Поиск `SkiaLayer`:** `findFocusable` ищет в `contentPane` именно `org.jetbrains.skiko.SkiaLayer` по имени класса и запрашивает фокус для него. Раньше бралась «первая фокусируемая» вещь — ею оказывалась обёртка `SwingPanel` с холстом VLC, фокус уходил к ней, и горячие клавиши в плеере молчали.
     - **Предотвращение кражи активности дочерними диалогами:** `topDialog` и `bottomDialog` настроены с `isAutoRequestFocus = false` и `focusableWindowState = false`. Из `syncOverlayBounds()` и `LaunchedEffect(isFullscreen)` удалены вызовы `.toFront()`, а при вызове `revealOverlays()` принудительно восстанавливается фокус главного окна через `WindowMode.restoreComposeFocus(owner)`.
     - Ввод текста в полях поиска/логина медиатеки защищен проверкой `playing == null`.
   - **Защита событий мыши в оверлеях:** при переходе в полноэкранный режим `LaunchedEffect(WindowMode.isFullscreen)` временно скрывает `topDialog` и `bottomDialog`, ожидая 80 мс перестройки Win32-окна, после чего отображает их заново и возвращает фокус слою Compose (`WindowMode.restoreComposeFocus(owner)`). Это гарантирует кликабельность кнопок оверлеев и мгновенную работу горячих клавиш.
   - **Чистая прозрачность оверлеев:** исключено манипулирование `d.opacity = 0f / 1f` на уровне AWT `Dialog`, сохраняя нативную попиксельную альфа-прозрачность Skiko без белых вспышек.
   - **Устранение артефактов границ:** при входе в полноэкранный режим вызывается `TitleBar.setFullscreenDwm(win)`, который отключает 1-пиксельную акцентную рамку Windows 11 (`DWMWA_BORDER_COLOR = DWMWA_COLOR_NONE`) и предотвращает скругление углов (`DWMWA_WINDOW_CORNER_PREFERENCE = DWMWCP_DONOTROUND`).
   - **Поддержка `F11`:** добавлена обработка клавиши `F11` (стандарт Windows / веб-плееров) как в глобальном слушателе окна `Main.kt` (`onPreviewKeyEvent`), так и в плеере `PlayerView.kt` наряду с `F` и `Enter`.
   - **Сохранение Fullscreen при выходе:** при нажатии кнопки «‹» в верхней панели плеер закрывается без принудительного сброса окна в плавающий режим (`WindowPlacement.Floating`), сохраняя полноэкранный режим каталога/приложения.

7. **Двухдвижковая система (mpv и VLC) и стабильность воспроизведения (2.2):**
   - **Абстракция `PlayerEngine`:** единый интерфейс плеера (`ru.suslikovanora.media.desktop.player.PlayerEngine`), инкапсулирующий работу с позицией, длительностью, дорожками звука/субтитров, фильтрами и громкостью. Основной движок — mpv (`MpvEngine` на базе `libmpv-2.dll`, библиотека входит в MSI), резервный — VLC (`VlcPlayer` в `VlcEngine.kt`, vlcj). `PlayerView` говорит с одним `engine` и одним `EngineListener` для обоих. Выбор сохраняется в `settings.properties` и переключается в «Настройках».
   - **Аппаратный вывод Direct3D 11 через Windows HWND (`wid`):** холст `java.awt.Canvas` передается в mpv (`api.mpv_set_option_string(p, "wid", hwnd.toString())`), вывод настраивается через `--vo=gpu`, `--gpu-api=d3d11`, `--hwdec=auto-safe`. Обеспечивает 0% нагрузки CPU, аппаратный VSync без тиринга, безупречный рендеринг стилизованных ASS/SSA субтитров (`libass`) и нулевой конфликт с DirectX DWM оверлеями Compose.
   - **Потокобезопасная загрузка внешних дорожек:** в `MpvEngine` списки внешних озвучек и субтитров (`pendingAudio`, `pendingSubs`) объявлены с аннотацией `@Volatile` и защищены мьютексом `trackLock`. Метод `addExternalTracks()` верифицирует, что текущий загруженный в mpv путь (`str("path")`) строго совпадает с `currentOpenUrl`, исключая гонки и затирание внешних дорожек новыми сериями при быстром переключении.
   - **64-битная раскладка нативных структур libmpv в памяти (JNA):**
     - В `Mpv.EV_END_FILE` поле указателя `void *data` в 64-битной структуре `mpv_event` расположено по смещению `16` байт. Считывание кода завершения (`reason`, смещение 0) и ошибки (`error`, смещение 4) производится строго после разыменования указателя `dataPtr = ev.getPointer(16)`.
     - В `onProperty` поле `name` структуры `mpv_event_property` представляет собой 8-байтный указатель `const char *name`, считываемый через `propPtr.getPointer(0)?.getString(0, "UTF-8")`.
   - **Точная телеметрия декодера и перезапуск видеопотока:**
     - В `MpvEngine.supervisorStats()` счетчик картинок учитывает состояние VO (`vo-configured == "yes"`) и вычитает число отброшенных кадров (`frame-drop-count`), а аудиопрогресс отслеживается по `audio-pts` вместо времени, что позволяет `PlaybackSupervisor` надежно определять зависания Direct3D 11 поверхности.
     - Метод `restartVideoOutput()` в `PlayerEngine` и `MpvEngine` программно переинициализирует видеопайплайн (сброс `vid` и синхронизирующий относительный seek 0) без разрушения окна и переоткрытия потока.
   - **Устранение гонки плейлистов и рассинхронизации буфера:**
     - Загрузка плейлиста M3U вынесена в единый `playlistDeferred = remember(req.playlist) { scope.async(Dispatchers.IO) { ... } }`, выполняемый параллельно с первичной инициализацией холста (440 мс).
     - Конкурирующий `LaunchedEffect(req.playlist)` удален. Исключены повторный сетевой запрос и прямая мутация `currentUrl`, приводившая к рассинхронизации адресов между плеером, `PlaybackSupervisor` и `BurstProxy` с последующим зависанием буфера.
   - **Управление жизненным циклом фоновых задач:** вспомогательные корутины (`ensureAudioJob`, `chaptersJob`, `canvasFocusJob`) в `PlayerView` переведены на отменяемые `Job?` с принудительной отменой предыдущих инстансов при смене серий и гарантированной очисткой в `onDispose`.

Сборка: `desktop/build.gradle.kts` (там `appVersion`), MSI собирается командой `./gradlew packageMsi`,
отладочная — `./gradlew packageMsi -Pdiag` (подробно `desktop/DEBUG-BUILD.md`). «Что нового»:
`desktop/src/main/resources/changelog.json`.

## 8. Сборка и выпуск (GitHub Actions)

| Workflow | Когда запускается | Что делает |
|---|---|---|
| `shared.yml` | пуш с изменениями в `shared/` | тесты общего модуля |
| `android.yml` | пуш в `android/`/`shared/`, или вручную | собирает APK (обычный и отладочный); вручную с `publish=true` выкладывает на сайт в канал `beta` или `stable` |
| `desktop.yml` | пуш в `desktop/`/`shared/`, или вручную | собирает MSI (обычный и отладочный); выкладывает так же |
| `promote.yml` | вручную | «выпустить всем»: версия из беты становится релизом |
| `update-status.yml` | вручную | проверка: какие версии сайт видит в каналах |
| `changelog.yml` | пуш с изменением `changelog.json` | сразу отправляет «Что нового» на сайт |
| `website.yml` | пуш в `website/` | только проверка синтаксиса (на сервер ничего не ставит) |
| `reports.yml` | вручную | показывает последние отчёты о сбоях и журналы, которые прислали приложения |

**Каналы.** Обычный путь — бета (видят только те, у кого введён код беты) → «выпускай всем» (`promote.yml`).
Приложения сами спрашивают сервер `/api/app/update` и предлагают обновиться.

**Версия** — три числа `2.x.y`: Android — `versionCode`/`versionName`, Windows — `appVersion`. При выпуске:
поднять версию, добавить запись в оба `changelog.json` (новая сверху), пуш, запустить сборку с публикацией.

## 9. Отладка

- **Отладочные сборки «Suslik Debug»** — отдельные приложения рядом с обычными, со своим входом и подробным журналом.
  - Android: журнал `Android/data/ru.suslikovanora.media.diag/files/diag/player.log`, метка 📍 в плеере.
  - Windows: журнал `%APPDATA%\SuslikMediaDebug\player.log`, метка — F8 в плеере, архив журнала — в настройках.
- **Теги журнала:** `[vlc]` и `[proxy]` (раз в 5 с: что показывает VLC и сколько запаса впереди), `[sys]` (батарея,
  процессор, сеть), `[http]` (каждый запрос), `[net]` (смена сети), `[mark]` (метка), `[ts]` (Blu-ray).
  Читать удобно от нужной метки назад.
- **Обычные приложения** тоже пишут журнал (поменьше) и присылают на сервер отчёты о сбоях.
