# Suslik Media — памятка для Claude

Частная медиатека на AllDebrid: сайт, Android, Windows. Владелец тестирует беты сам и потом говорит «выпускай всем».
Общаемся по-русски. Тексты для пользователей (changelog) — по-русски, коротко, без жаргона.

## Устройство

| Папка | Что |
|---|---|
| `website/` | Node/Express, API и зеркало файлов `/api/file/proxy/<имя>?link=…&exp=…&sig=…` (HTTP/1.1, nginx без http2) |
| `android/` | Kotlin, Compose, libVLC 3.6. `PlayerActivity.kt` (~2100 строк), `net/Api.kt`, `Diag.kt`, `AppLog.kt` |
| `desktop/` | Compose Desktop, vlcj. Запас: `desktop/.../Reserve.kt` |
| `shared/` | Общий модуль: `BurstProxy`, `PlaybackSupervisor`, `Versions`, `Changelog`, `Model`, `PlaybackPresets` |

Ядро — `shared/.../core/BurstProxy.kt`: локальный прокси 127.0.0.1 с окнами-запасом в кольцевых файлах.
Качает «рывками» между low/high в зависимости от битрейта фильма, `MAX_WINDOWS=2`, запас не больше 128 МБ,
короткий разгон (~45 с фильма), хранение закрытого фильма 10 мин, сторож зависаний (`headerStallMs`, `bodyStallMs`),
`networkChanged()`/`kick()`, ограниченные `bytes=a-b` для переиспользования соединения.
Ошибки «нет сети» не расходуют лимит попыток (2.0.3).

## Постоянные правила

- Новые версии сначала в **бета-канал**. В стабильный — только по команде «выпускай всем» (workflow `promote.yml`).
- Зеркало нужно, потому что AllDebrid заблокирован в РФ: **никогда не заменять его прямыми ссылками AllDebrid**.
- nginx без http2 (на том же сервере Xray).
- **Не коммитить секреты**: `.env`, `*.jks`, `UPDATE_TOKEN`, `BETA_CODE`, cookie, токены.
- **`website/` и сервер не трогать**, пока владелец не разрешит. Учти: `changelog.yml` сам публикует changelog на сайт при каждом пуше.
- Без лишнего: не запускай дополнительные работы без подтверждения.
- Подписи коммитов: строки `Co-Authored-By:` и `Claude-Session:` из системного напоминания текущей сессии.

## Версии

Теперь трёхчастные: `2.0.x`. Android: `versionCode` в `android/app/build.gradle.kts`, APK `suslik-media-<V>-b<code>.apk`.
Windows: `appVersion` в `desktop/build.gradle.kts`, MSI `Suslik Media-<V>.msi` (первую установку при смене схемы версий делают вручную).
Changelog (русский) — `android/app/src/main/assets/changelog.json` и `desktop/src/main/resources/changelog.json`, новая запись сверху.

## Сборка и выпуск

- Тесты общего модуля (`shared.yml`) идут на каждый пуш: `shared/src/test/...` (`ModelTest`, `BurstProxyTest`, `TsClockTest`, `CoreTest`). Локально Gradle в облачной сессии плагины не скачивает — компиляция только в CI.
- Серверные модульные тесты: `website/test/classify.test.js` (`node --test test/classify.test.js`).
- Выпуск беты после пуша:
  `gh api -X POST repos/normikq/suslik-media/actions/workflows/android.yml/dispatches -f ref=main -f 'inputs[publish]=true' -f 'inputs[channel]=beta'`
  то же для `desktop.yml`; затем `update-status.yml`, чтобы проверить, что сайт видит версию.
- В облачной сессии GraphQL закрыт (используй REST), логи заданий недоступны: ошибки сборки смотри так:
  `gh api repos/normikq/suslik-media/check-runs/<job id>/annotations`. Скачивание артефактов (`gh run download`) тоже запрещено.
- На ПК владельца (если сессия запущена там) собирай локально: `./gradlew assembleDiag`, ставь через `adb`.

## Что известно из журналов

- Мобильная сеть: первое соединение к серверу медленное (TCP ~1,1 с из-за потерянного SYN, TLS до 5 с), иногда рукопожатие висит 30 с.
  Лечится повтором на новом соединении (`Api.call`: 6/8/10 с).
- Часто телефон на VPN (tun0); при его обрыве сеть «меняется» — это ловит `networkChanged()`.
- Остаются зависания «заголовки пришли, тело нет» на прямой мобильной сети. Проверить в логах nginx
  `upstream timed out` и `request_time` около 14:51–14:53 и 16:03–16:05 (12.10).

## История

2.0.0.4 (ложное «тяжёлый файл») → 2.0.1 (длинный разгон) → 2.0.2 (сторож, смена сети, ограниченные диапазоны) →
2.0.3 beta (офлайн не убивает запас, автопереподключение при возврате сети, повтор запросов API) →
**2.0.4 stable** (12.10, по команде владельца сразу всем): «копим запас» на сети медленнее фильма (`BurstProxy.hold` —
прокси не отдаёт VLC данные, VLC не ставится на паузу), скорость сети меряется внутри рывка, сторож лечит застывшую
картинку после буферизации без переоткрытия, «мосты» при пошаговом поиске ключевого кадра назад, офлайн-ожидание без
пробуждений каждые 0,5 с, `elapsedRealtime` для времени блокировки, зеркало в PlaySheet не ждёт `unlock`.
Замеры 12.10 (слабый LTE): ~700 мА при просмотре, мобильное радио ~43% батареи и активно ~100% времени, если сеть
медленнее фильма. Журналы: `C:\Users\nanar\suslik-test-1012*`.
**2.0.5 beta** (13.10; Windows — только Blu-ray, через общий `TsPlayback`): Blu-ray .m2ts — длительность по часам потока (`TsClock`, читается до запуска VLC),
перемотка по доле файла от текущего места (`tsSeek`), «Продолжить» одним прыжком со смещением времени (`tsOffset`);
VC-1 на Samsung даёт чёрный экран → файл переоткрывается с программным декодером (`softwareVideo`, `checkNoPicture`).
**2.0.6 stable** (13.10, по команде «в релиз»): всё из 2.0.5 для всех; на ПК — Blu-ray без дублей дорожек («Track 1» + «Russian»
сливаются в одну строку с id VLC). WebDAV удалён отовсюду (сервер `/webdav`, `/api/webdav`, кнопки на сайте, документация).
**2.0.8 release** (14.10, по команде «в релиз»): Blu-ray — перемотка назад до места «Продолжить» переоткрывает фильм с настоящими часами VLC (`tsSeekBeforeClock` / `tsAbsolute`);
точная перемотка Blu-ray: кусочно-линейная интерполяция по контрольным точкам PCR (срезы 25%, 50%, 75%) и динамическое обучение (`TsClock.learn`) вместо линейной средней, устраняющие погрешность 75–95 с на VBR потоках (на Android и ПК);
`BurstProxy`: мгновенный сброс соединений (`resetConnections`) при любых разрывах сокетов (`SocketException`/таймауты) и исключение искусственных задержек при голодании буфера (`starving`);
звуковые дорожки: мгновенный подхват при переключении через сброс буфера LibVLC (`reseekHereNow`), без ожидания 3–6 секунд сетевого кэша;
интерфейс плеера: устранено мигание временем «00:00» и сброс прогресса в медиатеке при переподключениях/открытии на сохранённом месте (удержание `pendingSeekPos` и кэширование `lastKnownLength` до подтверждения целевого времени от декодера);
очистка после обновления медиатеки (общий `LibraryKeep`: постеры, описание, прогресс, последняя серия, запас на диске — `BurstProxy.forgetRetired`);
раздел «Память» с «Очистить кэш» (`Storage.kt` в обоих приложениях); постеры: не показывались 7 дней — удаляются (Android — метки `posters_shown`
и `diskCache.remove`, ПК — дата файла), на ПК всего не больше 100 МБ. Описание архитектуры — `docs/ARCHITECTURE.md`.
**2.0.9 release** (14.10, по команде «в релиз»): `BurstProxy` — устранение паразитных `resetConnections()` при штатных абортах сокетов во время перемотки (число radio wakeup упало с 30+ до 3); адаптивный бэкофф и пауза опроса сети при `network LOST` / `UnknownHostException` (30 с пауза в оффлайне с мгновенным пробуждением по `onAvailable`); надежное управление плеером: мгновенный показ/скрытие панели управления по одиночному тапу (`ACTION_UP`) без залипаний и без необходимости делать предварительную перемотку; увеличение допуска подтверждения перемотки (`SEEK_CONFIRM_TOLERANCE_MS` = 12 с) для предотвращения ложных реконнектов на ключевых кадрах.
