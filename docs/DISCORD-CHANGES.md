## Включение на сервере
1. `.env`: `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_BOT_TOKEN`, `DISCORD_GUILD_ID` (и при желании роли, `DISCORD_OWNER_ID`),
   `SITE_PREFIX=/media`, `COOKIE_SECURE=true`, `SESSION_SECRET`. Без бота и белого списка `DISCORD_ALLOWED_USERS` входит только `DISCORD_OWNER_ID`.
2. Developer Portal → OAuth2 → Redirects: `https://<домен>/api/auth/discord/callback`. Бот добавлен на сервер (scope `bot`, без прав).
   Rich Presence → Art Assets: картинки `brand-mark`, `play`, `pause`.
3. nginx: короткая ссылка для ТВ — `location = /link { return 302 /media/link$is_args$args; }` (`website/NGINX-MIRROR.md`).
4. `npm install` (пакет `ws`), перезапуск Node.

## ПК 2.5.1: исправления по ревью (20.10)
- Избранное у пользователей Discord отдаётся и не пропадает после перезапуска (`favorites.js` читает по `deviceId`, ключи `u_<id>` сохраняются).
- Вход по общему паролю: избранное и «свои раздачи» снова у каждого устройства (`deviceId` для `shared` — cookie `sdev`, а не один id на всех).
- Перенос данных устройства при первом входе через Discord работает (раздачи сравнивались не с тем полем, файлы затирались записью из памяти);
  переносится и при входе приложения по коду (`/api/auth/device/poll`).
- Комнаты: `client_id` устройств больше не рассылается (только отпечаток `key`, `host_key`) — гость не может выдать себя за ведущего,
  «выкинуть» другого или поставить ему «грузится». Пустые комнаты (и те, куда никто не вошёл) убирает обход раз в 5 минут.
- ПК: `DiscordRpc` работает на одном своём потоке — если Discord завис, не копятся заблокированные потоки.
- Комната без ведущего: если он не вернулся за минуту, ведущим становится тот, кто в комнате дольше всех (`promoteIfHostGone`).
- Поток комнаты закрывается, когда вход отозван (проверка раз в 20 с); ошибки записи в оборванный поток не роняют сервер.
  ПК на 401/403 выходит из комнаты и пишет почему, а не переподключается бесконечно.
- Лимиты: команды комнате — 300 в минуту, код связки устройства — свой счётчик 60 за 15 минут (а не общий с паролем 10).
- Белый список Discord: админ определяется по ролям через бота (раньше id пользователя сравнивался со списком id ролей).
  Админ Discord может удалять чужие раздачи; вход по общему паролю — нет.
- ПК: аватар не мигает и не грузится заново при сворачивании панели; «Другой фильм» есть и когда фильма нет в медиатеке;
  «Код скопирован»; гостю — подсказка на стрелки, главы и N/P; на экране входа старая ошибка стирается.
- Сайт: кнопка «Подтвердить» в окне связки неактивна, пока идёт запрос. `ROOMS_FILE` убран (комнаты только в памяти).

## ПК 2.5.2: общее ядро и исправления по журналам (20.10)
- В `shared/` вынесено всё, что понадобится Android: протокол комнат (`PartyProtocol`, `PartyRoom`), цикл синхронизации
  (`PartySyncEngine`, без Compose и корутин — приложение зовёт `tick()` раз в 400 мс), вход и «Мои фильмы» (`Auth.kt`).
  ПК переведён на них без изменения поведения. Шаги для Android — `docs/TODO.md`.
- По журналам двух приложений в одной комнате:
  - гость, перематываясь к ждущей комнате, вставал на паузу, перемотка засчитывалась за такт — «готов» раньше времени,
    потом вторая загрузка; теперь грузится без паузы;
  - после открытия mpv говорит «играю», а время стоит: стоящее 1 с время — тоже загрузка (`FROZEN_MS`);
  - новая серия брала время прошлой (до 4 с ожидания озвучек играет старый файл) — `switching` в `PlayerView`;
  - ответ на прежнее действие возвращал ведущего на прошлую серию — `PartyRoom.pendingFileKey`;
  - перемотка стрелками терялась (часы mpv перезаписывали цель за 250 мс накопления нажатий).
- Подсказки о действиях ведущего и «Ждём, пока загрузится у …» (`PartyNotice`).
- Discord Rich Presence: показ постеров фильмов и сериалов (`large_image` через CDN TMDB) вместо заглушки; передача названия типа активности («фильм» / «сериал»).
