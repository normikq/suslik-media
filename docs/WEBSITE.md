# Suslik Media — Сервер и веб-интерфейс (`website/`)

Документация по серверной части и веб-клиенту Suslik Media: архитектура, устройство файлов, маршруты API, зеркалирование медиапотоков, интеграция с трекерами и развёртывание.

---

## 1. Назначение и архитектурная роль

Серверная часть Suslik Media (`website/`) выполняет две ключевые функции:
1. **Бэкенд и зеркало (Proxy) медиатеки AllDebrid:**
   - Поскольку AllDebrid и многие торрент-трекеры заблокированы в РФ, сервер (развёрнутый на зарубежном VPS) выступает доверенным шлюзом.
   - Все запросы к AllDebrid API, парсинг трекеров, загрузка метаданных/постеров и раздача видеопотоков осуществляются через сервер.
   - Прямой трафик видео проксируется через связку **Node.js** (проверка HMAC-подписи и получение прямых ссылок) и **nginx** (`X-Accel-Redirect` для высокопроизводительной отдачи без нагрузки на Event Loop Node.js).
2. **Веб-интерфейс и дистрибуция клиентских приложений:**
   - Легковесный одностраничный веб-клиент (`public/index.html`) для просмотра и управления медиатекой из браузера.
   - Система самообновления мобильного и десктопного клиентов: раздача APK и MSI (каналы `beta` и `stable`), загрузка артефактов из CI GitHub Actions, приём телеметрии и отчётов об ошибках (`crash reports`).

## 3. Маршруты API `server.js`

Все API-эндпоинты начинаются с префикса `/api/`.

### 3.1. Аутентификация и сессии
- `POST /api/login` — вход по общему паролю (`SITE_PASSWORD`). Устанавливает сессионную cookie с защитой от перебора (rate-limit по IP).
- `POST /api/logout` — завершение текущей сессии, сброс cookie.
- `GET /api/session` — проверка валидности текущей сессии и получение базового статуса.

### 3.2. Медиатека (AllDebrid Library)
- `GET /api/library` — получение списка всех magnet-раздач пользователя. Сервер запрашивает статус в AllDebrid, кэширует его и отдаёт клиентам в оптимизированном формате.
- `GET /api/magnets/:id` — детальная информация по конкретной раздаче.
- `GET /api/magnets/:id/files` — пакетный запрос дерева файлов раздачи (`POST /v4/magnet/files`).
- `POST /api/magnets/:id/delete` (или `cancel`) — удаление или отмена загрузки раздачи. Защищено механизмом **Owner Lock** (`owners.json`): только устройство, добавившее раздачу, может её удалить.

### 3.3. Добавление медиа
- `POST /api/magnets` — добавление новой magnet-ссылки в AllDebrid.
- `POST /api/torrents` — загрузка `.torrent` файла в AllDebrid.
- `POST /api/unlock` — разблокировка внешней ссылки на файлообменнике через AllDebrid.

### 3.4. Поиск торрентов
- `GET /api/search?q=...&cat=...` — мета-поиск по всем подключённым индексаторам и трекерам.
  - Параллельный опрос rutor, rutracker, kinozal, NNM-Club, Prowlarr/Jackett.
  - Объединение дублей по infohash.
  - Приоритет русскоязычных трекеров (бейдж `RU`).
  - Классификация результатов через `classify.js`.
- `POST /api/search/add` — мгновенная отправка найденного результата в AllDebrid (автоматическое получение magnet со страницы раздачи или скачивание `.torrent`).
- `GET /api/favorites`, `POST /api/favorites` — управление списком избранного.

### 3.5. Стриминг и Зеркало видео (Video Proxy)
- `POST /api/file/unlock` — получение прямой ссылки AllDebrid (для режима «Напрямую»).
- `GET /api/file/mirror-url?link=...` — генерация защищённой подписанной ссылки зеркала:
  `/api/file/proxy/<имя>?link=<ссылка>&exp=<время>&sig=<HMAC-SHA256>`.
- `GET /api/file/proxy/:name` — эндпоинт зеркала.
  1. Проверяет цифровую подпись `sig` и срок действия `exp` секретом `SESSION_SECRET`.
  2. Запрашивает у AllDebrid актуальный URL файла.
  3. Отдаёт клиенту заголовок `X-Accel-Redirect: /alldebrid_stream/...`, делегируя отдачу байтов видео серверу nginx.
  4. Поддерживает HTTP range-запросы (`206 Partial Content`) для мгновенной перемотки.

### 3.6. Сериалы и Плейлисты
- `POST /api/playlist` — генерация плейлиста сезона `.m3u`.
- `GET /api/playlist/:id/:name` — отдача подписанного M3U-файла, содержащего список последующих серий до конца сезона с уже сгенерированными зеркальными ссылками.

### 3.7. Метаданные и Постеры (TMDB)
- `POST /api/media-metadata` — поиск описания и постеров фильма/сериала через TMDB API.
- `GET /api/poster` — получение URL постера.
- `GET /api/poster/img/...` — локальное кэширование и проксирование картинок постеров (чтобы клиенты не зависели от блокировок `image.tmdb.org` и экономили трафик).

### 3.8. Обновления приложений (App Update Distribution)
- `GET /api/app/update?platform=android|windows&channel=stable|beta` — проверка наличия свежих версий для клиентов.
- `GET /api/app/download/:file` — скачивание дистрибутива APK или MSI.
- `POST /api/app/upload` — защищённая загрузка новых сборок из GitHub Actions (по токену `UPDATE_TOKEN`).
- `POST /api/app/promote` — перевод версии из канала `beta` в релиз `stable`.
- `GET /api/app/status` — просмотр доступных сборок по каналам.
- `GET /api/app/changelog`, `POST /api/app/changelog` — просмотр и публикация истории изменений (`changelog.json`).

### 3.9. Телеметрия и Сбои
- `POST /api/app/report` — приём отчётов об аварийных завершениях (`crash logs`) от Android и Windows приложений.
- `GET /api/app/reports` — закрытый просмотр накопленных журналов ошибок.

## 4. Зеркалирование видео: Node.js + nginx

Поскольку прямое проксирование сотен мегабайт видеопотока через процесс Node.js приведёт к деградации производительности Event Loop и утечкам памяти, используется гибридная архитектура:

```
[Клиент (VLC/mpv/BurstProxy)]
           │ HTTP Range Request: /api/file/proxy/...
           ▼
        [nginx] (внешний порт 443 HTTPS, без http2)
           │ proxy_pass
           ▼
     [Node.js (Express)]
           │ 1. Проверка HMAC подписи
           │ 2. Резолв ссылки через AllDebrid API
           │ 3. Ответ: X-Accel-Redirect: /alldebrid_stream/<path>
           ▼
        [nginx]
           │ Внутренний location /alldebrid_stream/
           │ proxy_pass к cdn.alldebrid.com (HTTP/1.1)
           ▼
[AllDebrid CDN сервер]
```

### Важные нюансы конфигурации nginx:
- **Отключение HTTP/2 для видео:** в конфигурации виртуального хоста видеопотоков протокол HTTP/2 отключается (используется чистый HTTP/1.1), так как мультиплексирование HTTP/2 плохо сочетается с агрессивными разрывами TCP-соединений при частых перемотках плееров и сосуществованием с Xray VPN на том же порту.
- **Обработка 403 / 410 от CDN:** если прямая ссылка AllDebrid протухла во время просмотра, nginx перехватывает ошибку (`proxy_intercept_errors on`) и перенаправляет запрос обратно в Node.js для прозрачного обновления ссылки.
- Подробные директивы nginx описаны в [`website/NGINX-MIRROR.md`](file:///c:/Users/nanar/OneDrive/Desktop/suslik-media-mpv/website/NGINX-MIRROR.md).

## 5. Поиск по трекерам и обход блокировок

Подсистема поиска (`search.js` + `search-ru.js`) поддерживает два уровня провайдеров:
1. **Прямые парсеры трекеров:**
   - **Rutor:** парсинг HTML-выдачи зеркал (`RUTOR_URL`), извлечение magnet без авторизации.
   - **Rutracker.org:** авторизация по логину/паролю или сессионной cookie (`bb_session`), обход Cloudflare через **FlareSolverr** (`FLARESOLVERR_URL`), скачивание `.torrent` через `dl.php`.
   - **Kinozal.tv:** парсинг поисковой таблицы, извлечение info-hash со страницы деталей.
   - **NNM-Club:** поиск по `tracker.php` в гостевом режиме или по cookie.
2. **Агрегаторы индексаторов (Prowlarr / Jackett):**
   - Интеграция через стандартный Torznab API (`PROWLARR_URL` + `PROWLARR_API_KEY`).
   - Автоматическое обновление определений парсеров силами самого Prowlarr.
3. **Классификация раздач (`classify.js`):**
   - Автоматическое определение типа контента по регулярным выражениям: фильм (BDRip, WEB-DL, 1080p, 4K), сериал (Season, Серии, S01E01), либо не-видео (игры, софт, музыка).
   - Покрыто модульными тестами в `test/classify.test.js`.

## 6. Хранение данных на сервере

Сервер не требует внешней базы данных (PostgreSQL/MongoDB) и использует плоские JSON-файлы с атомарной записью в каталоге `DATA_DIR` (по умолчанию `website/data/`):
- `sessions.json` — активные пользовательские сессии.
- `owners.json` — привязка добавленных раздач к уникальным идентификаторам устройств (`sdev` cookie).
- `library-cache.json` — кэшированный список раздач AllDebrid для снижения частоты запросов к внешнему API.
- `poster-cache/` — локальные изображения постеров фильмов.
- `updates/` — бинарные файлы сборок (`suslik-media-*.apk`, `Suslik Media-*.msi`), а также подкаталог `updates/beta/`.

## 7. Переменные окружения (`.env`)

Ключевые переменные конфигурации (см. `.env.example`):

| Переменная | Назначение |
|---|---|
| `SITE_PASSWORD` | Мастер-пароль для входа на сайт и в приложения |
| `SESSION_SECRET` | 32-байтный hex-секрет для подписи cookie и ссылок зеркала |
| `ALLDEBRID_API_KEY` | API-ключ аккаунта AllDebrid |
| `UPDATE_TOKEN` | Секретный токен для публикации сборок из GitHub Actions |
| `BETA_CODE` | Секретный код для доступа клиентов к бета-каналу обновлений |
| `TMDB_API_KEY` | (Опционально) API-ключ The Movie Database для постеров |
| `FLARESOLVERR_URL` | URL локального FlareSolverr для обхода Cloudflare трекеров |
| `PROWLARR_URL` / `KEY` | Интеграция с локальным сервером Prowlarr |
| `COOKIE_SECURE` | Устанавливать в `true` при работе за HTTPS-прокси |
| `TRUST_PROXY` | Устанавливать в `true` при работе за nginx |

## 8. Проверка и разработка

```powershell
# Установка зависимостей
npm install

# Проверка синтаксиса JS и HTML встроенных скриптов
npm run check

# Запуск тестов классификатора
npm test

# Локальный запуск сервера
npm start
```

> [!WARNING]
> Пуш в GitHub **не обновляет сервер автоматически**. Workflow `website.yml` выполняет только синтаксическую проверку (`npm run check` и `npm test`). Развёртывание кода на production-сервер осуществляется вручную администратором.
