# Suslik Media — Сервер и веб-интерфейс (`website/`)

Документация по серверной части и веб-клиенту Suslik Media: архитектура, устройство файлов, маршруты API, зеркалирование медиапотоков, интеграция с трекерами и развёртывание.

---

## 1. Назначение и архитектурная роль

Серверная часть Suslik Media (`website/`) выполняет две ключевые функции:
1. **Бэкенд и зеркало (Proxy) медиатеки AllDebrid:**
   - Поскольку AllDebrid и многие торрент-трекеры заблокированы в РФ, сервер (развёрнутый на зарубежном VPS) выступает доверенным шлюзом.
   - Все запросы к AllDebrid API, парсинг трекеров, загрузка метаданных/постеров и раздача видеопотоков осуществляются через сервер.
   - Прямой трафик видео проксируется через связку **Node.js** (проверка HMAC-подписи и получение прямых ссылок) и **nginx** (`X-Accel-Redirect` для высокопроизводительной отдачи без нагрузки на Event Loop Node.js).
2. **Веб-интерфейс и дистрибуция клиентских приложений:**
   - Легковесный одностраничный веб-клиент (`public/index.html`) для просмотра и управления медиатекой из браузера.
   - Система самообновления мобильного и десктопного клиентов: раздача APK и MSI (каналы `beta` и `stable`), загрузка артефактов из CI GitHub Actions, приём телеметрии и отчётов об ошибках (`crash reports`).

## 3. Маршруты API (`src/routes/`)

Все API-эндпоинты начинаются с префикса `/api/`.

### 3.1. Аутентификация и сессии
Вход двумя способами: через Discord (основной) и по общему паролю (запасной, выключается `PASSWORD_AUTH_ENABLED=false`).
Каждый запрос проходит `resolveAuth`: сначала токен устройства (`X-Device-Token` или `Authorization: Bearer`), потом сессия.
- `POST /api/login` — вход по общему паролю (`SITE_PASSWORD`, можно bcrypt-хеш). Сессия без пользователя: профиль `shared` с ролью admin.
- `GET /api/auth/discord/start?return=<путь>` — начало входа через Discord (scope только `identify`). `return` — куда вернуть после входа
  (только путь этого сайта; без него — страница из `Referer`, иначе главная с `SITE_PREFIX`). Одноразовый `state` — в сессии и запасной cookie.
- `GET /api/auth/discord/callback` — обмен кода, профиль, **немедленный отзыв токена Discord**, проверка участника и ролей ботом,
  новая сессия с `uid`. Отказ — страница «Доступ ограничен» со ссылкой на главную того же сайта (`/media/`).
- `POST /api/auth/device` — код связки для ТВ/ПК (`user_code` вида `A3F-821`, 10 мин) и ссылка `…/link?code=…`.
- `GET /api/auth/device/check`, `POST /api/auth/device/confirm` (нужен вход) — подтверждение кода на сайте.
- `POST /api/auth/device/poll` — устройство забирает токен (`device_token`, хранится у устройства; на сервере только SHA-256) и профиль. 410 — код истёк.
- `POST /api/logout` — конец сессии; если вошли по токену устройства — токен отзывается.
- `GET /api/session` — `authenticated`, профиль `user` (`id`, `name`, `avatar`, `role`), `discord_enabled`, `password_enabled`,
  `discord_client_id` (публичный ID приложения Discord — для активности в профиле на ПК).

Роль пользователя перепроверяется ботом раз в 15 минут; без роли (`denied`) сессии и токены устройств перестают действовать.
Роль `admin` сервер проверяет только при удалении раздач (`removeChecker`); `requireAdmin` не подключён — см. `docs/DISCORD.md` §0.

### 3.1.1. Совместный просмотр (`/api/rooms`)
Комнаты живут в памяти сервера (перезапуск — комнаты пропадают). Транспорт — Server-Sent Events, а не WebSocket.
- `POST /api/rooms` (`client_id`) — создать комнату; создатель — ведущий (`host_id`, при общем пароле — его устройство `host_client_id`).
- `GET /api/rooms/:id` — состояние; `POST /api/rooms/:id/join` — «кто я» (в список участников попадают с открытием потока).
- `GET /api/rooms/:id/events?client_id=…` — поток событий (`init`, `state_changed`, `member_joined`, `member_left`), `X-Accel-Buffering: no`.
  Участник — это открытый поток: закрылся последний поток устройства — его нет в комнате.
- `POST /api/rooms/:id/leave` — выйти сразу.
- `POST /api/rooms/:id/action` — `change_file`, `play`, `pause`, `seek`, `rate` — **только ведущий**; `buffering` — любой участник.

Правила доступа и время жизни комнат:
- **1 аккаунт = 1 активная комната** (`findUserActiveRoom`): если пользователь с персональным аккаунтом (Discord) уже подключен к комнате (в том числе с другого устройства), вход в любые комнаты и создание новых блокируются с ошибкой 400 (`Этот аккаунт уже подключен к комнате с другого устройства.` / `Этот аккаунт уже находится в активной комнате.`). Одно и то же устройство (`client_id`) также не может находиться в двух разных комнатах одновременно. Повторный вход / переподключение с того же устройства в ту же комнату разрешено. Для входа по общему паролю (`shared`) совместный просмотр нескольких устройств сохраняется.
- **Время жизни пустой комнаты**: когда последний участник покидает комнату (`empty_since`), воспроизведение ставится на паузу. Пустая комната удаляется через 30 минут (`EMPTY_ROOM_TTL_MS`, таймер очистки `sweepRooms` проверяет раз в 5 минут). То же правило действует для комнат, в которые после создания так никто и не подключился.

Состояние: `playing`, `pos` в момент `anchor_server_ms`, `rate`, `seq`, `waiting`. Пока у кого-то `buffering` (не дольше 30 с), комната
ждёт (`waiting`, время стоит); все готовы — идёт дальше с того же места. Никого не осталось — пауза.

### 3.2. Медиатека (AllDebrid Library)
- `GET /api/library` — получение списка всех magnet-раздач пользователя. Сервер запрашивает статус в AllDebrid, кэширует его и отдаёт клиентам в оптимизированном формате.
- `GET /api/magnets/:id` — детальная информация по конкретной раздаче.
- `GET /api/magnets/:id/files` — пакетный запрос дерева файлов раздачи (`POST /v4/magnet/files`).
- `POST /api/magnets/:id/delete` (или `cancel`) — удаление или отмена загрузки раздачи. Защищено механизмом **Owner Lock** (`owners.json`): только устройство, добавившее раздачу, может её удалить.

### 3.3. Добавление медиа
- `POST /api/magnets` — добавление новой magnet-ссылки в AllDebrid.
- `POST /api/torrents` — загрузка `.torrent` файла в AllDebrid.

### 3.4. Поиск торрентов
- `GET /api/search?q=...&cat=...` — мета-поиск по всем подключённым индексаторам и трекерам.
  - Параллельный опрос rutor, rutracker, kinozal, NNM-Club, Prowlarr/Jackett.
  - Объединение дублей по infohash.
  - Приоритет русскоязычных трекеров (бейдж `RU`).
  - Классификация результатов через `classify.js`.
- `POST /api/search/add` — мгновенная отправка найденного результата в AllDebrid (автоматическое получение magnet со страницы раздачи или скачивание `.torrent`).
- `GET /api/favorites`, `POST /api/favorites` — управление списком избранного.

### 3.5. Стриминг и Зеркало видео (Video Proxy)
- `GET /api/file/mirror-url?link=...&name=...` — генерация защищённой подписанной ссылки зеркала (подпись живёт 12 ч; приложения берут здесь новую, когда старая истекла; свой лимит 300 в минуту):
  `/api/file/proxy/<имя>?link=<ссылка>&exp=<время>&sig=<HMAC-SHA256>`.
- `GET /api/file/proxy/:name` — эндпоинт зеркала.
  1. Проверяет цифровую подпись `sig` и срок действия `exp` секретом `SESSION_SECRET`.
  2. Запрашивает у AllDebrid актуальный URL файла.
  3. С `MIRROR_ACCEL=1` отдаёт `X-Accel-Redirect: /_alld/...` (nginx берёт байты с файл-хоста сам, см. `website/NGINX-MIRROR.md`), иначе передаёт поток через Node. HEAD отдаёт только заголовки. Ответ идёт с `Content-Security-Policy: sandbox`, чтобы HTML из раздачи не выполнялся как страница сайта.
  4. Поддерживает HTTP range-запросы (`206 Partial Content`) для мгновенной перемотки.

### 3.6. Сериалы и Плейлисты
- `POST /api/playlist` — генерация плейлиста сезона `.m3u`.
- `GET /api/playlist/:id/:name` — отдача подписанного M3U-файла, содержащего список последующих серий до конца сезона с уже сгенерированными зеркальными ссылками.

### 3.7. Метаданные и Постеры (TMDB)
- `POST /api/media-metadata` — сведения о видео через ffprobe (не больше двух процессов сразу, одинаковые запросы ждут один анализ).
- `GET /api/poster` — постер и признак «мультфильм»; для баннера «Продолжить просмотр» ещё `backdrop` (лучший широкий кадр без надписей, `/api/poster/img/w1280/…`), `logo` (логотип названия, русский или английский), `overview` (по-русски), `year`, `rating`. Кадры и логотип берутся из `/{movie|tv}/{id}/images` и карточки TMDB (`addBannerExtras` в `services/posters.js`); любой сбой этих запросов оставляет ответ поиска. Старые клиенты лишние поля игнорируют.
- `GET /api/tags` (`routes/tags.js`, `services/mediatags.js`) — `{tags: {id: ["Dolby Vision","HDR","DTS-HD MA"]}, pending}`: метки для постеров по самому файлу. ffprobe читает самый большой видеофайл готовой раздачи один раз (запись DOVI → Dolby Vision, PQ/HLG → HDR, дорожка dts → DTS / DTS-HD / DTS-HD MA / DTS:X), по одной раздаче в фоне, пауза 1,5 с, общий лимит ffprobe с `/api/media-metadata`. Ответ хранится в `media-tags.json`, пока раздача есть в AllDebrid (удалённые убираются при запросе, если список настоящий, не устаревшая копия); не вышло — повтор через 6 ч, не больше 3 раз. Клиенты переспрашивают каждые 30 с, пока `pending > 0`; без ответа сервера метки угадываются по названию.
- `GET /api/poster/img/...` (свой лимит 1000 в минуту) — локальное кэширование и проксирование картинок постеров (чтобы клиенты не зависели от блокировок `image.tmdb.org` и экономили трафик).

### 3.8. Обновления приложений (App Update Distribution)
- `GET /api/app/update?platform=android|desktop` — свежая версия для клиента (бета — с заголовком `X-Beta-Code`): версия, размер, `sha256`, заметки. Файл, положенный вручную, предлагается через минуту после того, как перестал меняться.
- `GET /api/app/download/:file` — скачивание дистрибутива APK или MSI.
- `POST /api/app/upload` — защищённая загрузка новых сборок из GitHub Actions (по токену `UPDATE_TOKEN`).
- `POST /api/app/promote` — перевод версии из канала `beta` в релиз `stable`.
- `GET /api/app/status` — просмотр доступных сборок по каналам.
- `GET /api/app/changelog`, `POST /api/app/changelog` — просмотр и публикация истории изменений (`changelog.json`).

### 3.9. Телеметрия и Сбои
- `POST /api/app/report` — приём отчётов об аварийных завершениях (`crash logs`) от Android и Windows приложений.
- `GET /api/app/reports` — закрытый просмотр накопленных журналов ошибок.

## 4. Зеркалирование видео: Node.js + nginx

Поскольку прямое проксирование сотен мегабайт видеопотока через процесс Node.js приведёт к деградации производительности Event Loop и утечкам памяти, используется гибридная архитектура:

```
[Клиент (VLC/mpv/BurstProxy)]
           │ HTTP Range Request: /api/file/proxy/...
           ▼
        [nginx] (внешний порт 443 HTTPS, без http2)
           │ proxy_pass
           ▼
     [Node.js (Express)]
           │ 1. Проверка HMAC подписи
           │ 2. Резолв ссылки через AllDebrid API
           │ 3. Ответ: X-Accel-Redirect: /alldebrid_stream/<path>
           ▼
        [nginx]
           │ Внутренний location /alldebrid_stream/
           │ proxy_pass к cdn.alldebrid.com (HTTP/1.1)
           ▼
[AllDebrid CDN сервер]
```

### Важные нюансы конфигурации nginx:
- **Отключение HTTP/2 для видео:** в конфигурации виртуального хоста видеопотоков протокол HTTP/2 отключается (используется чистый HTTP/1.1), так как мультиплексирование HTTP/2 плохо сочетается с агрессивными разрывами TCP-соединений при частых перемотках плееров и сосуществованием с Xray VPN на том же порту.
- **Обработка 403 / 410 от CDN:** если прямая ссылка AllDebrid протухла во время просмотра, nginx перехватывает ошибку (`proxy_intercept_errors on`) и перенаправляет запрос обратно в Node.js для прозрачного обновления ссылки.
- В блоке `/_alld/` стоит `proxy_hide_header Content-Disposition`: иначе рядом с нашим `inline; filename=…` приходит `attachment` от файл-хоста, и Firefox при открытии ссылки зеркала в браузере даёт `NS_ERROR_CORRUPTED_CONTENT` (плееры это не замечали).
- Подробные директивы nginx описаны в [`website/NGINX-MIRROR.md`](../website/NGINX-MIRROR.md).

## 5. Поиск по трекерам и обход блокировок

Подсистема поиска (`search.js` + `search-ru.js`) поддерживает два уровня провайдеров:
1. **Прямые парсеры трекеров:**
   - **Rutor:** парсинг HTML-выдачи зеркал (`RUTOR_URL`), извлечение magnet без авторизации.
   - **Rutracker.org:** авторизация по логину/паролю или сессионной cookie (`bb_session`), обход Cloudflare через **FlareSolverr** (`FLARESOLVERR_URL`), скачивание `.torrent` через `dl.php`.
   - **Kinozal.tv:** парсинг поисковой таблицы, извлечение info-hash со страницы деталей.
   - **NNM-Club:** поиск по `tracker.php` в гостевом режиме или по cookie.
2. **Агрегаторы индексаторов (Prowlarr / Jackett):**
   - Интеграция через стандартный Torznab API (`PROWLARR_URL` + `PROWLARR_API_KEY`).
   - Автоматическое обновление определений парсеров силами самого Prowlarr.
3. **Классификация раздач (`classify.js`):**
   - Автоматическое определение типа контента по регулярным выражениям: фильм (BDRip, WEB-DL, 1080p, 4K), сериал (Season, Серии, S01E01), либо не-видео (игры, софт, музыка).
   - Покрыто модульными тестами в `test/classify.test.js`.

## 6. Хранение данных на сервере

Сервер не требует внешней базы данных (PostgreSQL/MongoDB) и использует плоские JSON-файлы с атомарной записью в каталоге `DATA_DIR` (по умолчанию `website/data/`):
- `sessions.json` — активные пользовательские сессии (30 дней, продлеваются при заходе).
- `users.json` — пользователи Discord: ID, ник, имя, ссылка на аватар, роль, даты. Токенов Discord нет.
- `devices.json` — привязанные устройства: **хеш** токена → пользователь, имя устройства, даты.
- `owners.json` — привязка добавленных раздач к уникальным идентификаторам устройств (`sdev` cookie).
- `library-cache.json` — кэшированный список раздач AllDebrid для снижения частоты запросов к внешнему API.
- `poster-cache/` — локальные изображения постеров фильмов (и широкие кадры `w1280_…`, логотипы).
- `media-tags.json` — метки Dolby Vision / HDR / DTS по ffprobe (`services/mediatags.js`), до удаления раздачи.
- `updates/` — бинарные файлы сборок (`suslik-media-*.apk`, `Suslik Media-*.msi`), а также подкаталог `updates/beta/`.

## 7. Переменные окружения (`.env`)

Ключевые переменные конфигурации (см. `.env.example`):

| Переменная | Назначение |
|---|---|
| `SITE_PASSWORD` | Мастер-пароль для входа на сайт и в приложения |
| `SESSION_SECRET` | 32-байтный hex-секрет для подписи cookie и ссылок зеркала |
| `ALLDEBRID_API_KEY` | API-ключ аккаунта AllDebrid |
| `UPDATE_TOKEN` | Секретный токен для публикации сборок из GitHub Actions |
| `BETA_CODE` | Секретный код для доступа клиентов к бета-каналу обновлений |
| `TMDB_API_KEY` | (Опционально) API-ключ The Movie Database для постеров |
| `FLARESOLVERR_URL` | URL локального FlareSolverr для обхода Cloudflare трекеров |
| `PROWLARR_URL` / `KEY` | Интеграция с локальным сервером Prowlarr |
| `COOKIE_SECURE` | Устанавливать в `true` при работе за HTTPS-прокси |
| `PASSWORD_AUTH_ENABLED` | `false` — вход только через Discord: новые входы по паролю закрыты, вошедшие по паролю (сессии и привязанные из них устройства) выкидываются при следующем запросе |
| `SITE_PREFIX` | Путь сайта за nginx, например `/media` (ссылки после входа и для устройств) |
| `DISCORD_CLIENT_ID` / `DISCORD_CLIENT_SECRET` | Приложение Discord (OAuth2); без них вход через Discord выключен |
| `DISCORD_BOT_TOKEN` / `DISCORD_GUILD_ID` | Бот и сервер Discord: проверка участника и ролей. **Без них и без белого списка пускают любого** |
| `DISCORD_ROLE_ALLOW` / `DISCORD_ROLE_ADMIN` | ID ролей (через запятую): кого пускать / кто админ |
| `DISCORD_ALLOWED_USERS` / `DISCORD_OWNER_ID` | Белый список ID; владелец — всегда админ, бот для него не нужен |
| `DISCORD_REDIRECT_URI` | Адрес возврата, если не совпадает с `https://<домен>/api/auth/discord/callback` |
| `TRUST_PROXY` | Устанавливать в `true` при работе за nginx |

## 9. Интерфейс сайта: боковая панель и баннер (24.10)

Файлы: `public/index.html`, `public/redesign.css`, `public/home.js` (подключается после `redesign.js`; оборачивает `renderLibrary` и `setTab`, при отсутствии этих функций ничего не делает).

- **Боковая панель** (шире 900 px): «Главная», «Поиск раздач», «Magnet / торрент»; «КОЛЛЕКЦИЯ» — Фильмы, Сериалы, Аниме, Мультфильмы, Другое со счётчиками (`getItemCategory`); «СЕРВИС» — «Приложения». Выбор категории — `libraryCategory`, повторный клик по «Главной» на странице библиотеки сбрасывает её. Чипы категорий на широком экране скрыты, на телефоне остались вместе с нижней панелью.
- **Баннер «Продолжить просмотр»** (`#continueHero`): до 4 последних начатых фильмов, сменяются каждые 9 с (стоят под курсором). Прогресс — из `/api/sync` (только вход через Discord; приложения и ТВ кладут туда, где остановились). Кадр, логотип, описание, год и рейтинг — из `/api/poster`. «Продолжить» открывает окно выбора плеера на нужной серии с плейлистом. Скрыт при поиске и в категории не «Все»; на телефоне — одной колонкой без постеров.
- **Метки на постерах** (`getItemTags`, `serverTagMap`): ответ `/api/tags`, пока его нет — по названию раздачи.
- **Страницы библиотеки** (`libraryPageSize`, `renderLibraryPager` в `public/index.html`): страница — 3 ряда постеров (на телефоне — Android, iOS, ширина ≤ 600 px — 5 рядов), колонок столько, сколько ставит сетка; переключатель под сеткой, фильтры возвращают на первую страницу.
