# Кинотеатр Suslik Media в Cyberpunk 2077

V смотрит фильм из медиатеки на экране телевизора в мире игры (ПК, Borderless). Плеер — libmpv, как в ПК-версии,
поэтому кодеки те же. Звук игры на время фильма приглушается (можно отключить). Комнаты «Вместе» — общие с ПК,
Android и ТВ (хост 0.5.0).

## Устройство

```
Cyberpunk 2077 (D3D12, Borderless)
 ├─ CET, мод SuslikCinema (Lua) ──интерфейс──► VAO (телефон, меню, пульт)
 │      │ файлы ipc/ VAO
 ├─ helper cinema_helper.py (VAO.RegisterHelper)
 │      │ localhost TCP, JSON по строкам
 └─ suslik-cinema.exe (C++/Qt, cinema/host)
        ├─ ядро desktop-qt/core: BurstProxy, вход, медиатека, пресеты, озвучки, заставки, прогресс
        ├─ mpv: MpvEngine + MpvVideo из desktop-qt/app (без копий), кадр в FBO Qt Quick
        ├─ экран: кадр 1920×1080 → четырёхугольник телевизора (гомография, Item.transform) в прозрачном окне
        └─ звук игры: Core Audio, сессии процесса Cyberpunk2077.exe
```

VAO (`docs/bin/.../VsAPIOverlay`, чужой мод) используем только через его публичный API `VAO.*` и только для
интерфейса. Его код не копируем и не распространяем.

### Папки

| Папка | Что |
|---|---|

| `cinema/mod/SuslikCinema/` | мод CET: экран центром, `state.json` каждый кадр, инструкция — `cinema/mod/README.md` |
| `cinema/host/` | хост `suslik-cinema.exe`: подключается из `desktop-qt` с `-DSM_CINEMA=ON` |

| `cinema/mod/SuslikCinema/companion/cinema_helper.py` | helper VAO: запускает хост с телефона |

### Хост (каркас, 0.1.0)

- `QuadMath`: прямоугольник кадра → четырёхугольник (`QTransform::squareToQuad` → `QMatrix4x4`; перспектива
  через w, текстура с перспективной коррекцией). Тест — `cinema/host/tests/QuadMathTest.cpp`.
- `ScreenQuad`: углы в долях окна, `screens.json` в папке данных.
- `Overlay`: окно `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`, всегда сверху,
  следует за клиентской областью окна игры (раз в 0,5 с). В режиме калибровки принимает мышь.
  Окно игры в Borderless тоже «всегда сверху» и при активации встаёт над оверлеем, поэтому оверлей поднимается
  (`SetWindowPos(HWND_TOPMOST)`, без фокуса) при каждой смене активного окна и раз в 0,5 с.
- `GameAudio`: приглушает только сессии игры, сессии, приглушённые игроком, не трогает. Список приглушённых нами сессий хранится в
  `game-mute.json`. Windows помнит приглушение программы, а сессия игры после перезапуска та же: если игру закрыли во
  время фильма (или хост упал), сессия остаётся в файле и звук ей возвращается, когда игра снова запущена (проверка
  раз в 3 с, `restorePending`). До 0.3.1 хост в этом случае забывал сессию — новая игра шла без звука (08.11).
  `--unmute-game` снимает приглушение со всех сессий игры.
- Хост — один (`SingleInstance` ПК-версии, замок в папке данных): новый запуск просит прежний закрыться (место — на
  сервер, звук — игре) и ждёт до 10 с. Две копии рисовали два оверлея и путали звук игры (08.11).
- `CinemaSettings.cpp`: заглушка `PlaybackSettings::cacheMs()`, чтобы не тянуть настройки всего приложения.
- Папка данных — `%APPDATA%\SuslikCinema` (`SUSLIK_APPDIR`), журнал `player.log` с тегом `[cinema]`.
  libmpv берётся у ПК-версии (`%APPDATA%\SuslikMediaQt\mpv`, `SUSLIK_MPV_DIR`).

Запуск: `suslik-cinema.exe [--file <путь|адрес>] [--remote] [--pattern] [--no-game] [--no-mute] [--calibrate] [--mute-test]
[--mod-dir <папка>] [--lead-ms <мс>] [--present-frames <n>]`; медиатека — см. «Медиатека и воспроизведение».
Клавиши: Ctrl+Alt+C — ручная калибровка без мода (тянуть углы, S — сохранить, R — сбросить), Ctrl+Alt+P — пауза,
Ctrl+Alt+H — скрыть, Ctrl+Alt+Q — выход, Ctrl+Alt+PgUp/PgDn — поправка упреждения ±4 мс (`cinema.json`).

### Медиатека и воспроизведение (этап 1, 0.3.0)

```
suslik-cinema.exe --site <адрес> --login      вход по коду устройства (адрес запоминается)
suslik-cinema.exe --list [слова]              плитки: id, название, релизы с подписью и счётом
suslik-cinema.exe --play <id|название> [--quality 4K|1080p|<часть подписи>] [--release <id>]
                  [--season N] [--episode N] [--from-start] [--reserve-mb <МБ>]
```

- Из `desktop-qt/app/src` без копий: `Library` (вход, `/api/library`, прогресс, «последняя серия»), `AudioAttach`
  (его зовёт `Library`), `player/Reserve` (общий `BurstProxy`, новая подпись через `/api/file/mirror-url`).
  Из ядра: `CloudSync`/`WatchSync`, `groupVersions`, `buildPartyVariant`. Своё у хоста — `CinemaSession`
  (ключи и пульт), `ReleasePick` (выбор релиза, проверка адреса; тест `ReleasePickTest`) и `CinemaSettings.cpp`
  (`burstMb`, `cacheMs`, `reserveDir` вместо `Settings.cpp` ПК-версии, хранилище `settings` хоста).
- Адрес сервера: `SUSLIK_SITE` → сохранённый `--site` → `SM_SITE_URL` сборки. В репозитории его нет.
  Данные (cookie, токен устройства, прогресс) — свои в `%APPDATA%\SuslikCinema`: хост входит как отдельное
  устройство («Suslik Media Windows», имя задаёт `Library`). Строки статусов — `desktop-qt/resources/strings/ru.json`.
- Выбор релиза: версии плитки (`versionsOf`), у сериала — та же серия в каждой версии, у сборника — тот же фильм;
  `--release` → `--quality` (качество или часть подписи) → выбор пользователя в плеерах (`vmagnet:m<id>`,
  `vquality:m<id>`, `vquality:c<canonical_id>`, `vquality:*` — приходят по аккаунту) → лучший по счёту.
- Адрес файла — `/api/file/mirror-url`; хост открывает его, только если это свой сервер, https и путь
  `/api/file/proxy/` (`isMirrorUrl`), иначе отказ. Дальше — `BurstProxy` (`wrap`, `keepOnly`, длина фильма).
- Прогресс: с сохранённого места (`watchInfoWithFallback`, досмотренное — с начала), раз в 10 с, на паузе,
  после перемотки, в конце и при выходе (`Library::noteWatch` → облако, `kick` при выходе, выход через 1,5 с).
  Если место с другого устройства пришло в первые 30 с, а человек не перематывал, — переход туда.
- Фильм открывается, когда готовы и рисовальщик (пара кадров сцены), и адрес от сервера.
- Пульт до телефона VAO: Ctrl+Alt+←/→ — 10 с, Ctrl+Alt+↑/↓ — 10 мин, Ctrl+Alt+A — озвучка, Ctrl+Alt+S — субтитры,
  Ctrl+Alt+I — сводка mpv. Раз в 10 с в журнале `[mpv] … avsync=… [proxy] …`, запросы — `[http]` без параметров.
- Проверки и матрица кодеков — `cinema/TEST.md`.

### Экран в мире (этап 2, 0.2.0)

Мод `cinema/mod/SuslikCinema/init.lua` в `onUpdate` пишет `state.json`:
`{seq, t, pos, f, r, u, kx, ky, ox, oy, W, H, visible, occl, paused, cal, rev, end}`.
- `t` — `os.clock()`; `pos, f, r, u` — камера кадра; линза игры `ndc = k·(x/z) + o` подогнана по `ProjectPoint`
  четырёх точек на осях камеры (`x/z = ±0,25`), поэтому не зависит от того, видно ли экран.
- Файл пишется на месте, а не через переименование: на Windows `os.rename` не заменяет существующий файл, а удалять
  его каждый кадр, пока хост читает, ненадёжно. Хост берёт файл, только если `seq == end`.
- большие экраны: ширина до 40 м, сдвиги вправо ±15 м, вверх −5…15 м, наружу −0,5…5 м (Ctrl+клик — ввести число),
  центр можно ставить на любую стену; галочка «Hide behind walls» выключает загораживание (`"occl": false`
  в `screens.json`) — большой экран неизбежно заходит в стены, и лучи гасили бы его;
- пропорции экрана — список «Aspect» (`ar` в `screens.json`: 16:9, 21:9, 2.39:1, 32:9, 4:3, 0 — Free, высота своим
  ползунком; старая калибровка с `lock` читается как 16:9 или Free); «Left edge / Right edge» `<` `>` двигают один
  край (другой стоит, шаг 0,01–5 м), пропорции при этом — Free. «Picture» (`fit`: `fit` — поля, `fill` — обрезать
  края, `stretch` — растянуть) мод пишет и в `screen.json`; хост по сигналу `GameLink::fitChanged` ставит mpv
  `keepaspect` (`MpvEngine::setKeepAspect`, добавлен в desktop-qt) и `panscan`;
- списки ImGui в CET: `ImGui.Selectable(label, selected)` возвращает состояние «выбран», а не «нажат» — выбранный
  пункт отвечает true каждый кадр. Поэтому пункты рисуются через `pick()` без флага, текущий — со значком `>`;
- оверлей рисуется поверх оружия и интерфейса игры (настоящая глубина — только рисованием в движке, D3D12),
  поэтому мод пишет `hide`: `weapon` — оружие в слоте `AttachmentSlots.WeaponRight` (галочка «Hide screen while
  a weapon is drawn», `settings.txt`), `wheel` — `TimeSystem:IsTimeDilationActive()` (колесо оружия, сканер в бою),
  `user` — клавиша CET «Suslik Cinema: hide/show screen». В меню CET экран не прячется (калибровка);
- `fade` — множитель прозрачности (идеи TVKit, код не взят): дистанция выключения «Turn off beyond m» с плавным
  краем до 2 м (0 — не выключать) и NPC перед экраном (`GetLookAtObject`, `IsNPC`, ближе экрана по взгляду) —
  прозрачность «Opacity with NPC in front» (0,25; 1 — не притенять); NPC проверяется раз в 6 кадров с подтверждением
  двумя проверками;
  настройки — `settings.txt`. Хост сглаживает `occl` и `fade` за ~150 мс по настоящему времени кадра;
- `occl` — 5 лучей (центр и углы; старт луча в 35 см от глаз) раз в 6 кадров, новое значение принимается, только
  если две проверки подряд совпали: Static и Vehicle — 1, Dynamic — 0,5 (галочка «See-through when objects are in
  front» снята — Dynamic не проверяется, `objFade` в `settings.txt`), попадания ближе 50 см от глаз не считаются.
  Луч кончается в `od` м перед плоскостью экрана по нормали (ползунок «Ignore bumps up to m», 0,4; плюс утопление
  `sn < 0`): выступы стены над экраном (колонки, карниз, ступень) не притеняют его. Раньше луч кончался в 12 см
  вдоль луча, и такие выступы делали экран прозрачным. `paused` — `SystemRequestsHandler:IsGamePaused()`.
- Углы экрана — в `screen.json` (`rev` меняется при каждом изменении, хост перечитывает по `rev` из `state.json`).

Хост (`GameLink`, математика — `GameView`, тест `GameViewTest`):
- папка мода — от пути процесса окна игры, `bin\x64\plugins\cyber_engine_tweaks\mods\SuslikCinema`;
- `state.json` читается в каждом кадре оверлея в `QQuickWindow::afterAnimating` (поток интерфейса, перед синхронизацией
  сцены; оверлей рисуется непрерывно), с `FILE_SHARE_WRITE | FILE_SHARE_DELETE`, чтобы не мешать моду;
- часы: смещение `os.clock` → QPC — минимум `(QPC получения − t)` за 2 с, текущее подтягивается к нему не быстрее
  0,2 мс за кадр игры (скачок смещения давал рывок экрана на быстром повороте); Ctrl+Alt+R — запись 10 с по кадрам
  оверлея в `cinema-rec.csv`;
- момент показа — ближайший vblank DWM (`DwmGetCompositionTimingInfo`) + `--present-frames` периодов (1);
  упреждение `lead = показ − t + поправка`, от −120 до 100 мс. Поправка по умолчанию −24 мс: картинка игры на мониторе
  старше камеры мода (очередь кадров, генерация кадров DLSS ×3 у владельца — 168 к/с на экране при 56 настоящих),
  итоговое упреждение около −7 мс. `lead < 0` — интерполяция между двумя кадрами игры из истории (0,25 с), как у
  генерации кадров; `lead > 0` — прогноз поворота (рыскание вокруг вертикали, тангаж
  вокруг горизонтали, крен сохраняется) и сдвига по сглаженным скоростям, затухание при остановке, предел 8° и 25 см;
- проекция строится прямо из камеры (`screenTransform`): кадр -> мир -> камера -> доли окна одной однородной
  матрицей с w = глубина. Часть экрана за камерой отрезает видеокарта, поэтому большой экран вблизи не пропадает
  (раньше по четырём спроецированным углам он прятался, как только угол уходил за спину);
- экран прячется сразу: нет кадров игры 0,3 с, пауза игры, игра не на переднем плане (`SetWinEventHook`), экран
  спиной, целиком за камерой или вне кадра; `occl` — плавно (~150 мс);
- буфер кадра постоянный: 1920 по ширине (или ширина видео, если меньше), меняется только со сменой фильма или
  пропорций экрана. Подбор по размеру на мониторе отменён (08.11): пересоздание под 4K задерживало кадры на
  50–320 мс, а ступени 960/1280/1920 при обходе экрана давали мигание — новый буфер пуст до следующего кадра mpv;
  кайма 2 px в слое — мягкий край;
- быстрый поворот — прозрачность 50 % с запасом по порогу (вкл. выше 150°/с, выкл. ниже 100°/с) и плавно
  (0,12 с вниз, 0,3 с вверх): на пороге 120°/с без запаса экран мигал при обходе;
- видео: ядро mpv создаётся до первого кадра сцены, файл открывается после двух кадров. Если открыть файл раньше,
  чем `MpvVideo` создал render context (`vo=libmpv`), mpv выключает видео, а звук идёт — экран чёрный (08.11).
  Фильтры mpv в хосте быстрые (bilinear, без линейного уменьшения, деблокинга, дизеринга и замера пика HDR): на 4K
  дорогие фильтры ПК-версии задерживали кадры оверлея до 50–260 мс, и экран «прилипал» к камере (08.11);
  в строке журнала — «долгих кадров N (до M мс)», кадры оверлея длиннее 25 мс;
- журнал раз в 10 с: `[cinema] 10 с: кадров …/с, игры …/с, недописано …, показан …%, упреждение … мс (возраст … мс,
  поправка …), поворот до …°/с, буфер …`.

### Пульт на телефоне VAO (этап 3, хост 0.4.0)

Вместо задуманного TCP между helper и хостом — файлы в папке мода, как `state.json`: Lua в CET сокетов не умеет,
helper был бы только пересыльщиком файлов, а запись на месте с `seq`/`end` уже проверена на `state.json`.
Helper нужен для одного: Lua не может запустить программу.

| Файл | Кто пишет | Что |
|---|---|---|
| `remote.json` | мод (`remote.lua`) | `{"sid", "cmds": [{"n", "at", "op", …}]}` — последние 12 команд; хост выполняет новые по `n` (`RemoteLink::takeNew`), старше 30 с (после запуска хоста — 15 с) пропускает; новый `sid` — мод перезапущен, счёт заново |
| `host.json` | хост (`RemoteLink`) | состояние раз в 0,3 с при изменении и раз в секунду для признака жизни (`time` — секунды Unix): `auth, user, code, url, site, busy, msg, msgN, muteGame, pauseWithGame, libRev, play{title, rel, pos, dur, paused, buf, vol, audio[], subs[]}`; мод берёт файл, только если `seq == end` |
| `library.json` | хост | `{seq = libRev, items: [{id, t, y, k (m/s/c), ok, st, s: [{n, e[]}], n, rel: [{id, l}]}]}` — не чаще раза в секунду и только при изменении |
| `host.txt` | хост | путь к `suslik-cinema.exe` |

Команды: `login`, `cancelLogin`, `logout`, `refresh`, `play{id, release, season, episode, fromStart}`, `toggle`,
`seek{ms}`, `seekBy{ms}`, `audio{id?}`, `sub{id?}` (без id — следующая), `volume{v}`, `stop`, `opt{key, on}`, `quit`.

- Телефон: значок «Suslik Cinema» (`VAO.RegisterApp`), окно `SuslikCinema_remote`. Страницы: хост не запущен
  (кнопка запуска, при открытии окна запускается сам) → вход по коду (код крупно, «Открыть страницу на ПК» —
  `VAO.OpenUrl`; хост браузер сам не открывает: `Library::setOpenPairingPage(false)`) → медиатека (поиск без учёта
  регистра, в том числе русского, по 8 плиток) → фильм (сезон и серия, сборник — номер фильма; «Смотреть» — релиз
  как в плеерах, или конкретный релиз; «С начала») → пульт (место ползунком, ±10 с, ±10 мин, пауза, громкость,
  озвучка и субтитры по кругу, флажки, «Стоп»).
- Helper `companion/cinema_helper.py` (`VAO.RegisterHelper`, без автозапуска): хост жив (`host.json` моложе 4 с) —
  ничего; иначе запускает `host.txt --remote` отдельным процессом (`DETACHED_PROCESS`, отрыв от задания VAO) и ждёт
  ответа до 15 с. Хост, запущенный с `--remote`, не трогает уже запущенный (обычный запуск просит его закрыться).
- Хост теперь всегда с плеером: без фильма экран пуст (`Host.blank`, прозрачность 0 — рисовальщик mpv должен
  существовать до открытия файла). Тестовая картинка — `--pattern`.
- «Глушить звук игры во время фильма» и «Пауза фильма вместе с игрой» (`paused` из `state.json`) — флажки пульта,
  хранятся в `settings` хоста (`remote_muteGame`, `remote_pauseWithGame`), по умолчанию включены. Фильм ставится на
  паузу и когда окно игры пропало; продолжается сам, только если паузу ставил хост.

### 3D-звук (хост 0.6.0)

Идея TVKit (код не взят): звук фильма идёт от телевизора в мире игры. Режимы на пульте: выкл / стерео / объёмный
(по умолчанию), флажок «За стеной глуше».

- Расчёт — `SpatialAudio` (в `suslik_cinema_geom`, тест `SpatialAudioTest`), по камере последнего кадра игры и
  центру экрана (`GameLink::listener`): громкость полная до ширины экрана (не меньше 2 м), дальше `(1 − x)^1.5` до
  6 ширин (не меньше 20 м) — как у TVKit; дальнее ухо тише (стерео ×0,2 сбоку, объёмный ×0,4); у объёмного ещё
  тень головы (верха дальнего уха до 4 кГц) и «за спиной» (верха до 7 кГц, ×0,8); вблизи большого экрана
  направление размывается; за стеной (Static, `occl` мода) — ×0,4 и 700 Гц, как «Muffle» у TVKit.
- HRTF как в браузере у TVKit (Web Audio) в mpv без SOFA-файла нет, поэтому уши — по отдельности фильтрами lavfi:
  цепочка `@c3d` (`aformat` в стерео → `channelsplit` → на каждое ухо `lowpass` и `volume` → `join` → общий
  `volume`). Значения меняются на лету `af-command` раз в 50 мс со сглаживанием (~0,15 с, частоты — по логарифму),
  только когда изменились: цепочку не пересобираем (щелчки). `MpvEngine::open` сбрасывает `af` — хост ставит цепочку
  после каждого открытия (`SpatialSound::install`). Выкл — цепочки нет вовсе.
- Нет мода или камеры — цепочка нейтральна (звук как есть). Раз в 10 с в журнале `[audio3d] уши …, верха …, общая …`.
- Проверено без игры (08.11, libmpv 0.40, ffmpeg libavfilter 12.5): цепочка встаёт, звук 48 кГц стерео; экран справа
  и сзади — за ~1 с левое ухо 0,50 и верха 5,2 кГц, дальше команд нет (значения сошлись).

### Колонки 5.1 / 7.1 (хост 0.7.0)

Четвёртый режим 3D-звука «колонки» (`Audio3D::Speakers`, `remote_audio3d = 3`): каждый канал фильма звучит из своей
точки в мире, как от колонок домашнего кинотеатра. Точки ставятся в окне мода, раздел «Speakers».

- Мод: раскладка 5.1 (FL FR FC LFE SL SR) или 7.1 (+ BL BR); точка — в прицел (20 см перед поверхностью), где
  стоит V или «Auto» по ITU вокруг места V (фронт у краёв экрана, не уже ±22°, боковые ±110° / ±90°, тылы ±150°;
  колонка, которая ушла бы в стену, встаёт в 25 см перед ней). Клавиша «place next speaker at aim». Метки в кадре,
  пока открыто окно мода. Хранится в `speakers.json` (все точки, обеих раскладок), хосту — ключ `spk` в
  `screen.json` (только каналы раскладки, rev + 1). «За стеной» — `socc` в `state.json`: один луч Static за кадр
  по кругу, от 35 см перед глазами до 30 см перед колонкой, значение принимается, если две проверки подряд согласны.
- Расчёт — `speakerMix` (`SpatialAudio`): каждый канал — как экран в «объёмном» режиме (уши, тень головы, за спиной,
  стена), размер колонки 0,3 м. Громкость — по комнате колонок (`speakerRoom`: центр поставленных, радиус до дальней,
  не меньше 2 м): внутри радиуса ×1,25 полная, дальше спад (1 − x)^1.5 на max(20 м, 3 радиуса); ближняя колонка
  громче, дальняя тише (√(радиус / расстояние), ×0,6…×1,4). Сначала каждая колонка спадала по правилу телевизора
  (полная до 2 м, тишина к 20 м) — в зале с колонками в 17–23 м звук почти пропадал (08.11, владелец); сабвуфер — без направления, только расстояние и стена. Уровни как у
  стерео-сведения ITU: фронт 1, центр и тылы 0,707, сабвуфер 0,5. Подстановки (`speakerPlace`): тылы 7.1 ↔ боковые
  (раскладка 5.1 и фильм 5.1 «back»), центр — между фронтами, иначе экран; места нет — канал без направления.
- Цепочка `@c3d` для колонок: `aformat` в 7.1 (стерео — на FL/FR, 5.1(side) — на свои каналы) → `channelsplit` →
  каждый канал `asplit` на два уха (`lowpass@lN/rN`, `volume@glN/grN`) → `amix normalize=0` по уху → `join` в стерео.
  Смена раскладки цепочку не пересобирает. Журнал раз в 10 с: `[audio3d] колонки: FL 0.95/0.62 …` (`*` — канал
  без своей колонки).
- Проверено без игры (08.11): `SpatialAudioTest` 18/18; libmpv 0.40 (ctypes) — цепочка встаёт для 5.1(side), 7.1
  и стерео, выход стерео, `af-command` проходят. В игре не проверено — `cinema/TEST.md`, «Колонки 5.1 / 7.1».

### Эффект проектора (хост 0.8.0)

Картинка как с плёночного кинопроектора: шейдеры mpv GRAINLIGHT (github.com/claudiofabian-sudo/grainlight, MIT,
файлы и лицензия — `cinema/host/grainlight/`). Три прохода: дрожание кадра в фильмовом канале и мерцание лампы
(`HOOK MAIN`), кривая контраста, насыщенность, тёплый свет, ореол вокруг светлого, виньетка (`HOOK MAIN`), зерно,
пыль, волоски, метки смены части (`HOOK OUTPUT`). Шейдеры обычные для mpv, без libplacebo — работают с `vo=libmpv`.

| # | Пресет | Откуда |
|---|---|---|
| 0 | выкл | — |
| 1 | тонкий | GRAINLIGHT 1 «Sutil» |
| 2 | кино 2000-х | GRAINLIGHT 2 «Cine 2000» |
| 3 | старая копия | GRAINLIGHT 3 «Copia veterana» |
| 4 | сбалансированный | GRAINLIGHT 4 «Equilibrado» |
| 5 | немое кино | свой: шейдер 3, ч/б (`SATUR 0`), сепия, сильное мерцание и дрожание, без меток |
| 6 | домашний проектор | свой: шейдер 1, почти без зерна, ореол, виньетка, лёгкое мерцание, без пыли |

- Таблица и подстановка `#define` — `ProjectorLook` (в `suslik_cinema_geom`, тест `ProjectorLookTest` сверяет свои
  `#define` с настоящими файлами). Ставит `Projector`: шейдер из ресурсов `:/grainlight/` (с подстановкой) пишется в
  `%APPDATA%\SuslikCinema\shaders\<id>.glsl`, затем `change-list glsl-shaders clr` и `append` (путь одним элементом).
  После каждого открытия файла — снова, как 3D-звук.
- Звук плёнки (GRAINLIGHT `audio-presets.lua`): «оптика 35 мм» (полоса 55 Гц–9,5 кГц, подъём 2,2 кГц, мягкое сжатие)
  и «винил» (тепло 90 Гц, детонация 0,55 Гц, блеск). Фильтр `@film` ставится в `af` перед `@c3d` (`SpatialSound`),
  по каналам — колонки получают уже «плёночный» 5.1.
- Настройки — `remote_projector` (0–6), `remote_filmSound` (0–2), команды `opt{key: projector|filmSound, v}`,
  в `host.json` — `projector`, `filmSound`. Телефон: «Проектор: …» и «Звук плёнки: …» по кругу на пульте; окно мода:
  раздел «Projector look» (выпадающие списки, через `REMOTE.send`).
- По умолчанию выкл. Проверено без игры (08.11, libmpv 0.40, OpenGL WGL): все 6 пресетов — три прохода
  `user shader: 35mm-N …` в `vo-passes`, ошибок компиляции нет; `@film` + цепочка колонок встают. В игре не проверено.
- GRAINLIGHT настроен под SDR: на HDR-фильмах (4K HDR remux) вид будет другим.
- Проходы `HOOK MAIN` GRAINLIGHT хост переносит на `HOOK OUTPUT` (`hookAtOutput`): считаются на кадре буфера
  1920×1080, а не на кадре фильма. 08.11: «кино 2000-х» на 4K (Edgerunners 2160p) — игра 44 → 28–33 к/с, пока экран
  виден, у mpv сотни отброшенных кадров, экран запаздывал за камерой. Смещения GRAINLIGHT в долях высоты — вид тот же.

### Вписать в сцену (хост 0.9.0)

Оверлей рисуется поверх готового кадра игры: тонмаппинг, свет и постобработка игры на фильм не действуют, и он
выглядит приклеенным (ярче, контрастнее, резче и «чернее» зала). Флажок пульта «Вписать в сцену» (по умолчанию вкл):

- Шейдер «в зале» `cinema/host/scene/in-world.glsl` (`HOOK OUTPUT`, после пресета проектора, `Projector::install`):
  экспозиция 0,90, мягкое плечо светов с 0,60 (линейный свет), света теряют цвет на 20 %, насыщенность 1,0,
  свечение ярких мест (2 кольца по 8 точек, порог 0,55), неподвижная фактура полотна 1 %, мягкость 0,12, слабый шум.
  Значения — `#define` в начале файла. HDR-фильм (`video-params/gamma` pq/hlg, `main.cpp: syncHdr`): mpv сжимает
  HDR сам (`tone-mapping=bt.2446a` — держит насыщенность), шейдер ставится с `sceneShaderDefines(true)`
  (`ProjectorLook`: плечо 0,78, потеря цвета 8 %, насыщенность 1,06, свечение 0,10), файл `in-world-hdr.glsl`.
- Кадр на экран — слой с мипмапами (`layer.mipmap`): экран на мониторе меньше буфера 1920 и под углом, без них
  рябь и муар на мелких деталях.
- Подстройка под свет игры — `SceneProbe`: раз в 0,5 с снимает GDI (`StretchBlt` HALFTONE, фоновый поток) область
  вокруг экрана (экран, раздутый на 60 %), в уменьшенном виде 64 точки по длинной стороне; сам экран с отсветом
  (раздутый на 22 %) и самые яркие 10 % точек (HUD, лампы) не считаются. Сглаживание 1,2 с. Мерит, только когда фильм
  на экране, экран виден и игра не на паузе. Математика — `SceneLight` (в `suslik_cinema_geom`, тест `SceneLightTest`).
- По замеру (`sceneLookFor`): от тёмного зала (средний свет 0,4 %) до светлой сцены (18 %) — затемнение кадра
  ×0,84…1, свет зала на полотне 5…12 % цветом окружения ×3, сила отсвета 0,26…0,08 (×1,6 в шейдере). В `Main.qml`:
  чёрный и цветной прямоугольники поверх видео; отсвет — `ShaderEffect` `qml/shaders/spill.frag` (qsb при сборке,
  `qt_add_shaders`) на поле 25 % вокруг полотна: цвет края и средний цвет кадра из копии 256×144 с мипмапами,
  спад экспонентой 0,09 высоты. Пишет цвет с альфой 0 — в окне с премультиплицированной альфой свет прибавляется
  к игре (тёмный кадр вокруг не затемняет, яркий светит сильнее). Переходы 0,6 с.
- Настройка `remote_scene`, команда `opt{key: scene, on}`, в статусе `scene`. Выкл — ни шейдера, ни замера, ни отсвета.
- Вкладка «Картинка» на телефоне (кнопка «Картинка…» рядом с флажком): 10 ползунков `SceneKnob` (`SceneLight.cpp`,
  та же таблица `R.LOOK` в `remote.lua`, сверяет `SceneLightTest`). Яркость, насыщенность, светлые места, свечение,
  мягкость, фактура — `#define USER_*` шейдера «в зале» поверх его значений (и HDR-значений), `Projector::setTuning`
  ставит шейдер снова, только если они поменялись. Подстройка под свет зала, свет зала на полотне, отсвет, размер
  отсвета — `tunedLook` в `SceneProbe` и `scene.spillSize` в `Main.qml`. Значение уходит, когда ползунок отпущен:
  `opt{key: look, id, v}`, сброс — `opt{key: look, reset: true}`; настройки `remote_look_<id>`, в статусе `look{id: v}`.
- mpv держит прочитанные шейдеры в кэше по пути до конца работы: переписанный файл с тем же именем не перечитывается
  (08.11 ползунки не действовали). `Projector` пишет шейдеры как `<имя>-<8 знаков SHA-1>.glsl`, прежние версии удаляет.
- Отсвет с альфой 0 («прибавить свет») Windows не показывает: альфа пятна — по яркости его цвета (тёмное не затемняет).
- Замер раз в секунду; в журнал раз в 30 замеров — `[scene] снимок: в среднем … мс, до … мс` (снимок рабочего стола
  через GDI может тормозить видеокарту: при «плавающем» экране сравнить с выключенным «Вписать в сцену»).
- Ограничение: руки, оружие и HUD перед экраном оверлей по-прежнему не перекрывают (нужна глубина движка).
- Телефон VAO в режиме курсора забирает фокус своему окну («V's API Overlay (overlay window)», pythonw.exe), и хост
  прятал экран («игра не на переднем плане»). Теперь окно VAO и оверлей NVIDIA считаются спутниками игры
  (`Overlay.cpp`, `isCompanion`): экран остаётся и держится под их окном, после закрытия — снова сверху.

### Экран как у ведущего (комнаты, хост 0.9.0)

Гость комнаты ставит у себя экран в том же месте мира игры, что и ведущий (координаты мира у всех игроков одни).
- Сервер: действие комнаты `screen` (`website/src/services/rooms.js`, `cleanScreen`): только ведущий; поля `c`, `n`
  (по 3 числа), `w`, `h`, `sr`, `su`, `sn`, `ar`, `fit`, остальное отбрасывается; `null` — убрать. Хранится в комнате

- Ведущий: `CinemaParty::shareScreen` раз в 2 с читает `screens.json` мода (`RoomScreen::screenFromCalib`) и, если

### Комнаты «Вместе» (хост 0.5.0)

Те же комнаты, что у ПК, Android и ТВ: сервер `/api/rooms`, код комнаты, ведущий, гости. Без своих копий:
`app::Party` из ПК-версии (создание, вход по коду, поток событий, часы, права, варианты раздач и сдвиг времени между
ними) и общий движок синхронизации ядра `core::PartySyncEngine` (тот же, что у Android и ПК: дрейф, ожидание
буферизации, пауза и перемотка ведущего). Своё у хоста — `CinemaParty`, как `PartySync` у ПК-версии: плеер хоста
для движка (`SyncPlayer`: место, пауза, перемотка, скорость; метка перемотки — `CinemaSession::seekStamp`).

- Ведущий включил фильм (телефон или `--play`) — он становится фильмом комнаты (`putFilm`: ключ, название,
  canonical_id, монтаж, варианты релизов). Комнату создали, когда фильм уже шёл, — тоже. «Стоп» ведущего — комната
  без фильма (`closeIfNobodyWatches`).
- Гость сразу открывает фильм ведущего с места комнаты (как `PartyFollow.qml` у ПК: только что включённый фильм
  ждёт место ведущего до 2,5 с); фильма нет в медиатеке — она перечитывается один раз. Ведущий сменил фильм или
  серию — гость за ним; закрыл — у гостя фильм останавливается. «Стоп» гостя — он ждёт кнопку «Включить фильм
  комнаты». Пауза и перемотка гостя заперты («Паузой и перемоткой управляет …»).
- Подсказки движка («ставит паузу», «перематывает на…», «ждём загрузку») — всплывашками на телефоне (строки
  `ru.json` ПК-версии). Выход из аккаунта — выход из комнаты.
- Просьбы Discord Activity поискать на RuTracker через этот ПК кинотеатр отклоняет (`CinemaTrackers.cpp`:
  браузерный мост ПК-версии сюда не тянем).
- Телефон: «Смотреть вместе» в медиатеке и строка комнаты на пульте → страница «Вместе» (код, «Войти», «Создать
  комнату»; в комнате — ведущий, участники, фильм и его состояние, «Выйти из комнаты»). Команды `roomCreate`,
  `roomJoin{code}`, `roomLeave`, `roomFollow`; состояние — `room{in, code, host, hostName, members[], title, line,
  connected, busy, error, watching}` в `host.json`.

## Итоги разведки (этап 0, 08.11)

Стенд владельца: игра 2.5, CET 1.38.1, Codeware 1.21.2, Borderless 2560×1440, DLSS Quality и генерация кадров.

**Камера.**
- Позиция глаз: `CameraSystem:GetActiveCameraWorldTransform(Transform.new())` (в CET 1.38 нужен out-параметр)
  или `player:GetFPPCameraComponent():GetLocalToWorld():GetTranslation()`. Значения совпадают до миллиметра.
  `player:GetWorldPosition()` — это ноги, на ~1,6 м ниже.
- Направления: `GetActiveCameraForward/Right/Up`.
- FOV: `FPPCamera:GetFOV()` = 68,24, в настройках 100. Угадывать его не нужно, см. «Проекция».

**Проекция.** `Game.GetCameraSystem():ProjectPoint(Vector4)` даёт NDC проекцией игры (FOV, аспект, поправки):
`px = (x+1)/2·W`, `py = (1−y)/2·H`. Своя камера-обскура с FOV «на глаз» ошибается к краям экрана.
Хосту фокус передаём числами: `kx, ky` по наименьшим квадратам `ndc = k·(x/z)` по углам экрана
(`predictPose` в `cinema/recon/.../init.lua`).

**Экран.**
- Ставится центром, как в TVKit: прицел в центр экрана → луч.
- Брать попадание по стеклу (`glass_electronics`, группы Dynamic/Interaction). Коллизия корпуса (Static, `plastic`)
  на ~5 см ближе, и экран по ней висит перед телевизором.
- Нормаль — `GetWorldForward()` объекта класса `TV` (`GetLookAtObject`), иначе — нормаль поверхности.
- Размер — ползунок ширины (16:9), плюс сдвиги вправо, вверх, наружу. Четыре угла отдельными лучами неудобны,
  их порядок нужно разбирать.
- Телевизор в квартире V (Мегабашня H10): центр (−1376,28; 1267,68; 124,11), нормаль (−0,9962; 0,0872; 0),
  экран 1,16 × 0,65 м. Владелец увеличил виртуальный экран до 1,96 × 1,10 м со сдвигом вверх 0,09 м.

**Время.**
- `onUpdate` и `onDraw` вызываются раз на кадр. Кадр 16 мс ± 1 мс, рвано не бывает.
- Камера, прочитанная в кадре, на ~1 кадр впереди картинки на экране. Лучше всего рамку держит упреждение на 1 кадр:
  `Lag frames = −1` (линейно по экранным углам) или режим `pose` (поворот камеры вперёд на `Lead ms` ≈ 15 мс,
  затухание при остановке, перепроекция с `kx, ky`). Какой из двух лучше, журнал не показал: оба лучше, чем без упреждения.
- Генерация кадров DLSS не влияет.
- Скорость поворота при обычной игре: медиана 12°/с, 90 % — до 51°/с, максимум ~100°/с.
  Один кадр отставания при 50°/с — около 30 px.
- Результат владелец считает удовлетворительным.

**Окно поверх игры.** Прозрачное окно хоста (Qt Quick, OpenGL, `WS_EX_LAYERED|TRANSPARENT|NOACTIVATE`) видно поверх
игры в Borderless. Перспективный четырёхугольник рисуется (снимок 08.11). Фокус и клики проверены только в CET,
окно хоста при игре — нет.

**TVKit** (`docs/TVKit`, чужой мод, не в git, только идеи):
- `ProjectPoint`; экран центром с ползунками;
- `state.json` пишется каждый кадр, companion читает его раз в 4 мс;
- сглаживание мелкого дрожания (мёртвая зона, затем EMA);
- упреждение 0–60 мс одинаковым сдвигом всех углов;
- скрытие за стенами пятью лучами (центр и углы): Static прячет, Dynamic притеняет;
- звук 3D через Web Audio.

### Этап 3. Мост и интерфейс (в коде, хост 0.4.0; см. «Пульт на телефоне VAO»)

- Helper `cinema/helper/cinema_helper.py` через `VAO.RegisterHelper`: запускает хост, держит TCP с ним
  (протокол выше), передаёт команды из телефона VAO.
- Телефон VAO: вход по коду, медиатека, выбор фильма, пульт (пауза, перемотка, громкость, дорожки),
  переключатель «Звук игры во время фильма: приглушить / не трогать».
- Пауза фильма, когда игра на паузе или открыто меню (флаг в `state.json`), приглушение и его снятие,
  восстановление звука после сбоя.

### Этап 4. Функции ПК

Озвучки (`CustomAudio`), субтитры (PGS/ASS через mpv), прогресс по аккаунту (`WatchSync`), заставки и титры
(`MarkersDetector`), релиз по пресету.

### Этап 5. Бета

Сборка хоста в CI вручную (`workflow_dispatch`, `-DSM_CINEMA=ON`), zip мода, список проверенных версий игры, CET,
Codeware и VAO, `docs/CYBERPUNK.md` для пользователя. Стабильный канал — только по «выпускай всем».
