# Suslik Media — Windows-приложение (`desktop/`)

Документация по настольному клиенту Suslik Media для Windows: архитектура плеера, вывод mpv в единой сцене Compose (Skiko OpenGL), дизайн-система «Жидкое стекло», Win32-интеграция и сборка.

---

## 1. Стек технологий

- **Язык и платформа:** Kotlin 2.0+ (JVM 17 или 21).
- **UI-фреймворк:** Compose Desktop (Jetpack Compose for Desktop / Skiko / DirectX DWM).
- **Движок воспроизведения:**
  - **mpv:** нативная библиотека `libmpv-2.dll` (x86_64) через JNA; кадры рисуются в OpenGL-контексте окна (Skiko) через render API (`vo=libmpv`), аппаратное декодирование `hwdec=auto-safe`.
- **Интеграция с Win32 API:** JNA (`User32`, `Gdi32`, `Dwmapi`) для Borderless Fullscreen, масок окон `SetWindowRgn`, блокировки DirectFlip и анимаций окна.
- **Общий модуль:** прямая зависимость от `:shared` (`BurstProxy`, `PlaybackSupervisor`, `TsClock`, `Model`, `Versions`).

## 3. Движок воспроизведения (mpv)

Плеер работает на базе нативного движка mpv (`MpvEngine.kt`), реализующего контракт `PlayerEngine`:

- **Вывод в сцене окна (render API):** `vo=libmpv`, кадры рисует сам mpv в OpenGL-контексте, которым Skiko рисует окно; видео — обычный слой Compose под панелями (подробно — §4). Аппаратное декодирование `hwdec=auto-safe` сохраняется (на NVIDIA — `nvdec`, кадр в память процессора не копируется).
- **Стилизованные субтитры (libass):** безупречный рендеринг сложной верстки ASS/SSA субтитров. Изменение масштаба (`sub-scale`) выполняется на лету через вызов C-API `mpv_set_property_string` без остановки потока и без артефактов перерисовки.
- **Индикация буферизации в процентах:** отслеживание нативного свойства mpv `cache-buffering-state` (`demuxer-readahead-secs`, `cache-pause=yes`), плавно транслирующее процент заполнения буфера в интерфейс плеера.
- **Потокобезопасная синхронизация дорожек:** списки внешних звуковых дорожек и субтитров защищены мьютексом `trackLock` с аннотацией `@Volatile`, а метод добавления дорожек верифицирует совпадение URL потока с текущим `path` в mpv по событию `EV_FILE_LOADED`, исключая гонки при быстром переключении серий.
- **Безопасная 64-битная работа с нативной памятью (JNA):**
  - Для события `EV_END_FILE` поле `void *data` в 64-битной структуре `mpv_event` считывается со смещением **16 байт**.
  - Для событий изменения свойств `onProperty` указатель `name` считывается по 8-байтному смещению с кодировкой UTF-8.
- **Перезапуск видеовывода без деструкции (`restartVideoOutput`):** программный сброс видеопайплайна (`vid = no` → `vid = auto` с относительным seek 0) для восстановления рендеринга без пересоздания окон; render context при этом остаётся.
- **Управление библиотекой `libmpv-2.dll`:** версия (архив сборки mpv и SHA-256 архива и библиотеки) зафиксирована в `src/main/resources/libmpv.properties`. Установщик везёт её сжатой внутри себя и кладёт в `%APPDATA%\SuslikMedia\mpv\` с меткой `libmpv.version`; приложение (`player/MpvInstall.kt`) при совпадении метки ничего не делает, а если библиотеки нет (самообновление со старой версии) — скачивает архив (~30 МБ) и распаковывает его `tar.exe` из Windows. Пути поиска: рядом с приложением, `%APPDATA%\SuslikMedia\mpv\`, `SUSLIK_MPV_DIR`, PATH.

## 4. Видео и панели в единой сцене Compose

Видео и панели рисуются в одной поверхности окна — нет окон-оверлеев и Win32-обходов (устаревших схем с AWT Canvas, `syncOverlayBounds`, `clipToBottom`, `WS_DISABLED`, скрытия окон на 80 мс).

- **Контекст.** Skiko рисует окно через OpenGL (`-Dskiko.renderApi=OPENGL`) на потоке интерфейса и не отпускает свой контекст. `SkikoGl.find(window)` берёт из внутренних полей Skiko 0.8.x HDC, HGLRC и `DirectContext` Skia (`SkiaLayer.getRedrawer$skiko`, `WindowsOpenGLRedrawer.device/context/contextHandler`).
- **Render context.** `MpvEngine.startVideo` → `MpvVideoOut.start`: `mpv_render_context_create` (API `opengl`, `get_proc_address` — `wglGetProcAddress`, для GL 1.1 — экспорт `opengl32.dll`) до первого `loadfile`. Колбэк update из потоков mpv только ставит `invokeLater`; на потоке интерфейса — `mpv_render_context_update` (заодно выполняет запросы ядра: снимок кадра и т. п.) и, если есть кадр, `mpv_render_context_render` (`BLOCK_FOR_TARGET_TIME=0`, `FLIP_Y=0`).
- **Кадр без копии.** Текстуру создаёт Skia (`Surface.makeRenderTarget`, `TOP_LEFT`, RGBA8); mpv рисует прямо в её кадровый буфер, а картинка для Compose — снимок этой поверхности, который делит с ней текстуру. Skia номер буфера не сообщает: после `canvas.clear` + `flush` берётся привязанный `GL_DRAW_FRAMEBUFFER_BINDING` и проверяется, что к нему прикреплена текстура нужного размера. Не вышло — запасной путь: своя текстура + `Surface.makeFromBackendRenderTarget` + `makeImageSnapshot` (копия на видеокарте) с `notifyContentWillChange` перед каждым кадром. `SUSLIK_VIDEO_COPY=1` включает его принудительно.
- **Состояние GL — главная ловушка общего контекста:**
  - перед каждым вызовом mpv (`Gl.defaultsForMpv`) — сэмплеры Skia сняты со всех текстурных блоков, буферы (`PIXEL_UNPACK` и др.) и VAO отвязаны, `glPixelStore` и `glEnable`-флаги по умолчанию. Без этого у HEVC/AV1 (10 бит, HDR) был мусор и чёрный кадр с точками;
  - после работы — `glBindFramebuffer(0)` и `DirectContext.resetGLAll()` (`leaveGl`). Skiko при изменении размера окна оборачивает под окно тот буфер, что привязан сейчас: оставленный буфер mpv уводил всё окно в текстуру видео (чёрный экран после ресайза).
- **Слой Compose.** `MpvVideoSurface` — `Canvas`, который рисует картинку; новый кадр меняет `frame` (перерисовка без перекомпоновки), размер области (`onSizeChanged`) уходит в mpv — он сам вписывает кадр и рисует субтитры по всей области.
- **Панели.** `PlayerTopBar` (75 dp) и `PlayerBottomBar` (460 dp) — слои того же `Box` (`SceneBars`, своя область перекомпоновки). У нижней панели `inputHeight`: клики мимо кнопок ловит только полоса 220 dp (с открытым меню — вся высота), выше — видео (пауза, двойной клик, колесо громкости). Движения мыши над всем плеером видит один `pointerInput` в проходе `Initial`. Курсор прячется `pointerHoverIcon` (пустой курсор), фокус клавиатуры не теряется — окно одно.
- **Ресайз.** Пока тянут край окна, AWT на каждом шаге перекладывает окно (`WComponentPeer.reshape`, `setBounds`) и держит поток интерфейса по 1–5 с. Пока открыт плеер mpv, `Toolkit.setDynamicLayout(false)`: окно перестраивается один раз после отпускания края, видео идёт; новый участок окна до отпускания чёрный.
- **Закрытие.** Render context освобождается на потоке интерфейса до `mpv_terminate_destroy`, иначе mpv роняет процесс (`Broken API use: mpv_render_context_free() not called`, `0xC0000409`). Compose при закрытии окна удаляет GL-контекст Skiko раньше `onDispose`, поэтому `onCloseRequest` сначала зовёт `MpvVideoOut.disposeAll()`.
- **Ограничения.** HDR на HDR-мониторе тональнокомпрессируется в SDR (окно Skiko 8-битное). Скорость кадров зависит от потока интерфейса: длинная перекомпоновка задерживает кадр.
- **Замер** (RTX 5070 Ti, Spider-Man 4K HDR, ~2 мин, против 2.3.5 с `vo=gpu`): процессор плеера 11→18 % одного ядра (медиана), видеокарта 2→3 %, 43→45 Вт — в пределах шума; `drop=0`, `vo-drop=0`.

## 5. Управление фокусом и горячие клавиши

Благодаря рендерингу mpv в единой сцене окна Skiko фокус ввода не теряется:
- Нет нативных AWT Canvas или дочерних оверлейных диалогов, перехватывающих системный фокус.
- В `Main.kt` обработка горячих клавиш централизована на уровне `Window(onPreviewKeyEvent = { ... })` и `KeyboardFocusManager`.

### Таблица горячих клавиш:
| Клавиша | Действие |
|---|---|
| `Space` / `K` | Пауза / Воспроизведение |
| `←` / `→` | Перемотка назад / вперед на 10 секунд |

## 6. Дизайн-система «Жидкое стекло» (Liquid Glass)

Интерфейс выполнен в монохромном стиле высокой читаемости:
- **100% Vector Canvas иконки (`PlayerIcons.kt`):** полный отказ от платформенных эмодзи и системных глифов (`🔊`, `⚙`, `♫`, `CC`, `⛶`, `⏭`), вызывавших разнобой масштабов и цветные артефакты в Windows 10/11. Все иконки нарисованы математическими путями в Compose Canvas.
- **Люминесцентное радиальное свечение:** мягкий ореол градиентом `Brush.radialGradient` вокруг интерактивных элементов при наведении (Hover $\alpha = 0.28$) и активации (Active $\alpha = 0.40$).
- **Интерактивная капсула звука (`VolumeGlassCapsule`):** компактная кнопка 42dp, при наведении мыши плавно разворачивающаяся в горизонтальный ползунок (или вертикальный оверлей при ширине окна $< 880\,\text{dp}$).
- **Монохромный таймлайн:** чистый белый цвет таймкода и белая подсветка точки скраббинга (полный отказ от паразитного янтарного оттенка).

## 7. Полноэкранный режим (Borderless Fullscreen) и Мини-плеер

1. **Win32 Borderless Fullscreen (`WindowMode.kt`):**
   - Отказ от стандартного Java AWT FSEM (`GraphicsDevice.setFullScreenWindow`), так как показ прозрачных дочерних окон DWM поверх FSEM приводил к сбросу полноэкранного режима.
   - Реализован нативный Borderless через Win32 `SetWindowLongW` и `SetWindowPos`.
   - **Защита DirectFlip:** окно сохраняет структуру оверлейного окна со срезанными рамками, а высота выставляется на 1 пиксель больше рабочей области экрана (`monH + 1`). Это физически блокирует переход менеджера окон Windows в режим Exclusive DirectFlip, исключая белый экран и артефакты Skiko.
   - Скрытие акцентных рамок Windows 11 через `TitleBar.setFullscreenDwm` (`DWMWA_BORDER_COLOR = DWMWA_COLOR_NONE`).
2. **Мини-плеер (PiP):**
   - Реализован через Win32 без участия Compose `WindowState` (чтобы избежать конфликта рекомпозиции и геометрии окна).
   - Плавная анимация уезда в правый нижний угол экрана за 320 мс в отдельном системном потоке `mini-fly` с флагом `SWP_ASYNCWINDOWPOS`.
   - Автоматическая подгонка пропорций окна под реальный формат фильма (`videoAspect`).
   - Ревью `WindowMode` (22.10, ветка `fix-review`): координаты из физических пикселей в AWT переводятся относительно своего монитора (`toAwt`: смещение внутри `rcMonitor` / масштаб + `graphicsConfiguration.bounds`), а не делением глобальной координаты — иначе на двух мониторах с разным масштабом мини-плеер вставал не туда. `setFullscreen(true)` из мини сначала выходит из мини (иначе оставались `isMini` и `HWND_TOPMOST`). Поток `mini-fly` помечен поколением `flyGen`: устаревший поток выходит, не трогая `miniAnimating`. `currentWindow` — `WeakReference`. Убран мёртвый код User32 (`EnableWindow`, `EnumChildWindows`), фокус ищет `is SkiaLayer`. На устройстве не проверено.

## 8. Звук и ночной режим (DRC)

- **Ночной звук (Dynamic Range Compressor):** выравнивание громкости ночного просмотра (приглушение взрывов, подъем тихих диалогов) через фильтр `compressor`.
- **Мягкий `reopen(time)`:** при переключении режима звука плеер делает снимок кадра в память (`grabFrame()`) и переоткрывает аудиопоток с текущей миллисекунды без разрушения окон Compose и без мерцания черным экраном.

## 9. Сборка и установщики

```powershell
# Запуск из исходников
./gradlew desktop:run

# Сборка релизного MSI установщика
./gradlew packageMsi
# Результат: desktop/build/compose/binaries/main/msi/Suslik Media-<V>.msi

# Сборка и локальная установка диагностической версии Suslik Debug
./install-desktop-debug.ps1
```

Установщик и окно удаления — `desktop/setup` (WPF, .NET Framework 4.7.2, одна программа):
- `Suslik Media Setup-<V>.exe` — единственный файл для людей и для обновлений (на сайт идёт он, MSI только внутри): шаги, выбор папки, тихая установка MSI с ходом в своём окне, проверка видеодвижка, запуск.
- Видеодвижок `libmpv-2.dll` не входит ни в установщик, ни в MSI. Установщик ищет его в `<папка>\app\resources` (метка `libmpv.version` = SHA-256); если его нет — качает с нашего сервера (путь `path` в `desktop/src/main/resources/libmpv.properties` — `/media/mpv/libmpv-2.dll` на сайте; домен вшивается при сборке из секрета `SITE_URL`; файл кладёт владелец) и сверяет SHA-256. Сервер недоступен — окно «Видеодвижок не скачан» с кнопкой «Повторить» (приложение при этом уже стоит).
- Приложение (`MpvInstall.kt`) докачивает libmpv туда же, если её всё-таки нет, и говорит об ошибке (диалог при запуске фильма без libmpv, «Настройки → Скачать mpv»).
- `SuslikUninstall.exe` — без MSI, лежит в `app/resources`. Регистрирует себя в «Установленных приложениях» (`/register`, вызывает и само приложение после самообновления, `Uninstaller.kt`), запись MSI прячется. «Удалить» открывает окно с галочкой «Удалить все сохранённые данные и кэш» (`%APPDATA%\SuslikMedia`, `%TEMP%\SuslikMedia-stream`, `%TEMP%\SuslikMedia-update`); видеодвижок из папки приложения удаляется всегда. `/uninstall /quiet` — без окна, данные остаются.
- Самообновление скачивает Setup.exe и запускает его с `/update`: сразу ход установки в ту же папку, затем снова запуск приложения (окно остаётся только при ошибке).
- `.github/workflows/setup-preview.yml` рисует окна установщика в PNG (`/preview <папка>`) — артефакт `setup-preview`.

Диагностическая сборка Suslik Debug собирается с ключом `-Pdiag`:
- Ставится рядом с релизной версией (свой `upgradeUuid`).
- Пишет подробный лог в `%APPDATA%\SuslikMediaDebug\player.log`.
- Поддерживает горячую клавишу `F8` для установки временной метки `[mark]` при воспроизведении.

## 10. Системные медиа-контролы Windows (SMTC)

`player/MediaControls.kt` — чистый JNA COM/WinRT (без сторонних библиотек): `RoGetActivationFactory` →
`ISystemMediaTransportControlsInterop::GetForWindow(HWND главного окна)`. Плеер виден в окне громкости Windows,
Media Flyout, ModernFlyouts; работают клавиши мультимедиа.

- **Что отдаём:** название (фильм или серия + сериал) в `VideoProperties` и `MusicProperties`, статус Playing/Paused
  (по настоящей паузе: `pausedAt > 0 || enginePaused`, буферизация — «играет»), полоса времени (`ISystemMediaTransportControls2`),
  доступность «следующая/предыдущая».
- **Кнопки:** `add_ButtonPressed` (Play и Pause — оба `togglePause()`: Flyout с одной кнопкой шлёт противоположное тому,
  что видел), Next/Previous — серии, перемотка по полосе — `add_PlaybackPositionChangeRequested`. Колбэки JNA держатся
  полями объекта (иначе GC — `0xc0000005` в `Windows.Media.MediaControl.dll`) и передаются в EDT через `invokeLater`.
- **Поток `smtc`:** весь COM — на отдельном STA-потоке, который сам качает сообщения (`PeekMessageW` +
  `MsgWaitForMultipleObjects` на событии, в простое не просыпается). На EDT (STA без насоса сообщений) оболочка ждала нас,
  и курсор замирал; в MTA постер до Flyout не доходил. Публичные методы только ставят задачу.
- **Подключение позже первого состояния:** окно-владелец может появиться после первых вызовов плеера, поэтому
  последнее состояние (`wantMeta`, `wantPlaying`, `wantCaps`) применяется в `attach`. Иначе на первом фильме пауза была серой.
- **Закрытие плеера:** `detach` — статус Stopped, `ClearAll`, `put_IsEnabled(false)` (в Flyout не остаётся пустой записи).
- **Постер:** `Library.posterFileFor(posterQueries)` берёт постер карточки с диска и уменьшает до 320 px (JPEG);
  без постера — кадр из видео раз на серию (через поток плеера). Картинка — `StorageFile.GetFileFromPathAsync` →
  `RandomAccessStreamReference.CreateFromFile` (запасной путь — поток `SHCreateStreamOnFileW` →
  `CreateRandomAccessStreamOverStream`; `CreateFromUri` с `file:///` вне Store не работает).
  `put_Thumbnail` — **только когда картинка сменилась**: повторная передача при каждом `Update()` (смена серии) подвешивала
  оболочку Windows, и курсор замирал на ~0,5 с.
- **Файлы:** `%APPDATA%\SuslikMedia\smtc\` — хранится только последняя картинка (`MediaControls.thumbFile`), входит в «Очистить кэш».
- **Журнал:** строки `[smtc]` (`attached`, `button event`, `poster`, `thumbnail … set`, `updateMetadataNow: Update() … ms`).
- Свой `AppUserModelID` не задаём: ярлыки jpackage его не несут, и закреплённый значок на панели задач раздваивался.

## 11. Предотвращение сна и гашения экрана (`DisplayAwake`)

При просмотре видео экран не должен гаснуть по таймеру неактивности, а ноутбук — уходить в спящий режим. Поскольку `vo=libmpv` рисует в окне Compose без собственного окна mpv, стандартный механизм плеера не работает.

Реализация в `player/DisplayAwake.kt`:
- **Power Requests API (Windows 7–11):** через `PowerCreateRequest` создаётся объект запроса с описанием `«Suslik Media: воспроизведение видео»`. При активном воспроизведении выставляются `PowerRequestDisplayRequired` (экран не гаснет) и `PowerRequestSystemRequired` (система не засыпает). Запрос виден в `powercfg /requests`.
- **`SetThreadExecutionState`:** на долгоживущем фоновом потоке `power-awake` выставляется `ES_CONTINUOUS | ES_DISPLAY_REQUIRED | ES_SYSTEM_REQUIRED`.
- **Периодический пульс (каждые 30 с):** периодический вызов `SetThreadExecutionState(ES_DISPLAY_REQUIRED | ES_SYSTEM_REQUIRED)` сбрасывает таймеры неактивности дисплея и системы, гарантируя защиту от сна даже при агрессивных профилях питания ноутбуков и в Windows Modern Standby (S0 Low Power Idle).
- **Управление состоянием:** флаг `isPlaybackActive = playing && !userPaused && !closing`. При паузе, окончании фильма или закрытии плеера запросы немедленно снимаются, позволяя системе засыпать штатно. При выходе из приложения вызывается `DisplayAwake.release()`.
- **Журнал:** строки `[power]` (`display awake: ON` / `OFF`).



## 12. Discord: вход, совместный просмотр, активность (2.5.0)

### 12.1. Вход
- Экран входа: «Войти через Discord» и запасной вход по паролю. Кнопка Discord запрашивает у сервера код связки
  (`POST /api/auth/device`), открывает в браузере `…/media/link?code=…` и раз в 2 с опрашивает `/api/auth/device/poll`.
- Подтвердили в браузере — приложение получает **токен устройства** (`Api.deviceToken`, `%APPDATA%\SuslikMedia\auth.properties`)
  и профиль. Токен уходит с каждым запросом заголовком `X-Device-Token`; «Выйти» отзывает его на сервере.
- Cookie, токен и бета-код отправляются только на свой сервер (`Api.request`): аватар с CDN Discord грузится без них.
- Профиль ставится **до** `authenticated = true`: смена флага закрывает экран входа вместе с корутиной, которая его вызвала.

### 12.2. Совместный просмотр (`party/`)
- Пункт «Совместный просмотр» в боковой панели → `TogetherView`: создать комнату, войти по коду, фильм комнаты, участники
  (кто создал, кто загружается). Фильм комнаты — ключ просмотра `magnetId|путь`, у всех общая медиатека.
- **Ведущий** (создатель) выбирает фильм: открытый им в медиатеке фильм становится фильмом комнаты (`Party.putFilm`),
  следующая серия — тоже. Пауза, продолжение и перемотка ведущего — у всех.
- **Участник**: «Библиотека» и «Избранное» закрыты, таймлайн — сплошная полоса «● Вместе» (как у стрима), нет «±10 с»,
  «Следующей», стрелок и глав. Своя пауза — только у себя; снял — плеер возвращает к месту ведущего.
  Пока ведущий держит паузу (или комната ждёт загрузку), кнопка воспроизведения серая, пробел не снимает паузу.
- `PartySync` (раз в 400 мс) вызывает общий `PartySyncEngine` (`shared/…/party/`, его же получит Android): новая команда
  комнаты — сразу; своё действие ведущего — в комнату (перемотка ловится по отметке `lastSeekAt` плеера, а не по скачку
  времени; пока нажатия ±10 с копятся 250 мс, часы mpv не трогают `time`, иначе перемотка терялась).
- Протокол и данные комнаты — общие (`PartyProtocol`, `PartyRoom`): состояние берётся только более новое по `seq`;
  пока сервер не подтвердил смену фильма (`pendingFileKey`), ответы со старым фильмом его не возвращают.
- **Ожидание загрузки.** Перемотка через сеть грузится секунды (видео и все озвучки). Плеер, который грузится
  (после перемотки; застрял > 1 с; время движка стоит 1 с без паузы, хотя mpv говорит «играю» — так бывает сразу после
  открытия), сообщает `buffering`; перемотка к комнате, пока та ждёт других, грузится без паузы (на паузе она засчитывалась
  за такт, и гость говорил «готов» раньше времени); комната ждёт — у остальных пауза на месте комнаты, все готовы —
  дальше вместе. Догонять комнату перемотками больше не пытаемся: это давало чёрный экран (перемотка → загрузка → отстал → перемотка).
- Небольшое расхождение (0,3–2 с) — скоростью 0,95/1,05×, больше 2 с — перемотка (`DriftController` в `shared/…/party`).
- Подсказки (`PartyNotice`): гостю — «Аня ставит паузу / продолжает / перематывает на 12:34 / включает «Серия»», всем —
  «Ждём, пока загрузится у …», если комната стоит дольше 2 с. Строкой плеера (`flash`), глаголы в настоящем времени.
- Смена серии: пока новая ждёт озвучки (до 4 с), mpv ещё играет прошлую — её время и «играю» не берутся (`switching`).
- Ведущий закрыл фильм — через 1,5 с комната на паузе. Часы сервера — `PartyClock` (замер с наименьшей задержкой).
- Журнал: строки `[party]` — `apply seq=…`, `local seek/pause`, `loading: the room waits`, `ready`, `seek done in … ms`, `drift seek`.

### 12.3. Активность в Discord (`DiscordRpc`)
- Локальный канал `\\.\pipe\discord-ipc-N`, без сторонних библиотек. «Смотрит» (тип 3; старый Discord — «Играет»),
  название, серия, полоса времени. Обновляется, когда фильм пошёл, на паузе, перемотке и смене серии.
- ID приложения Discord приходит от сервера (`discord_client_id` в `/api/session`) и запоминается; запасной — `-Dsuslik.discordClientId`
  при сборке (`DISCORD_CLIENT_ID`). Без ID ничего не показывается: Discord отвечает «Invalid Client ID».
- Картинки `brand-mark`, `play`, `pause` загружаются в Developer Portal (Rich Presence → Art Assets).
- Переключатель — в настройках. Ответы Discord читаются, отказ пишется в журнал (`[discord] …`).

## 13. Боковая панель, баннер и метки (24.10)

- **Боковая панель** (`Sidebar.kt`): «Главная», «Моя медиатека» (бывшие «Мои фильмы»), «Поиск раздач», «Magnet / торрент», «Совместный просмотр»; «КОЛЛЕКЦИЯ» — Фильмы, Сериалы, Аниме, Мультфильмы, Другое со счётчиками; «СЕРВИС» — «Настройки». Счётчики считаются по странице, на которой вы сейчас (на «Моей медиатеке» — только по своим). Категория запоминается отдельно для «Главной» и «Моей медиатеки» (`LibraryNav.category` / `mineCategory`); клик по разделу остаётся на текущей странице; повторный клик по «Главной»/«Моей медиатеке» на ней же сбрасывает на «Все». Чипы категорий со страницы библиотеки убраны.
- **Баннер «Продолжить просмотр»** (`ContinueRow` в `LibraryView.kt`): до 4 последних начатых фильмов, сменяются каждые 9 с (не под курсором; клик по постеру выбирает и перезапускает отсчёт). Широкий кадр, логотип, описание, год, рейтинг — `Library.hero()` (`/api/poster`: `backdrop`, `logo`, `overview`, `year`, `rating`); без них (старый сервер, нет сети) баннер тёмный, постером фон не подменяется (растянутый, он мутный). Не вмещающаяся часть широкого кадра не обрезается: она уходит за рамку баннера размытым «свечением» (размытие 22 dp, края тают маской, внутри рамки не рисуется — `clipPath`) на фон страницы. Кадр и свечение меняются одним `Crossfade` (350 мс); свечение — отдельный слой с размытием, поэтому его прозрачность считает собственный `updateTransition`. На время изменения ширины окна свечение отключается (его размытие пересчитывалось бы на каждом шаге) и возвращается через 0,2 с после последнего. `expandVertically`/`shrinkVertically` баннера без обрезки (`clip = false`), иначе свечение вне рамки возникало бы рывком. Картинки подгружаются при запуске (`warmContinue`), текст не заезжает под постеры в узком окне. Нет «Подробнее» и «⋯» — по решению владельца. Крестик на постере убирает фильм из списка.
- **Метки Dolby Vision / HDR / DTS** на постере (`itemTags`, `Library.tagsOf`): ответ сервера `/api/tags` (ffprobe по файлу, хранится до удаления раздачи), пока его нет — догадка по названию. `Library.refreshTags()` переспрашивает каждые 30 с, пока сервер разбирает остальные.
- **Страницы библиотеки** (`LibraryView.kt`, `PAGE_ROWS = 3`): страница — 3 ряда постеров (сколько влезает по ширине окна; в списке 12 строк), внизу «‹ 1 2 3 … ›» (`PageBar`); поиск, подборка, сортировка и «только готовые» возвращают на первую. Счётчик в заголовке показывает все найденные.
