Обновление: серверная часть, плейлист сезона, контракт с Android-приложением

Сервер (server.js)
- Ссылки файлов (/api/magnets/:id/files) больше не разблокируются все сразу: разблокировка — только по нажатию «Получить ссылки».
- /api/library: деревья файлов готовых magnet-ссылок кэшируются (память + library-files-cache.json). «Обновить» = один запрос magnet/status плюс файлы только новых magnet-ссылок. Одновременные обновления делят один запрос; при сбое AllDebrid отдаётся последний удачный результат (stale:true). Есть ETag.
- Плейлисты без хранения: POST /api/playlist {magnetId,title,items:[{index,link}]} → подписанный адрес /api/playlist/<id>/<название>.m3u?f=8.9&exp=…&sig=… ; .m3u строится при каждом запросе, переживает перезапуск. Если библиотека изменилась, сервер отвечает 409 и сайт просит обновить её.
- Сессии хранятся в sessions.json (вход не слетает при перезапуске). Папку для sessions.json и кэшей можно задать через DATA_DIR в .env.
- Новые файлы данных: sessions.json, library-files-cache.json (добавлены в .gitignore). При остановке сервера (SIGTERM/SIGINT) они дописываются на диск.

Сайт (index.html = public/index.html)
- Запуск серии в PotPlayer (ПК) и в Android-приложении: выбранная серия + все следующие до конца сезона.
- Явный контракт с приложением: если есть window.__suslikApp>=2, сайт сам вызывает nativePlay({url,title,playlist}); приложение ничего не ищет по тексту кнопок.
- Вкладка «Открыть ссылку»: у каждого файла кнопка «Получить ссылки» (ленивая), общая функция fileLinkActions с окном папки.

Обновлять сайт и приложение нужно вместе. Перезапустите: node server.js, на странице Ctrl+F5.
