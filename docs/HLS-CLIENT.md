# HLS на сайте — клиент (T5, T6)

Контракт — `docs/HLS.md` (§9 `direct_ok`, §10 блок `hls` в `variant-url`, §12 сайт). Здесь — как устроен плеер сайта и админка.

## T5. Плеер

### Файлы

| Файл | Что |
|---|---|
| `website/public/hls-player.js` | модуль плеера (ES2017, без сборщика, внешний скрипт — CSP пускает только `'self'` и хеши встроенных скриптов). В браузере — `window.SuslikHls`, в Node — `module.exports` (без DOM) |
| `website/public/index.html` | точка врезки: `<script src="hls-player.js" defer>` и одна строка в конце `psLoad()` — `SuslikHls.attach({sheet, file, magnet, mirrorUrl, live, api, watch})` |
| `website/public/vendor/hls.min.js` | hls.js (кладёт T4); грузится лениво, только когда нужен |
| `website/test/hls-player.test.js` | `pickSource` на фикстурах `docs/hls-fixtures/variant-url-*.json`, сдвиг позиции, `direct` → MIME, разбор `master-v1.m3u8`, выбор дорожек, реакция на ошибки hls.js; подписи и выбор качества, `hlsConfig`, состояние `playerState` для `mount` |
| `website/scripts/check.js` | проверка синтаксиса `hls-player.js` в `npm run check` |

CSP не меняется: `pageCsp()` (`src/services/precompressed.js`) считает хеши встроенных скриптов из файла сам, у `<script src>` хеша нет.
Адрес CDN в `connect-src`/`media-src` и `worker-src 'self' blob:` (для воркера hls.js) добавляет T4.

### Как работает

1. Окно фильма (`openPlaySheet` → `psLoad`) как раньше подписывает зеркало (`GET /api/file/mirror-url`) и готовит кнопку «Смотреть» (PotPlayer, VLC, приложение Android). Это не меняется.
2. Затем `attach()`:
   - запущено в приложении Android (`nativeApp()`: `window.__suslikApp >= 2` и `SuslikNative`) — ничего не делает, приложение играет само;
   - у окна нет раздачи (файл из поиска без `magnet`) — ничего не делает;
   - иначе `POST /api/file/variant-url {ad_id, path}`. Ошибка или в ответе нет блока `hls` (HLS выключен, пользователь не в бете) — всё как раньше.
3. `pickSource(resp, caps)` — чистая функция:

| Ответ | Браузер | Что видно |
|---|---|---|
| нет `hls` | любой | как раньше (`legacy`) |
| `ready` | HEVC через MediaSource (`isTypeSupported('video/mp4; codecs="hvc1.1.6.L120.90"')`) | «▶ Смотреть в браузере», hls.js |
| `ready` | Safari: `canPlayType('application/vnd.apple.mpegurl')` и `canPlayType` hvc1 | «▶ Смотреть в браузере», нативный HLS |
| `ready`, `v1-copy`, `direct.vcodec = h264` | H.264 через MediaSource или нативно | HLS (копия видео H.264, `docs/HLS.md` §5) |
| `ready`, без HEVC | `direct_ok` и `canPlayType` по `direct` | зеркало (прямой файл) |
| `ready`, без HEVC | прямой файл не играет | «Этот браузер не показывает такое видео» + «Открыть в приложении» |
| `encoding` / `none` | `direct_ok` и `canPlayType` | зеркало; HLS включится позже (см. ниже) |
| `encoding` | прямой файл не играет | «Готовим для браузера, примерно N мин» (`eta`) + «Открыть в приложении» |
| `none` | прямой файл не играет | «Скоро будет готово для браузера» + «Открыть в приложении» |
| `restoring` | `direct_ok` и `canPlayType` | зеркало; HLS включится, когда версию вернут из архива (как при `encoding`) |
| `restoring` | прямой файл не играет | «Достаём из архива, примерно N мин» (`eta`) + «Открыть в приложении» |

   `direct` → MIME (`directMime`): `mp4`/`m4v` → `video/mp4`, `webm` → `video/webm`; `h264` → `avc1.640028`, `hevc` → `hvc1.1.6.L120.90`, `vp9`, `av1`;
   звук `aac` → `mp4a.40.2`, «плохой» звук тоже пишется в codecs (`ac-3`, `ec-3`, `dtsc`, `mlpa`), чтобы `canPlayType` честно ответил «нет». `mkv`/`avi`/`ts` → прямого просмотра нет.
   «Открыть в приложении» нажимает ту же ссылку, что «Смотреть» (приложение Android, PotPlayer, VLC). Пока окно открыто и статус `encoding`/`restoring`/`none`, статус переспрашивается раз в минуту.
4. Плеер — полноэкранный слой поверх окна фильма: `<video controls>`, «Закрыть» (и Esc), меню «Качество» (ниже), выбор озвучки и субтитров из `master.m3u8` (hls.js: `audioTracks`/`subtitleTracks`; Safari и зеркало — `video.audioTracks`/`textTracks`). По умолчанию — дорожка с `DEFAULT=YES`, субтитры выключены; выбор сохраняется при переключении источника (по имени, потом по языку).
5. Ошибки hls.js (`hlsErrorAction`): сеть — до 3 повторов `startLoad()`, потом новая подпись (`variant-url`) и перезапуск с того же места, потом откат; медиа — `recoverMediaError()`, затем `swapAudioCodec()` + `recoverMediaError()`, потом откат; прочее — откат. Откат — на зеркало, если `direct_ok` и браузер его играет, иначе сообщение и «Открыть в приложении». hls.js не загрузился (`vendor/hls.min.js` нет) — нативный HLS, если есть, иначе откат.
6. HLS стал готов во время просмотра зеркала: раз в 90 с переспрашивается `variant-url`; когда `ready` — надпись «Версия для браузера готова — включим, когда поставите на паузу», переключение **на паузе** (не на лету), а также при следующем запуске и на следующей серии (окно фильма заново спрашивает `variant-url`).
7. Позиции: время HLS = время файла + `shift_ms` (`toHlsMs`/`toFileMs`). Старт — с места «здесь вы остановились» (`/api/sync`, как карточка в окне фильма).
   Сохранение — `POST /api/sync {watch:[{key:"<id раздачи>|<путь>", pos, len, at}]}` во времени файла: раз в 30 с при просмотре, на паузе, в конце, при закрытии и уходе со страницы (`keepalive`).
   Сервер принимает только вход через Discord; на 403 (общий пароль) больше не шлём.

### Качество

Перемотка, громкость и полноэкранный режим — у браузера (`video.controls`); качество, озвучка и субтитры — свои выпадающие списки под видео (цвета и шрифт — переменные `redesign.css`, на телефоне списки делят строку поровну).

- Меню «Качество»: «Авто (сейчас 1080p)» и уровни `hls.levels` от лучшего к худшему. Подпись (`levelLabel`) — ближайший стандарт по ширине **или** высоте (≥ 85 %): кадр обычно обрезан — 1920×800 и 1040 → 1080p, 1280×534 и 694 → 720p, 2160 → 4K, 576 → 480p. Одинаковые подписи различает битрейт («1080p · 8 Мбит»).
- Выбор уровня — `hls.currentLevel = i`: сразу, hls.js сбрасывает буфер вперёд и грузит ближайший сегмент нового качества. «Авто» — `hls.loadLevel = -1` (без сброса, ABR со следующего сегмента). «сейчас …» обновляется по `LEVEL_SWITCHED`.
- Выбор запоминается в `localStorage["suslik.hls.quality"]` (`"auto"` или подпись, например `"720p"`; ошибки хранилища глотаются) и применяется при следующем запуске: hls.js стартует с `autoStartLoad: false`, после `MANIFEST_PARSED` ставится `startLevel`/`loadLevel` нужного уровня (`startLevelFor`: по подписи, из одинаковых — с большим битрейтом; такого уровня нет — авто), затем `startLoad()`.
- Меню нет (`showQualityMenu`): Safari и нативный HLS (уровни выбирает браузер), зеркало, профиль `v1-copy` (один уровень).
- `capLevelToPlayerSize` убран: плеер на странице уже 1920 пикселей, и hls.js держал 720p даже на хорошем канале («качество не переключается»); файлы лёгкие (v1: 1080p ≤ 5 Мбит), «Авто» решает по скорости канала.

Буфер (`hlsConfig`):

| Параметр | Значение | Почему |
|---|---|---|
| `backBufferLength` | 90 с | короткая перемотка назад без повторной загрузки; по умолчанию у hls.js — всё (`Infinity`), на длинном фильме это упирается в квоту MediaSource (~150 МБ видео в Chrome). 90 с при 5 Мбит ≈ 56 МБ |
| `maxBufferLength` / `maxMaxBufferLength` | 30 / 120 с | вперёд 30 с, на быстром канале до 120 с (по умолчанию 600): переживаем провал скорости, вместе с буфером назад остаёмся в квоте, не качаем то, что при перемотке выбросим |
| `abrEwmaDefaultEstimate` | 5 Мбит | первая оценка канала (по умолчанию 0,5 Мбит — старт с худшего). ABR сравнивает с `AVERAGE-BANDWIDTH` × 0,95: у 1080p v1 ≈ 3,6 Мбит — на нормальном канале сразу 1080p, на слабом первый сегмент даст настоящую оценку |
| `startLevel` | −1 | авто по оценке канала, а не «первый уровень из манифеста» |

### Встраиваемый режим (страница фильма)

`SuslikHls.mount(container, opts) → controller` — плеер 16:9 **внутри** `container` (без слоя на весь экран; полноэкранный режим — кнопкой браузера). Выбор источника тот же (`pickSource`): HLS, зеркало при `direct_ok`, экраны «Готовим для браузера, примерно N мин» / «Достаём из архива…» / «Этот браузер не показывает такое видео» (опрос `variant-url` раз в минуту, готово — запуск), переход зеркало → HLS на паузе, сохранение позиции в `/api/sync`. Код общий с оверлеем (`createPlayer`/`loadFile`).

```
opts: { adId, path, title?, startAt? (сек, позиция файла), autoplay? (bool),
        api? (path, opts) → Promise<JSON>  // по умолчанию fetch с credentials:'same-origin' и JSON, адрес — от места hls-player.js
        controls? (true — свои списки качества/озвучки/субтитров под видео; иначе страница рисует их по onState),
        onState?(state), onEnded?(), onTime?(sec — время файла),
        onOpenApp?()  // дополнительно: если задан, на экранах «Готовим…»/ошибки есть кнопка «Открыть в приложении» }
state: { kind: "hls"|"mirror"|"preparing"|"unsupported"|"error", message?, etaMin?,
         levels?: [{index, height, label}]   // пусто — меню качества не показывать (Safari, зеркало, один уровень)
         level?: number (-1 авто), audio?: [{index, name, lang}], audioIndex?, subtitles?: [{index, name, lang}], subtitleIndex? (-1 выкл.),
         levelNow?, qualityLabel? }          // дополнительно: что играет сейчас и готовая подпись («Авто (сейчас 1080p)»)
controller: { load(adId, path, startAt?), setQuality(index | -1), setAudio(index), setSubtitle(index | -1),
              play(), pause(), currentTime() → сек файла (с учётом shift_ms), destroy() }
```

- `onState` зовётся только при изменении состояния (сравнение JSON). Состояние строит чистая функция `playerState` (тесты).
- `load()` сохраняет позицию старого файла и открывает новый в том же элементе (серия, версия); выбор озвучки/субтитров переносится по имени и языку.
- `play()` до готовности запоминает желание и запускает, когда файл станет готов; `pause()` — наоборот.
- Ответ без блока `hls` (HLS выключен, не в бете) → `unsupported` «Просмотр в браузере пока недоступен»; ошибка `variant-url` → `error`.
- В приложении Android (`SuslikNative`) `mount` не отключается (в отличие от `attach`) — решает страница.

### Проверено

- `node --test website/test/*.test.js`, `npm run check`.
- Chrome 64-бит без окна (headless, Windows, без GPU, страница-стенд с фикстурами вместо сервера): `ready` без HEVC → «Этот браузер не показывает такое видео»;
  с подменой `isTypeSupported` под HEVC → «Смотреть в браузере», без `vendor/hls.min.js` → «Не удалось запустить плеер. Откройте в приложении.»; `encoding` → «Готовим для браузера, примерно 14 мин»;
  `none` → «Скоро будет готово…»; `mp4-direct` → «Смотреть в браузере», битый файл → сообщение; без блока `hls` — панели нет; в приложении (`__suslikApp`, `SuslikNative`) — панели нет.
- Архив (§17): `pickSource` на фикстуре `variant-url-restoring.json` (`wait` с `restoring: true`, «Достаём из архива, примерно 3 мин»; с `direct_ok` — зеркало с `upgrade`).
  В браузере не проверено.
- Меню качества и `mount` (19.11): Chrome без окна, стенд с настоящим HLS из ffmpeg (H.264, 1920×800 и 1280×534, fMP4, профиль `v1-copy` в ответе, чтобы шло через hls.js),
  поддельный API под префиксом (`/public/api/…` — проверка адреса по умолчанию): меню «Авто (сейчас 1080p) / 1080p / 720p», выбор 720p — `videoHeight` 534 через ~4 с,
  «Авто (сейчас 720p)», после перезагрузки страницы стартует с запомненного 720p; старт с `startAt` 10 с; `load()` на одноуровневый — меню нет; `load()` на mp4 — `mirror`;
  `destroy()` очищает контейнер; `encoding` — экран «Готовим для браузера, примерно 14 мин» с кнопкой (`onOpenApp`); ширина 375 пикселей — без горизонтальной прокрутки;
  оверлей из листа (`attach`) — играет с места «здесь вы остановились», меню качества, Esc закрывает; `/api/sync` получает позиции старого файла при `load()` и при уходе со страницы.
  Переход «готовим → готово» по таймеру (60 с) в браузере не ждали.
- **Не проверено:** настоящий сайт с сервером T4, настоящее видео HLS и hls.js, Safari, Firefox, Chrome с аппаратным HEVC, переключение на паузе, сохранение в `/api/sync`.

### Ручной сценарий

Нужно: сервер с T4, `HLS_ENABLED`, пользователь в бете (`HLS_BETA_USERS`), вход через Discord (иначе позиция не сохраняется), раздачи: (А) MKV HEVC с готовым ассетом, (Б) MKV в кодировании, (В) MP4 H.264+AAC без ассета, (Г) раздача без ассета и не MP4.

Chrome (Windows с аппаратным HEVC):
1. (А) «Смотреть» → в окне есть «▶ Смотреть в браузере». В DevTools → Network: `POST variant-url`, `master.m3u8`, `index.m3u8` и `.m4s` с CDN, ошибок CSP в Console нет.
2. Переключить озвучку и субтитры, перемотать, поставить на паузу, закрыть. Открыть окно снова — «С ЧЧ:ММ» совпадает с местом закрытия (после минуты кэша `loadWatch`). Тот же фильм в приложении на ПК/Android начинает с этого места.
3. В DevTools заблокировать запросы к CDN во время просмотра — после повторов воспроизведение остановится с сообщением (у (А) `direct_ok = false`) или перейдёт на прямой файл (если `direct_ok`).
4. (Б) — «Готовим для браузера, примерно N мин» и «Открыть в приложении» (открывает PotPlayer); (Г) — «Скоро будет готово для браузера».
5. (В) — «Смотреть в браузере» играет зеркало (`/api/file/proxy/…`). Дождаться, пока ассет станет `ready`, поставить на паузу — источник меняется на HLS с того же места (с алиасом — с поправкой `shift_ms`).
6. Сериал: досмотреть серию с зеркала, пока следующая готова в HLS, — следующая серия открывается в HLS.

Safari (macOS/iOS):
7. (А) — играет нативно (в Network нет `hls.min.js`), выбор озвучки и субтитров работает, на iPhone — полноэкранный режим системы.

Firefox (без HEVC) — заглушка:
8. (А) — «Этот браузер не показывает такое видео» и «Открыть в приложении»; (В) — прямой файл; (Б) — «Готовим для браузера…».

Приложение Android (WebView с `SuslikNative`):
9. Окно фильма без новой панели, «Смотреть» открывает плеер приложения, как раньше.

## T6. Админка

Страница `website/public/hls-admin.html` (адрес `<сайт>/hls-admin.html`) и скрипт `website/public/hls-admin.js`. Только для администратора медиатеки
(`isLibraryAdmin`: Discord-пользователь с ролью admin). Ссылки на страницу с сайта нет — открывать по адресу.

### Как отдаётся

- Статика: `express.static`. Для всех `.html` он ставит `Cache-Control: no-cache` и CSP страницы `index.html` (`pageCsp`):
  `script-src 'self'` + хеши встроенных скриптов `index.html`, `style-src 'self' 'unsafe-inline'`, `frame-ancestors 'none'`.
  Поэтому в `hls-admin.html` нет встроенных скриптов и обработчиков `on…=` — весь код во внешнем `hls-admin.js`; стили — в `<style>` (разрешено).
- Сама страница статическая и прав не проверяет: данные отдаёт только API (`requireLogin` + `isLibraryAdmin`).
- Адреса запросов относительные (`api/hls/admin/...`), поэтому страница работает и когда сайт не в корне (`SITE_URL` с путём).

### Что показывает

Данные — `GET api/hls/admin/state` (`docs/HLS-SERVER.md`, «Админка (для T6)»). Обновление раз в 10 с; пока вкладка скрыта — пауза,
при возврате — сразу обновляется. Кнопка «Обновить» — вручную. Если обновить не удалось — сообщение, прежние данные остаются.

| Блок | Что |
|---|---|
| Состояние | включён ли HLS (`enabled`); что не задано в `.env` (`configured` → имена переменных); сводка `totals` |
| Место на CDN | `cdn`: занято / всего, %, полоса (красная от 90 %), сколько видео и версий, когда пришло (`received_at`). `null` → «CDN ещё не присылал данных» |
| Очередь | в порядке выдачи воркеру: файл, раздача, состояние, приоритет словами (0 «Смотрят сейчас» … 4 «Улучшение качества»), профиль, метка «перекодирование» (`force`); у кодируемого — стадия, %, сколько осталось, полоса; размер, попытки, когда поставлено, ошибка со стадией |
| Готовые и кодируемые | ассеты (свежие сверху): файл-источник, `hls_id`, длительность, серия, монтаж, размер, когда смотрели, какой профиль играет (`active_profile`); профили со статусом, размером, кодировщиком; профили из `pending_delete` — «ждёт удаления на CDN» (у архивных — «…и в архиве»); источник и алиасы (со сдвигом) |
| Архив (§17) | в сводке — «в архиве» (версий с копией), «в архиве занимают», «только в архиве» (`cold` + `restoring`), показываются, когда есть; у профиля — статус «в архиве» / «достаём из архива» (сколько осталось, ошибка возврата), у готовой — метка «есть в архиве»; размер `cold` — по `archive_bytes` |

### Действия

| Кнопка | Где | Запрос |
|---|---|---|
| «Повторить» | задание в состоянии `failed` | `POST api/hls/admin/retry {job_id}` |
| «Перекодировать с этой раздачи» | у источника и каждого алиаса ассета, с подтверждением | `POST api/hls/admin/reencode {ad_id, path, hls_id}` (`hls_id` — этот ассет: после кодирования его алиасы переходят на новый) |
| «Удалить» | у профиля (кроме уже ждущих удаления), с подтверждением | `POST api/hls/admin/delete {hls_id, profile}` |
| «Достать из архива» | у профиля «в архиве»; у «достаём из архива» — неактивная «Уже достаём» | `POST api/hls/admin/restore {hls_id, profile}` |
| «Удалить всё» / «Удалить запись» | у ассета, где больше одной живой версии / нет версий | `POST api/hls/admin/delete {hls_id}` |

После удаления профиль помечен «ждёт удаления на CDN»; запись исчезает, когда CDN пришлёт `evicted`. После действия — короткое сообщение и обновление.

POST идут с cookie сайта (`credentials: "same-origin"`); браузер сам шлёт `Sec-Fetch-Site: same-origin`, и `sameOriginWrites` их пропускает.

### Ошибки

`errorText(status, body)` в `hls-admin.js`:

| Ответ | Текст |
|---|---|
| нет связи | «Нет связи с сервером.» |
| 401 | вместо данных — «войдите через Discord как администратор» и ссылка `api/auth/discord/start?return=<эта страница>`; автообновление останавливается |
| 403 `forbidden` | «Нет доступа: страница только для администратора медиатеки.» (без ссылки) |
| 409 `not_cold` | «Этой версии нет в архиве.» |
| 409 `busy` | «Задание сейчас в работе. Попробуйте позже.» |
| 404 `unknown_job` / `unknown_asset` / `unknown_profile` / `unknown_file` | «Задания уже нет.» / «Запись уже удалена.» / «Этой версии уже нет.» / «Файла больше нет в раздаче.» |
| 503 / `not_configured` | «HLS на сервере не настроен.» |
| 429 | «Слишком много запросов. Подождите минуту.» |
| 5xx | «Ошибка сервера. Попробуйте позже.» |
| прочее | `error` из ответа |

### Код

`hls-admin.js` — одна обёртка без сборщика. Чистые функции (`formatBytes`, `formatEta`, `formatDuration`, `formatAgo`, `percent`, `progressPercent`,
`fileName`, `stateText`, `stageText`, `priorityText`, `profileStatusText`, `errorText`, `missingConfig`) в Node экспортируются через `module.exports`
и DOM не трогают. Разметка строится через `textContent` (названия файлов не попадают в HTML). Файл проверяется `npm run check`
(вместе с `hls-admin.html`: `lang="ru"`, встроенных скриптов нет).

### Тесты

`website/test/hls-admin.test.js`: права на все четыре маршрута (без входа 401, не админ 403 `forbidden`, админ пускает), отказ POST с cookie
с чужого сайта, retry (`failed` → `queued`, в аренде → 409 `busy`), reencode (приоритет 0, `force`, в `state.queue`; нет файла → 404 `unknown_file`),
delete → `pending_delete` → `pending-deletes` → `evicted` → записи нет (повтор → 404), `cdn-stats` в `state.cdn`, страница со CSP без встроенных скриптов
и обработчиков, чистые функции `hls-admin.js` (в т.ч. статусы архива и `not_cold`). Сервер архива и `admin/restore` — `website/test/hls-archive.test.js`.

(без горизонтальной прокрутки), без ошибок в консоли; 401 — ссылка на вход; «Повторить», «Удалить», «Перекодировать» работают и показывают сообщение.

## Страница фильма

У каждой готовой раздачи медиатеки своя страница с плеером: сведения о фильме, выбор озвучки, субтитров, качества,
версии, сезона и серии, плеер 16:9 под ними. Оформление — токены и шрифты сайта (`redesign.css`), тёмная тема,
на телефоне одна колонка.

### Адреса

| Адрес | Что |
|---|---|
| `<база>/media/watch/<id>` | страница раздачи `<id>` (номер AllDebrid, только цифры); локально без nginx — `/watch/<id>` |
| `?s=<сезон>&e=<серия>` | серия сериала (если номер в сезоне повторяется — `?f=`) |
| `?f=<путь файла>` | файл раздачи по пути (так ведёт ссылка «Страница фильма →» из окна фильма в медиатеке) |
| `&t=<сек>` | позиция при открытии; сама страница её в адрес не пишет (место сохраняет плеер через `/api/sync`) |
| `/watch/<id>/<что угодно>` | относительный редирект 302 на `../<id>` с той же строкой запроса |
| `/watch/abc` | та же страница с кодом 404, она пишет «Не найдено» и ведёт в медиатеку |

Без параметров сериал открывается с серии, где остановились (по `/api/sync`, иначе последняя открытая в этом браузере —
`localStorage.lastEpisodeV1`, иначе первая), и адрес сразу получает `?s=&e=` (`history.replaceState`) — ссылку можно
копировать (кнопка «Скопировать ссылку»).

### Устройство

- **Сервер** (`src/app.js`): `GET /^\/watch\/([^/]+)(\/.*)?$/` → `sendPrecompressed(..., "watch.html")` — свой CSP по
  `pageCsp` (встроенных скриптов нет, `script-src 'self'`), gzip/brotli, ETag. Файлы страница берёт относительными
  путями `../watch.js`, `../watch.css`, `../library-model.js`, `../hls-player.js` — сайт может стоять под путём
  (`/media/`, `docs/MIGRATION.md`), поэтому `<base>` (запрещён CSP `base-uri 'none'`) и абсолютные пути не годятся.
- **`public/library-model.js`** — модель медиатеки (`window.SuslikLibrary`, в Node — `module.exports`): `parseEpisode`,
  `seasonOf`, `nameSeason`, `buildPlaylist` (фильм / сериал `{type, seasons:[{season, items}]}` / сборник),
  `numberedEpisodesOf`, `groupLibraryVersions`, `tileTitle`, `getItemTags` и соседи. Код **скопирован из index.html
  слово в слово**; `index.html` на модуль ещё не переведён (отдельный шаг). Тест `library-model.test.js` сравнивает
  тексты функций в обоих файлах: правило поменяли в одном месте — тест падает. Постеры для слияния версий страница
  берёт из того же `localStorage.posterCacheV2`, что и медиатека (`setPosterDb`), метки сервера — из `/api/tags`.
- **`public/watch.js`** — страница. Порядок: `/api/session` (не вошли — «Нужно войти»: вход через Discord с
  `return` на эту страницу, вход по паролю — ссылка на главную), `/api/library` (нет раздачи или не готова — «Не найдено»),
  затем параллельно `/api/title/<id>`, `/api/tags`, `/api/sync?since=0` (до 3 с, вход по паролю — без прогресса).
- **Плеер**: `SuslikHls.mount(#wpScreen, {adId, path, title, startAt, autoplay, api, controls:false, onState, onEnded,
  onTime, onOpenApp})`. Озвучку, субтитры и качество страница рисует сама по `onState` (озвучка — кнопками, одна дорожка —
  блок скрыт; качество — «Авто (сейчас …)» из `qualityLabel`/`levelNow`, уровней меньше двух — скрыто). Экраны «Готовим…»,
  «не показывает», ошибки и кнопку «Открыть в приложении» рисует плеер, кнопка вызывает `onOpenApp` → подписанный адрес
  зеркала (`/api/file/mirror-url`) → `playerHref` (PotPlayer / VLC / intent Android, как кнопка «Смотреть»).
  Смена серии — `controller.load(...)` без перезагрузки + `history.pushState`; «Назад» браузера — `popstate`.
  Конец серии (`onEnded`) — плашка «Дальше: N серия через 5 с» с «Сейчас» и «Отмена».
- **Без `SuslikHls.mount`** (старый `hls-player.js`) и в приложении Android (`__suslikApp >= 2`) — карточка «Плеер
  обновляется» с кнопкой «▶ Смотреть» (внешний плеер по зеркалу) и, если есть, «Смотреть в браузере» старого `attach`.
- **Сведения о фильме** — `GET /api/title/:adId` (`src/routes/title.js`, `src/services/tmdb-details.js`; вход, лимит как
  у `/api/poster`). Фильм ищется как постер: принятое название ИИ «Original» + год (результат того же года ±1), иначе
  название раздачи без пометок релиза; подсказка тип — сериал/фильм по файлам или по ответу ИИ. Подробности —
  `/{movie|tv}/{id}?language=ru-RU&append_to_response=credits,release_dates|credits,content_ratings`.
  Ответ: `{found, tmdb_id, type, title, original_title, tagline, overview, release_date, year, countries[], directors[]
  (сериал — created_by), genres[], runtime_min (сериал — средняя серия), age (RU «16+», иначе US «PG-13»/«TV-MA»),
  rating, votes, cast[] (до 10), cast_more, seasons, poster (/api/poster/img/w500/…)}`. Рейтинг — TMDB (IMDb в TMDB нет).
  Кэш — `DATA_DIR/tmdb-details.json`: найденное 30 дней, «не нашлось» сутки; сбой сети не запоминается (502).
  Без `TMDB_API_KEY` — `{found:false}`; страница тогда берёт описание, год и рейтинг из `/api/poster?hero=1` и показывает
  наше: название, постер, качество, размер.
- **Ссылка из медиатеки**: в окне фильма (`index.html`, `ensurePlaySheet`/`psLoad`) строка «Страница фильма →»
  (`watch/<id>?f=<путь>`), в приложении Android скрыта.

### Ручной сценарий

1. Войти на сайте, открыть фильм из медиатеки → «Страница фильма →». Адрес `…/media/watch/<id>?f=…`, вкладка — название.
2. Шапка: название, оригинал серым; карточка: постер, таблица (рейтинг TMDB, слоган, дата, страна, режиссёр, жанр,
   «В качестве», возраст, время, актёры, размер); пустых строк нет. Ниже «Про что фильм «…»:».
3. Фильм с несколькими релизами: «Версия:» — кнопки, переход на `/watch/<другой id>`.
4. Сериал: вкладки сезонов, сетка серий (✓ — досмотрено, % и полоска — начато). Клик по серии — плеер меняет файл без
   перезагрузки, адрес `?s=&e=`; «Назад» браузера возвращает прошлую серию.
5. Озвучка (если дорожек больше одной), субтитры, качество — переключаются на ходу.
6. Досмотреть серию до конца → «Дальше: … через 5 с»; «Отмена» оставляет текущую.
7. Файл ещё кодируется → «Готовим для браузера, примерно N мин» и «Открыть в приложении» (PotPlayer/VLC/Android).
8. `/media/watch/1` (нет такой) → «Не найдено» и «Открыть медиатеку»; выйти и открыть страницу → «Нужно войти»,
   вход через Discord возвращает на неё же.
9. Телефон (390 px): одна колонка, озвучки в 2 столбца, без горизонтальной прокрутки.
