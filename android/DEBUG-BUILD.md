# Отладочная сборка «Suslik Debug»

Отдельное приложение для поиска того, что оптимизировать. Код тот же, что у обычного, но сборка пишет подробный журнал.
У неё свой пакет `ru.suslikovanora.media.diag`, поэтому:

- она ставится **рядом** с обычной и ничего в ней не трогает;
- у неё свой вход, свои настройки и своя история;
- сама она не обновляется, новую версию ставят с компьютера.

Собирается оптимизированно, как релиз, чтобы цифры были честными. Имена классов в ней читаемые. Её можно профилировать из
Android Studio или Perfetto (`profileable`). На сайт она не публикуется.

## Где взять

GitHub → Actions → «Android APK» → последний зелёный запуск → артефакт **android-debug-apk**
(`suslik-debug-<версия>-b<код>.apk` внутри zip).

## Установка и разрешения (с компьютера, adb)

```sh
adb install -r suslik-debug-*.apk
P=ru.suslikovanora.media.diag

# Системный журнал (предупреждения сети, радио и питания всей системы) → system.log
adb shell pm grant $P android.permission.READ_LOGS
# Статистика батареи приложения (время активного радио, wakelock, CPU) → batterystats-*.txt
adb shell pm grant $P android.permission.DUMP
# Поколение мобильной сети (LTE / 5G / 3G) в строках [sys]
adb shell pm grant $P android.permission.READ_PHONE_STATE
```

После выдачи разрешений перезапустите приложение: `adb shell am force-stop $P`. Что выдано, видно в
«Настройки → Отладочная сборка».

## Как проводить опыт

```sh
adb shell dumpsys batterystats --reset   # обнулить счётчики батареи перед опытом
# … смотрите фильм как обычно; в момент проблемы нажмите 📍 в плеере (метка в журнале) …
adb pull /sdcard/Android/data/ru.suslikovanora.media.diag/files/diag
```

Снимок батареи из приложения на новых Samsung (Android 17) отвечает «нужно PACKAGE_USAGE_STATS». Тогда выдайте
`adb shell appops set $P GET_USAGE_STATS allow` или снимайте с компьютера после опыта:
`adb shell dumpsys batterystats ru.suslikovanora.media.diag > batterystats.txt`.

Без компьютера: «Настройки → Поделиться» (zip всех файлов) или «Отправить журнал» (хвост журнала на сервер, kind = diag-journal).

## Файлы

| Файл | Что в нём |
|---|---|
| `player.log` (+ `.old.log`) | Единая лента событий, до 2×20 МБ. Помимо обычных строк журнала плеера в ней есть строки ниже. |
| `logcat.log` | Android-журнал самого приложения: VLC (при «Журнал VLC: Подробный» это `-vv`) и StrictMode (диск или сеть в главном потоке, утечки). |
| `system.log` | Предупреждения всей системы (только с READ_LOGS). |
| `batterystats-*.txt` | `dumpsys batterystats` приложения. Пишется при закрытии фильма и по кнопке «Батарея». |

Строки в `player.log`:

- `[sys]` — каждые 5 с, пока открыт фильм или приложение на экране, иначе раз в минуту:
  - заряд, температура, ток (мА, минус — разряд);
  - сеть: тип, поколение, сигнал, лимитная или нет, оценка канала;
  - трафик приложения и часть его через запас;
  - CPU за интервал и самые занятые потоки;
  - память;
  - экран, энергосбережение, doze, перегрев, Data Saver.
- `[ui]` — кадры интерфейса: сколько отрисовано, сколько медленных (>17 мс) и зависших (>700 мс), худший кадр.
- `[vlc]` — каждые 5 с, даже при выключенном экране:
  - позиция, состояние, скорость чтения;
  - показанные и потерянные кадры, декодированные кадры, звук;
  - ошибки демуксера.
- `[engine]` — какой движок открыл файл и почему (настройка, контейнер, память для файла); переход Media3 → VLC с причиной.
- `[media3]` — то же, что `[vlc]`, когда играет Media3, плюс: дорожки файла (с пометкой `(no)`, если декодера нет), имена
  декодеров видео и звука, состояние FFmpeg, ошибки, загружено вперёд в память (с), оценка сети, через запас или напрямую; запас — в `[proxy]`, как у VLC.
- `[proxy]` — состояние запаса по каждому окну:
  - сколько впереди, пороги low/high;
  - фаза probe/ramp/full;
  - качает или отдыхает;
  - сколько читателей, сколько секунд никто не читал.
- `[http]` — каждый запрос: новое или переиспользованное соединение, DNS/TCP/TLS, время до первого байта. Только путь, без параметров (подписи и ссылки в журнал не попадают).
- `[net]` — переключения сети, как их видит Android (available / LOST / validated / blocked).
- `[event]` — экран вкл/выкл, зарядка, энергосбережение, doze, показ и скрытие экранов, нехватка памяти.
- `[battery]` — ключевые строки снимка batterystats.
- `[diag]` — старт процесса и причины, по которым завершались прошлые процессы (Android 11+): убит системой, сбой, память.
- `[mark]` — ваши метки (📍 в плеере, «Метка» в настройках).

В обычном приложении всего этого нет: `BuildConfig.DIAG` там равен `false`, и R8 вырезает код.
