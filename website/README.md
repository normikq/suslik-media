# Suslik Media — частный медиапортал AllDebrid

Минималистичный портал на Node.js/Express. Все запросы к API AllDebrid выполняются на сервере. Ссылки воспроизведения передаются авторизованному браузеру для использования в локальном плеере; при прямом воспроизведении хост потока может видеть IP-адрес зрителя.

## Локальная установка (Windows PowerShell)

1. При необходимости установите Node.js.
2. Скопируйте `.env.example` в файл `.env`.
3. Укажите значения `SESSION_SECRET`, `SITE_PASSWORD` и `ALLDEBRID_API_KEY` в `.env.
4. Запустите `npm start`.
5. Откройте http://127.0.0.1:3000

Создать секрет сеанса можно командой:
`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

## Важные замечания

- По умолчанию сервер слушает `127.0.0.1`, что подходит для безопасного локального тестирования.
- Перед развёртыванием на VPS настройте обратный прокси и HTTPS, установите `COOKIE_SECURE=true`, используйте уникальные надёжные пароль и секрет сеанса. При необходимости измените адрес прослушивания на подходящий внутренний интерфейс или `0.0.0.0` за прокси.
- Не добавляйте `.env` в систему контроля версий.
- Перед публикацией сверьте адреса API и форматы ответов с актуальной официальной документацией AllDebrid.
- Сайт не проксирует видеотрафик. При прямом воспроизведении видеохост может видеть IP-адрес пользователя.

## AllDebrid library

После входа откройте раздел **Медиатека** и нажмите **Обновить**. Сервер получает список magnet-ссылок через `POST /v4.1/magnet/status`, затем пакетами запрашивает дерево файлов через `POST /v4/magnet/files`. Ключ API AllDebrid никогда не передаётся браузеру. Поиск фильтрует названия magnet-ссылок и вложенные пути файлов. Ссылки на некоторые файлы могут отсутствовать, пока обработка не завершена или если AllDebrid не вернул сведения о файлах.

Official API documentation: https://docs.alldebrid.com/

## Необязательные постеры фильмов и сериалов (TMDB)

Чтобы показывать постеры на карточках медиатеки, получите ключ TMDB и добавьте `TMDB_API_KEY=ваш_ключ` в `.env`, затем перезапустите сервер. Без ключа будут отображаться градиентные изображения. Поиск постеров выполняется сервером. Совпадение определяется приблизительно по названию magnet-ссылки, поэтому возможны ошибки.

## Локальный снимок медиатеки

После успешного обновления медиатеки браузер сохраняет снимок (названия magnet-ссылок, пути файлов, состояние и прогресс) в локальном хранилище. Он остаётся видимым после перезагрузки страницы и обновляется из AllDebrid при нажатии «Обновить». Данные не синхронизируются между браузерами и устройствами; очистка данных браузера удаляет снимок.
\n\n## Срок действия сеанса входа\nCookie входа действует до 30 дней и обновляется при активности (`rolling: true`). Не меняйте `SESSION_SECRET` в `.env` между перезапусками, иначе сеансы могут стать недействительными. Для публичного HTTPS-развёртывания установите `COOKIE_SECURE=true` и настройте `TRUST_PROXY`, если используется обратный прокси.\n

## Подготовка к релизу 1.0.0
- Пользовательский интерфейс, сообщения ошибок и состояния загрузки переведены на русский язык.
- Язык документа объявлен как `ru`; обновлены название и метаданные пакета.
- Добавлена команда `npm run check`: она проверяет синтаксис серверного JavaScript, клиентских файлов и встроенных скриптов в обеих HTML-страницах.
- Перед развёртыванием настройте `SITE_PASSWORD`, уникальный длинный `SESSION_SECRET`, `ALLDEBRID_API_KEY`, HTTPS и `COOKIE_SECURE=true`. Если сервер стоит за прокси, корректно настройте `TRUST_PROXY`.
- Для production замените стандартное хранилище сессий Express на постоянное хранилище (например, Redis или совместимое с Express Session). Встроенное MemoryStore не предназначено для production и теряет сеансы при перезапуске.
- Проверка кода не включает запросы к реальному аккаунту AllDebrid, запуск внешних плееров и тесты на устройстве. Эти сценарии требуют ручной интеграционной проверки.

## Поиск по трекерам (вкладка «Поиск»)
Один запрос по названию опрашивает несколько трекеров параллельно, объединяет дубли по infohash и показывает результаты с приоритетом русскоязычных трекеров (бейдж **RU**; порядок «RU сначала» → «по сидам» переключается в списке сортировки). Кнопка «＋ В библиотеку» отправляет magnet (или .torrent) в AllDebrid и показывает прогресс; готовые файлы появляются в «Моя библиотека».

### Фильтр «Фильмы и сериалы»
Над результатами есть список типа раздачи: «Фильмы и сериалы» (по умолчанию), «Только фильмы», «Только сериалы», «Всё подряд». Игры, софт, музыка, книги и 18+ скрываются, а сколько скрыто — написано над списком. Выбор запоминается в браузере. Тип определяется по категориям индексатора (Prowlarr/Jackett), а если их нет — по названию (теги вроде BDRip/WEB-DL/1080p, «Сезон/Серии», S01E01 — фильм или сериал; PC/RePack/FLAC/PDF и т. п. — не видео). Раздача без явных признаков считается фильмом. Правила лежат в `classify.js`; если что-то определилось неверно, пришлите название — поправлю.

### Русскоязычные трекеры (приоритетные)
| Трекер | Что нужно | Как работает |
|---|---|---|
| **rutor** | ничего (без аккаунта) | прямой разбор выдачи, magnet берётся из строки; `RUTOR_URL` — список зеркал через запятую |
| **rutracker.org** | `RUTRACKER_USER`+`RUTRACKER_PASS` или `RUTRACKER_COOKIE` | поиск по трекеру, magnet берётся со страницы раздачи в момент добавления; при отказе — .torrent через `dl.php` |
| **kinozal.tv** | `KINOZAL_USER`+`KINOZAL_PASS` или `KINOZAL_COOKIE` | поиск, инфо-хеш со страницы раздачи → magnet; при отказе — .torrent |
| **NNM-Club** | не обязателен (гостевой поиск); при необходимости `NNMCLUB_USER`+`NNMCLUB_PASS` или `NNMCLUB_COOKIE` | поиск по `tracker.php`, magnet берётся из строки результата или со страницы раздачи; домен — `NNMCLUB_URL` (по умолчанию nnmclub.to) |

Закрытые трекеры (rutracker, kinozal, NNM-Club) включаются автоматически, когда заданы их учётные данные. Если при входе по паролю срабатывает капча, возьмите cookie из браузера (DevTools → Application → Cookies) и укажите её в `*_COOKIE`.

**Важно.** Парсеры написаны по вёрстке сайтов (rutracker и kinozal сверены с публичными определениями Jackett, NNM-Club — по типовой схеме phpBB-трекеров) и проверены на тестовых копиях страниц, а не на живых сайтах. Если вёрстка изменится, включите `SEARCH_DEBUG=1` — в логе появится начало ответа сайта. rutracker.org и часть зеркал rutor заблокированы в РФ: сервер должен стоять там, откуда они открываются (или укажите рабочее зеркало). Самый устойчивый вариант для rutracker/kinozal — подключить их в **Prowlarr** (он сам обновляет определения индексаторов при смене вёрстки) и задать `PROWLARR_URL` + `PROWLARR_API_KEY`: результаты из индексаторов с русскими названиями тоже получают приоритет RU.

### Если трекер отвечает «Just a moment…» (Cloudflare)
rutracker (а иногда и kinozal) закрыт проверкой Cloudflare: обычный запрос с сервера её не проходит, и в строке ошибки под чипами написано про Cloudflare. Решение — FlareSolverr, который открывает страницу настоящим браузером:

```
docker run -d --name flaresolverr --restart unless-stopped -p 127.0.0.1:8191:8191 ghcr.io/flaresolverr/flaresolverr:latest
```
и в `.env`: `FLARESOLVERR_URL=http://127.0.0.1:8191`. Первый поиск после этого может занять 10–30 секунд (решается проверка), дальше полученный пропуск кэшируется на 20 минут. Для rutracker и kinozal можно указать либо cookie (`RUTRACKER_COOKIE`, можно просто значением `bb_session`), либо логин и пароль: при заданном `FLARESOLVERR_URL` вход выполняется через браузер FlareSolverr прямо с IP сервера. Если cookie отвергнута сайтом (устарела, неполная или создана с другого IP), а логин и пароль заданы, сервер сам перейдёт на вход по паролю. Тот же FlareSolverr подключается и в Prowlarr, если вы выберете его.

### Остальные провайдеры
`SEARCH_PROVIDERS` в `.env` (по умолчанию `rutor,rutracker,kinozal,nnmclub,prowlarr,jackett,apibay,nyaa`; недоступные из-за отсутствия настроек пропускаются): встроенные `apibay` (TPB), `nyaa` и `yts` (по умолчанию выключен: домен yts.mx часто не открывается, добавьте `yts` в `SEARCH_PROVIDERS` и укажите рабочее зеркало в `YTS_URL`), а также `prowlarr` / `jackett` (все ваши индексаторы). Зеркала: `APIBAY_URL`, `YTS_URL`, `NYAA_URL`.

**Безопасность:** браузер получает только id результата. Ссылки на .torrent (в них API-ключ Prowlarr/Jackett или cookie трекера) остаются на сервере; скачивать .torrent сервер умеет только с настроенных Prowlarr/Jackett и с rutracker/kinozal. Поиск ограничен 15 запросами в минуту, результаты кэшируются на 5 минут. Лимит двух одновременных загрузок на IP действует и для добавления из поиска.

Добавить свой трекер: новый объект в `providers` (`search.js` или `search-ru.js`) с методом `search(q)`, возвращающим `{title, size, seeders, leechers, date, infoHash}` (или `lazy` — если magnet доступен только после открытия раздачи).

## Кто может удалить раздачу

Сервер запоминает устройство (долгоживущий cookie `sdev`), с которого раздача добавлена в библиотеку (через «Поиск», magnet или .torrent), и записывает это в `owners.json` (в `DATA_DIR`). Отменить/удалить такую раздачу может только это же устройство, остальным сервер отвечает 403. Владельцем считается только устройство (cookie), IP не учитывается. Браузер и приложение на одном телефоне — разные устройства (у WebView свои cookie). Раздачи без записи о владельце (добавленные раньше или напрямую в AllDebrid) удаляются как прежде. Если очистить cookie сайта или данные приложения, устройство будет считаться новым. Отключить проверку: `OWNER_LOCK=false` в `.env`.

В медиатеке на плитке раздачи появляется кнопка: «Отменить загрузку», пока она качается или обрабатывается, и «Удалить из библиотеки», когда она уже скачана. Кнопка видна только устройству-владельцу.

## Оформление «Проекторная» и прокси превью

Оформление лежит отдельным слоем: `public/redesign.css`, `public/redesign.js` и шрифты в `public/fonts/` (всё отдаётся с вашего сервера, внешние сервисы не нужны). Чтобы вернуть прежний вид, удалите из `index.html` и `public/index.html` строки `<link rel="stylesheet" href="/redesign.css">` и `<script src="/redesign.js" defer></script>`.

Постеры (TMDB) браузер и приложение больше не берут напрямую у `image.tmdb.org`: `/api/poster` возвращает адрес вида `/api/poster/img/w500/…`, а сервер сам скачивает картинку и кэширует её в `DATA_DIR/poster-cache` (около 40–60 КБ на постер; папку можно удалять в любой момент). Для работы по-прежнему нужен `TMDB_API_KEY`.

## Энергоэффективность (страница в браузере и в приложении)

- Нет бесконечных CSS-анимаций: луч проектора «разгорается» один раз при открытии, логотип и фон статичны. Бесконечная анимация держала бы GPU и экран в постоянной перерисовке, даже когда вы ничего не делаете.
- Убран `backdrop-filter` (размытие под нижней панелью, кнопками ▶ на плитках, модальными окнами) — он пересчитывается на каждом кадре прокрутки. Фон этих элементов сделан почти непрозрачным, на вид разницы нет.
- Постеры и анализ видео (разрешение/битрейт) запрашиваются только для плиток, которые подходят к экрану. Найденные постеры запоминаются в браузере на 30 дней, «постера нет» — на 3 дня; неудачный анализ видео не повторяется 6 часов.
- Опрос статуса загрузок: 5 с первые 2 минуты, потом 15 с, после 10 минут — 30 с; нет активных загрузок или вкладка скрыта — запросов нет. Ожидание после «В библиотеку» в поиске тоже замедляется со временем и ставится на паузу в фоне.
- Сервер сжимает текстовые ответы (`compression`): страница 120 КБ → ~34 КБ, JSON медиатеки и поиска — в разы меньше. Видео-прокси и плейлисты не сжимаются.
- Шрифты кэшируются на год; `redesign.css`/`redesign.js` подключены с `?v=…` и тоже кэшируются на год. **После правки этих файлов увеличьте `?v=` в `index.html`**, иначе браузеры будут держать старую версию.
- Ответы TMDB на поиск постера кэшируются в памяти сервера на сутки.

После обновления выполните `npm install` (добавлен пакет `compression`). Без него сайт работает, просто без сжатия — в логе будет предупреждение.
