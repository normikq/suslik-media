## 4. «Сессии» (с отзывом)

Вкладка в боковой панели («Сервис») и кнопка «Сессии» в шапке на телефоне. Показывает входы пользователя: браузеры и устройства (ПК, ТВ, Android), время последней активности и вход, пометку «это устройство». Действия: «Завершить» / «Выйти» (для текущей, с подтверждением), «Завершить все остальные», «Завершить неактивные (7+ дней)». Неактивные больше 7 дней затемнены.

**API** (`routes/auth.js`, нужен вход; владелец — `req.user.id`, при входе по общему паролю — `"shared"`):

| Запрос | Что делает |
|---|---|
| `GET /api/sessions` | список `{id, kind: browser/device, name, created_at, last_seen, current}` |
| `POST /api/sessions/revoke` `{id}` | завершить одну; для текущего браузера — выход |
| `POST /api/sessions/revoke-others` | завершить все, кроме текущей |
| `POST /api/sessions/revoke-stale` `{days=7}` | завершить неактивные дольше N дней (1–365), текущую не трогает |

- `id` — начало SHA-256 (`b…` — сеанс браузера, `d…` — ключ устройства); настоящие идентификаторы сеансов и токены наружу не отдаются.
- Браузерные сеансы: `FileSessionStore.listFor(uid)`; последняя активность = срок cookie − `SESSION_MAX_AGE_MS` (cookie «скользящая»). При входе (пароль, Discord) в сеанс пишется `meta {ua, at}` — название браузера и система из User-Agent (`describeAgent`); адрес не сохраняется. Старые сеансы без `meta` показываются как «Браузер» без даты.
- Устройства: `listDevices(userId)`, `revokeDeviceById` в `services/users.js`.

**Выход приложения при отзыве.** При привязке по коду приложение получает ключ устройства и cookie-сеанс. Сеанс помечается `meta {app: true, dev: <хеш ключа>}` и в списке отдельной строкой не показывается (его представляет ключ). Отзыв ключа:
- `destroyAppSessions` закрывает привязанные сеансы (старые, без `dev`, — все app-сеансы этого пользователя; приложения входят по своему ключу);
- `resolveAuth` не пускает сеанс, чей ключ уже удалён;
- сеанс, выданный до этой пометки (Android шлёт и ключ, и cookie), `resolveAuth` привязывает к ключу при первом запросе с действующим ключом.

**Исправления после проверки (26.10):**
- при входе по общему паролю вкладка показывает только текущую сессию, завершить чужие нельзя (`shared: true` в ответе);
- изменяющие запросы с cookie сеанса принимаются только со страниц самого сайта (`sameOriginWrites` в `middleware/security.js`: `Sec-Fetch-Site`, иначе `Origin`); запросы с ключом устройства и без cookie не затрагиваются;
- «Выйти» в своей строке закрывает сеанс через `req.session.destroy` (cookie действительно стирается); завершённый сеанс не может записаться обратно запросом, начатым до отзыва (`FileSessionStore.gone`, 10 мин);
- «Завершить все остальные» и «неактивные» спрашивают подтверждение и показывают ошибку;
- тесты: `website/test/sessions.test.js`.

Приложение должно само обработать ответ 401 (стереть токен, показать вход) — в приложениях не проверялось.

## Ограничения и что не сделано

- Вход по общему паролю не привязан к человеку: такие сеансы видят в «Сессиях» только себя.
- Ключи устройств не истекают, браузерные сеансы живут 30 дней после последнего захода — автоматического закрытия нет (предложено: 30 дней простоя для браузера, 90 для ключей).
- Приложения называют устройства одинаково («Suslik Media Android»): имя собирается в `LoginScreen.kt:77` (Android), `Library.kt:124` (ПК), `tizen/js/app.js:87`. Рекомендуемый формат — `Suslik Media <платформа> <версия> · <модель/имя ПК>` (до 64 символов). Вход паролем в приложении показывается как «Браузер», пока у клиента нет своего User-Agent.
- Вкладок «Вместе» на сайте нет (в приложении — 5 вкладок, на сайте — 5 с «Скачать» вместо «Вместе»).
- Остальные экраны (окно «Смотреть», поиск, «Добавить») с приложениями не сверялись.
