# Suslik Media — памятка для Claude

Частная медиатека на AllDebrid: сайт, Android, Windows. Владелец тестирует беты сам и потом говорит «выпускай всем».
Общаемся по-русски. Тексты для пользователей (changelog) — по-русски, коротко, без жаргона.

## Устройство

| Папка | Что |
|---|---|
| `website/` | Node/Express, API и зеркало файлов `/api/file/proxy/<имя>?link=…&exp=…&sig=…` (HTTP/1.1, nginx без http2) |
| `android/` | Kotlin, Compose, libVLC 3.6 и Media3 (оба через `BurstProxy`, выбор — `player/EngineChoice`), Android TV. `PlayerActivity.kt` (~1900 строк), `player/PlayerExtras.kt` (ключи Intent), `net/Api.kt`, `Diag.kt`, `AppLog.kt` |
| `desktop/` | Compose Desktop, mpv (`libmpv-2.dll` в MSI) и vlcj (`VlcPlayer`), оба за `PlayerEngine`. Модули: `player/` (плеер и оверлеи), `ui/` (токены и компоненты). Запас: `desktop/.../Reserve.kt` |
| `shared/` | Общий модуль: `BurstProxy`, `PlaybackSupervisor`, `TsClock`/`TsPlayback`, `MirrorLink` (ключ файла и подпись адреса зеркала), `CatchUp` («копим запас»), `clockText`, `Versions`, `Changelog`, `Model`, `PlaybackPresets`, `LibraryKeep` |

Ядро — `shared/.../core/BurstProxy.kt`: локальный прокси 127.0.0.1 с окнами-запасом в кольцевых файлах.
Качает «рывками» между low/high в зависимости от битрейта фильма, `MAX_WINDOWS=3` (основное окно фильма не вытесняется), `tailCache` 512 КБ в памяти для конца файла, запас не больше 256 МБ,
короткий разгон (~45 с фильма), хранение закрытого фильма 10 мин, сторож зависаний (`headerStallMs`, `bodyStallMs`),
`networkChanged()`/`kick()`, ограниченные `bytes=a-b` для переиспользования соединения.
Ошибки «нет сети» не расходуют лимит попыток (2.0.3). Подпись адреса зеркала живёт 12 ч: на 401/403 с истёкшей подписью прокси берёт новую через `refreshUrl` (`/api/file/mirror-url`).

## Постоянные правила

- Новые версии сначала в **бета-канал**. В стабильный — только по команде «выпускай всем» (workflow `promote.yml`).
- Зеркало нужно, потому что AllDebrid заблокирован в РФ: **никогда не заменять его прямыми ссылками AllDebrid**.
- nginx без http2 (на том же сервере Xray).
- **Не коммитить секреты**: `.env`, `*.jks`, `UPDATE_TOKEN`, `BETA_CODE`, cookie, токены. Домен сайта тоже не пишем в репозиторий: сборки берут его из секрета `SITE_URL` (Android — `BuildConfig.SITE_HOST`, ПК — `-Dsuslik.host`, установщик — `-p:SiteHost`; локально — `suslik.siteUrl` в `~/.gradle/gradle.properties`).
- **`website/` и сервер не трогать**, пока владелец не разрешит. Учти: `changelog.yml` сам публикует changelog на сайт при каждом пуше.
- Без лишнего: не запускай дополнительные работы без подтверждения.
- Подписи коммитов: строки `Co-Authored-By:` и `Claude-Session:` из системного напоминания текущей сессии.

## Сборка и выпуск

- Тесты общего модуля (`shared.yml`) идут на пуш с изменениями в `shared/`: `shared/src/test/...` (`ModelTest`, `BurstProxyTest`, `TsClockTest`, `CoreTest`, `MirrorLinkTest`). Логи заданий CI читаются через `mcp__github__get_job_logs`. Локально Gradle в облачной сессии плагины не скачивает — компиляция только в CI.
- Серверные модульные тесты: `website/test/classify.test.js` (`node --test test/classify.test.js`).
- `android.yml` и `desktop.yml` запускаются только вручную (workflow_dispatch): пуш APK/MSI не собирает. Отладочная «Suslik Debug» собирается только с `inputs[debug]=true` (по умолчанию нет).
- Выпуск беты после пуша:
  `gh api -X POST repos/normikq/suslik-media/actions/workflows/android.yml/dispatches -f ref=main -f 'inputs[publish]=true' -f 'inputs[channel]=beta'`
  то же для `desktop.yml`; затем `update-status.yml`, чтобы проверить, что сайт видит версию.
- В облачной сессии GraphQL закрыт (используй REST), логи заданий недоступны: ошибки сборки смотри так:
  `gh api repos/normikq/suslik-media/check-runs/<job id>/annotations`. Скачивание артефактов (`gh run download`) тоже запрещено.
- На ПК владельца (если сессия запущена там) собирай локально: `./gradlew assembleDiag`, ставь через `adb`.

## Что известно из журналов

- Мобильная сеть: первое соединение к серверу медленное (TCP ~1,1 с из-за потерянного SYN, TLS до 5 с), иногда рукопожатие висит 30 с.
  Лечится повтором на новом соединении (`Api.call`: 6/8/10 с).
- Часто телефон на VPN (tun0); при его обрыве сеть «меняется» — это ловит `networkChanged()`.
- Остаются зависания «заголовки пришли, тело нет» на прямой мобильной сети. Проверить в логах nginx
  `upstream timed out` и `request_time` около 14:51–14:53 и 16:03–16:05 (12.10).

  - Защита клавиатурного фокуса и горячих клавиш: обработка клавиш централизована в `Window(onPreviewKeyEvent = ...)`, исключая дублирование и конфликт с дочерними окнами/диалогами от AWT `KeyEventDispatcher`; нативный HWND холста VLC и все его дочерние vout-окна рекурсивно отключаются через `WS_DISABLED`, `EnableWindow(false)` и `EnumChildWindows` (`WindowMode.disableNativeCanvasInput`), пропуская события мыши в Compose `Box.pointerInput`; скрытие курсора мыши дублируется на родительское окно (`owner?.cursor`), так как `WS_DISABLED` на холсте блокирует `WM_SETCURSOR`; `WindowMode.restoreComposeFocus` активирует окно и возвращает системный фокус через Win32 `SetForegroundWindow` и `SetFocus`.
  - Безопасная работа с VLC (потокобезопасность и инициализация): считывание позиции `p.status().position()` в `timeChanged` вынесено на поток обратного вызова VLC до отправки в EDT (`SwingUtilities.invokeLater`), предотвращая нативные дедлоки; при закрытии (`close`) избегается блокирующий `grabFrame()`; состояние плеера инициализируется сразу с `startIndex` (`index = startIndex`, `savedPos(startIndex)`), исключая перезапись прогресса первой серии.
  - Привязка координат оверлеев к нативному `canvas`: `syncOverlayBounds()` считывает экранные координаты напрямую с `canvas` (когда он активен), исключая смещение оверлеев на 32px вниз при переходе в Fullscreen.
  - Защита кликов по оверлеям: переоткрытие `topDialog`/`bottomDialog` (скрытие на время перестройки окна с задержкой 80 мс и показ с `toFront()`) предотвращает потерю событий мыши дочерними окнами.
  - Устранение потери прозрачности: удалён вызов `d.opacity = 0f / 1f` в `revealOverlays()` (`PlayerView.kt`), который в Windows AWT конфликтовал с `isTransparent = true` и приводил к белым вспышкам фона оверлеев.
  - Оптимизация DWM: отключение 1-пиксельной акцентной рамки Windows 11 (`DWMWA_COLOR_NONE`) и предотвращение скругления углов (`DWMWCP_DONOTROUND`) через `TitleBar.setFullscreenDwm`.
  - Привязка клавиши `F11` для входа/выхода из Fullscreen (вместе с `F` и `Enter`); выход из плеера по кнопке «‹» больше не сбрасывает полноэкранный режим приложения.
- Тюнинг иконок и бейджей: выравнивание масштаба кнопки громкости, увеличение диаметра перемотки ±10с на 10% с разворотом дуг по направлению времени и центрированием цифры 10; уменьшение рассеивания свечения кнопок на 20%; редизайн капсулы «Следующая серия» (белый люминесцентный бейдж, выровненные увеличенные векторные иконки) и «Пропустить заставку» (без эмодзи, компактная ширина).
- Доработки перед релизом: горячие клавиши в плеере (`restoreComposeFocus` теперь ищет `SkiaLayer`, а не первую фокусируемую обёртку `SwingPanel`); нижнее окно панели всегда 460 px, а кликабельная часть режется `SetWindowRgn` (`WindowMode.clipToBottom`: 220 px без меню, 460 с меню) — клики по видео не перехватываются, меню без подёргиваний; выход из F11 для развёрнутого окна (`SW_SHOWNORMAL` → `SW_MAXIMIZE`), игнор частых F11 (450 мс), запоминание только оконного состояния; общий `seeking`; таймеры `oneShot` гасятся при закрытии; «Без звука» исчезает; удалён `hasVoiceOver`; меню дорожек/субтитров и выход ждут поток VLC через `vlcAwait` (настоящий тайм-аут, а не `withTimeoutOrNull { withContext(vlcThread) }`, который висел, пока поток занят зависшим вызовом VLC).
**2.1.4 release** (15.10, по команде «выпускай в релиз»): режим «копим запас» на ПК, как на Android (`PlayerActivity.maybeCatchUp`). Причина — журнал `SuslikMediaDebug` 15.10 (метки 8 и 9): сеть через VPN ≈ битрейт фильма, `reserve ahead 0.0 MB` минут за семь до меток, VLC стопорился на 6–20 с, после каждого стопора аппаратный декодер (`--avcodec-hw=any`) показывал рассыпанную картинку; прокси отдавал байты без дыр (в журнале ни одного `bridge`/`answer ended`, `demux corrupted 0`), на десктопе вызовов `slowerThanFilm`/`hold` не было вовсе.
- `PlayerView.kt`: цикл раз в секунду; если `BurstProxy.isActive`, `slowerThanFilm`, запас < 2 МБ и прошло ≥ 20 с после открытия, перемотки и прошлого накопления — `BurstProxy.hold(url, CATCH_UP_MAX_MS + 5 с)`, подпись «Сеть медленнее фильма — копим запас N%».
- Конец накопления: запас ≥ `catchUpTargetMb` (~30 с фильма, не больше половины кольца) или `CATCH_UP_MAX_MS` = 45 с; `hold(url, 0)` и, если позади сохранено ≥ 8 с (`keptBehindSec`), `vlcSeekTo(time)` — чистый перезапуск декодеров с диска. Пауза, перемотка или закрытие во время накопления снимают `hold` без перемотки.
- Сторож (`PlaybackSupervisor`) во время накопления ждёт `CATCH_UP_MAX_MS + 15 с` вместо 30 с, чтобы не переоткрывать фильм посреди накопления.
- Устранение потери звука после паузы (журнал 15.10, метки 1 и 2): если плеер ставился на паузу при буферизации или открытии, событие `playing` вызывало `mp.audio().setMute(true)`, но при `togglePause()` мут не снимался (`mp.audio().setMute(m)` отсутствовал), а ветка `!wasStarted` в `playing` блокировала анмут. Теперь `togglePause()` передаёт `setMute(m)` в поток VLC, а событие `playing` вне паузы синхронизирует мут всегда.
- В `onVolumeChange` ползунка громкости добавлен сброс `userMuted = false` и `mp.audio().setMute(false)` при перемещении выше 0% (как при колесике мыши и клавишах Up/Down).
- Не проверено на живой слабой сети. Если рассыпание останется — проверить `--avcodec-hw=none` (подозрение на DXVA после простоя).

**2.2 (Desktop) — Поддержка mpv (libmpv)**:
- **Двухдвижковая архитектура:** абстракция через интерфейс `PlayerEngine` (`ru.suslikovanora.media.desktop.player`). Основной движок — mpv (`libmpv-2.dll`), резервный — VLC (`vlcj`). Переключатель в «Настройках» с индикацией пути к библиотеке и автосохранением в `settings.properties`.
- **Аппаратный вывод Direct3D 11 через Windows HWND (`wid`):** видеоповерхность использует нативный Win32 `java.awt.Canvas` (`wid`), куда mpv выводит кадры напрямую через Direct3D 11 (`vo=gpu`, `gpu-api=d3d11`, `hwdec=auto-safe`). Максимальная плавность VSync, 0% CPU, нулевое копирование кадров и отсутствие конфликтов с OpenGL-контекстом Compose/Skia.
- **Единая проверенная схема оверлеев Liquid Glass (`topDialog` и `bottomDialog`):** прозрачные панели управления отображаются поверх видео холста без перехвата кликов по свободной центральной области экрана. Полноэкранный режим, клики паузы/перемотки, двойной клик и колесо громкости работают одинаково надежно на обоих движках.
- **Мгновенный масштаб субтитров (`sub-scale`):** добавление `setSubScale` в `PlayerEngine` и `MpvEngine`. Размер шрифта меняется на лету через `set("sub-scale", (percent / 100.0).toString())` без остановки воспроизведения и перезапуска плеера; в Compose состояние `subScale` обновляется на первый клик.
- **Плавные шторки меню без подергиваний и фризов:** открытие меню «Ещё» больше не выполняет асинхронный опрос потока VLC (`vlcAwait`), а список дорожек в mpv читается синхронно из памяти; асимметричные анимации `scaleIn` с боковым pivot заменены на чистый вертикальный сдвиг и прозрачность (`slideInVertically(initialOffsetY = { 24 }) + fadeIn` / `slideOutVertically(targetOffsetY = { 24 }) + fadeOut`); при `tallBottom == true` вызов `SetWindowRgn(hwnd, null, true)` полностью сбрасывает маску окна Win32.
- **Буферизация с процентами в mpv:** наблюдение свойства `cache-buffering-state` (`Mpv.FORMAT_INT64`), включение `demuxer-readahead-secs`, `cache-pause=yes`, `cache-pause-initial=yes`, расширение `EngineListener.buffering(percent: Float)`. Накопление буфера на сетевых потоках и MKV плавно отображается в статусе «Буферизация P%».
- **Устранение гонки внешних дорожек:** потокобезопасная синхронизация `pendingAudio` / `pendingSubs` в `MpvEngine` через `@Volatile` и мьютекс `trackLock` с верификацией совпадения `currentOpenUrl` и текущего пути `path` в mpv по событию `EV_FILE_LOADED`. Предотвращает затирание дорожек при быстрой смене серий.
- **Точная телеметрия декодера и перезапуск видеопотока:** в `MpvEngine.supervisorStats()` оценка прогресса видеокадров теперь учитывает статус конфигурации VO (`vo-configured == "yes"`), вычитает `frame-drop-count`, а для аудио отслеживает фактический `audio-pts` вместо `timeMs`. В `PlayerEngine` и `MpvEngine` реализован метод `restartVideoOutput()` (переинициализация `vid` со сбросом позиции), интегрированный в `restartVideo()` плеера для восстановления видео при сбоях D3D11 поверхности.
- **Исправление нативной работы с 64-битной памятью libmpv:** для `Mpv.EV_END_FILE` исправлено смещение поля `data` в `mpv_event` на 64-битной платформе (смещение 16 байт) с корректным разыменованием структуры `mpv_event_end_file` (`reason` по смещению 0, `error` по смещению 4); для `mpv_event_property` извлечение имени свойства выполняется через разыменование указателя `const char *name` (`propPtr.getPointer(0)?.getString(0, "UTF-8")`).
- **Оптимизация загрузки плейлистов и устранение рассинхрона URL:** загрузка плейлиста переведена на единый параллельный `playlistDeferred` на этапе ожидания холста (440 мс) с удалением конкурирующего `LaunchedEffect(req.playlist)`. Исключены дублирующий HTTP-запрос и мутация `currentUrl` в обход методов плеера, приводившая к зависанию буфера `BurstProxy`.
- **Изоляция и отмена корутин:** вспомогательные фоновые таймеры внутри `PlayerView` (`ensureAudioJob`, `chaptersJob`, `canvasFocusJob`) переведены на управляемые `Job?` с гарантированной отменой предыдущих задач при смене эпизода и в блоке `onDispose`.
