# Suslik Media для Samsung TV (Tizen)

Веб-приложение Tizen для телевизоров Samsung 2018 года и новее (Tizen 4.0+, проверяем на UE40NU7100).
Переносит Android-приложение: тот же сервер и API, тот же вход через Discord по коду устройства, те же правила медиатеки.
Код в репозитории — без сборщика, обычный JavaScript ES2017: в Tizen 4.0 браузер на Chromium 56 (нет `?.`, `??`, модулей).

## Что есть (0.2.0)

- **Вход** через Discord по коду устройства: на ТВ QR-код (ссылка с кодом) и та же ссылка текстом. Токен устройства хранится на ТВ.
- **Вкладки сверху**: Медиатека, Мои, Поиск, Добавить, Вместе, Настройки (`js/app.js`; вкладки — `search.js`, `add.js`, `together.js`).
  «Назад» из содержимого — на вкладки, с вкладок — «Закрыть приложение?».
- **Медиатека**: «Продолжить просмотр» (недосмотренное и следующие серии), постеры, раздача → фильм или серии по сезонам,
  кнопка «Продолжить с …», «В Мои» (`/api/shelf`).
- **Поиск** раздач по трекерам (`/api/search`), фильтры как на Android, добавление (`/api/search/add`) и ход загрузки.
- **Добавить** — magnet-ссылка (`/api/magnets`), история с ходом загрузки и отменой. Ссылки https не принимаются:
  `/api/unlock` отдаёт прямую ссылку AllDebrid, а смотреть можно только через зеркало. QR-код сайта — добавить с телефона.
- **Вместе** — совместный просмотр: создать комнату или войти по коду; ведущий открывает фильм — он становится фильмом
  комнаты; гость сразу смотрит фильм комнаты, пауза у гостя — своя, перемотка и выбор серии — у ведущего. Логика —
  перенос `shared/.../core/party` (`js/partycore.js`), поток событий читается XHR (EventSource не шлёт `X-Device-Token`).
  AVPlay не меняет скорость плавно: расхождение до 2 с терпим, больше — перемотка.
- **Прогресс по аккаунту Discord** (`/api/sync`, `js/sync.js` — перенос `WatchSync.kt`): ТВ, ПК и телефон продолжают с одного
  места. Выбор озвучки и субтитров ТВ не синхронизирует (номера дорожек AVPlay свои).
- **Настройки**: аккаунт и выход, версия, «Что нового» (`js/changelog.js`, показывается один раз после обновления).
- Плеер — `webapis.avplay` (аппаратный плеер ТВ) по подписанной ссылке зеркала. Перемотка, пауза, следующая серия,
  выбор звуковой дорожки и встроенных субтитров, новая ссылка при обрыве сети или истёкшей подписи.
- **Предупреждения о том, что телевизор не умеет** (сервер не перекодирует, решение 21.10):
  - в медиатеке, поиске и списке серий: `.iso` и AV1 — «не поддерживается», `.avi`, Blu-ray (`.m2ts`) и DTS/TrueHD в имени — «⚠»;
  - озвучка отдельным файлом (`.mka` рядом с видео) — серая строка «на телевизоре недоступна»;
  - после открытия: дорожки DTS/TrueHD в меню звука помечены и не выбираются, такая дорожка по умолчанию
    заменяется другой с подсказкой; если звука, который ТВ играет, нет — окно «Звук этого файла телевизор не воспроизводит»;
  - время фильма идёт заметно медленнее настоящего (журнал 21.10: `.m2ts` — 1 кадр в секунду) — подсказка «видео идёт рывками»;
  - AVPlay не открыл файл — «Этот файл телевизор не поддерживает».
- **Проба** (жёлтая кнопка или Info в плеере): кодеки, дорожки и события AVPlay — чтобы понять, что играет этот телевизор.

- **Звук, который ТВ не играет, и Blu-ray — через сервер** (0.2.5): `.m2ts`/`.ts` и файлы с DTS/TrueHD в имени сначала
  спрашивают `/api/file/tv-info`; если в файле нет звука, который ТВ играет (видно после открытия), — тоже. Сервер отдаёт
  видео как есть, звук — AC3 (см. `website/README.md`, «Поток для телевизора»). Перемотка — новым потоком с нужного места
  (точность — до ближайшего ключевого кадра, 1–5 с), смена звука — тоже. Не вышло — файл открывается по зеркалу, как раньше.

Пока нет: внешних субтитров и озвучек (файлы рядом с видео), удаления раздач, запаса `BurstProxy` (веб-приложение на ТВ
не может открыть локальный сервер; запас держит сам AVPlay).

## Пульт

OK или ▶❚❚ — пауза · ← → — 10 с · ⏪ ⏩ — минута · ⏮ ⏭ — соседняя серия · ↓ — звук и субтитры · ↑ — панель · жёлтая/Info — проба
(в пробе OK — замер скорости сети) · «Назад» или ■ — выход.

## Сборка и установка на телевизор

Tizen Studio Samsung объявил устаревшей. Замена — расширение **Tizen TV** для VS Code (`code --install-extension tizensdk.tizentv`).
Наше приложение — веб-приложение (не .NET), поэтому нужны именно команды «Tizen TV» этого расширения.

1. Телевизор в режиме разработчика: Apps → на пульте `1 2 3 4 5` → Developer mode **On**, IP компьютера → перезагрузить ТВ.
2. Подготовить папку приложения (домен сайта в репозиторий не пишем), результат — `tizen/build/app`:
   - Windows, PowerShell в папке `tizen`: `powershell -ExecutionPolicy Bypass -File .\build.ps1 -SiteUrl https://<сайт>`
     (без `-SiteUrl` адрес берётся из `SITE_URL` или `suslik.siteUrl` в `~\.gradle\gradle.properties`);
   - Linux/macOS/Git Bash: `SITE_URL=https://<сайт> ./tizen/build.sh`.

   Открыть папку `tizen/build/app` в VS Code.
3. Настройки VS Code: `tizentv.targetDeviceAddress` — IP телевизора.
4. Команда **Tizen TV: Run Certificate Manager** → новый профиль **Samsung** (тип TV), в сертификат дистрибьютора
   добавить DUID телевизора (расширение видит его, когда ТВ подключён).
**Обязательно для ТВ 2017–2018 (проверено на UE40NU7100):** без шага «Permit to install» телевизор отклоняет любой
пакет с ошибкой `install failed[118012]` (`118, -12`, «Check certificate error»), даже если DUID в сертификате верный.
Tizen Studio → `C:\tizen-studio\tools\device-manager\bin\device-manager.exe` (нужен Visual C++ 2013:
`winget install Microsoft.VCRedist.2013.x86`) → подключить ТВ → правый клик → **Permit to install applications**.
Перед этим активным должен быть профиль с Samsung-сертификатом (`tizen security-profiles set-active -n <профиль>`).
Вручную (`sdb push device-profile.xml /home/developer/`) ТВ этот файл не принимает.

**Подпись для Tizen 4.0 — всегда профиль «mixed»** (проверено 21.10 на UE40NU7100): автор — `author.p12` с Samsung-сертификатом
(Samsung VD Author CA), дистрибьютор — Samsung `distributor.p12` с DUID телевизора. Другие профили дают `118012`.
Обновление ставится поверх, только если автор тот же, что у установленной версии.
```
tizen security-profiles add -n mixed -a "<путь>\author.p12" -p <пароль> -d "<путь>\distributor.p12" -dp <пароль>
tizen security-profiles set-active -n mixed
$env:TIZEN_PROFILE="mixed"; .\build.ps1 -SiteUrl https://<сайт>
```

5. **Tizen TV: Build Signed Package** (пакет появится в корне папки), затем **Tizen TV: Launch Application** — ставит и запускает на ТВ.
   Для отладки — **Tizen TV: Debug Application** (Chrome Web Inspector).

Запасной путь — Tizen Studio (ещё работает, но не развивается) и его CLI:
`SITE_URL=… TIZEN_PROFILE=<профиль> ./tizen/build.sh` соберёт `tizen/build/SuslikMedia-<версия>.wgt`,
дальше `sdb connect <IP>` и `tizen install -n <файл .wgt> -t <имя из sdb devices>`.

Самообновления нет: новую версию ставят так же, через `tizen install`.

## Тесты

`node --test tizen/test/*.test.js` — правила медиатеки (те же случаи, что `ModelTest.kt`), проверки поддержки файлов,
комната и движок синхронизации (`party.test.js`), прогресс по аккаунту (`sync.test.js`), версия в «Что нового» = `config.xml`.
